# PRD-059: Anthropic Raw-API Inference Adapter

## Objective

Implement the first PRD-058 inference adapter: Anthropic Messages API
as a raw runtime (`anthropic-api`) so Familiar's own loop can drive
Claude models directly — with honest cache-category usage, correct
tool and streaming semantics, and accounting that reconciles against
PRD-052 organization cost collection.

## Design (provider details verified 2026-08-30; re-verify at implementation)

**Protocol.** Requests target the Messages API (`POST /v1/messages`)
with content-block messages. Canonical tools project to native tool
definitions (input schema, optional strict validation so tool inputs
validate exactly); model tool calls arrive as `tool_use` content
blocks and results return as `tool_result` blocks — all results for a
parallel batch in one user message, per the provider contract.
Structured output uses the output-config format surface. Streaming
delivers text, tool-call, and usage deltas which the adapter forwards
as PRD-058 events. Current models reject assistant prefill; the
adapter never uses it.

**Reasoning.** Thinking is configured through the current adaptive
surface with effort controls, per the worker's capability profile.
Returned thinking blocks are replayed unchanged on the same model per
the provider's replay rules. Reasoning spend is billed inside the
provider's output accounting; the adapter records what the provider
reports and does not fabricate a separate reasoning category the API
does not expose.

**Usage and caching.** The usage block's input, output, cache-read,
and cache-creation categories map one-to-one onto the PRD-051 ledger
categories — this adapter is the first source that populates
cache-write natively. Prompt caching follows PRD-029: byte-stable
prefix, cache-control breakpoints (bounded per request) after the
stable content, volatile task state last. Missing usage fields stay
unknown.

**Stop reasons.** Provider stop reasons map deterministically onto
the PRD-058 closed set: normal end, max-tokens, tool-use
continuation, pause-class continuation, and refusal — a refusal
records its provider-reported category as an honest terminal fact.
Nothing maps to token exhaustion unless the ledger actually says so.

**Identity and probing.** The requested model identifier and the
response's resolved identity are both recorded (PRD-057: aliases are
identity risks). The provider's model-metadata surface supplies
context-window and capability facts, and token counting supplies
preflight sizing — both non-billable probes under PRD-047 discipline.

**Billing.** Runtime `anthropic-api` with an API-key auth reference is
`local-estimate` mode: versioned, dated, source-attributed price
schedules produce estimates; PRD-052's organization collector
reconciles them where an Admin source is configured. Nothing from
Claude Code applies here — no client-side cost estimate, no
subscription semantics, no harness permissions; this is a different
PRD-057 empirical identity by construction.

**Security.** The API key exists as an external reference resolved
inside the adapter boundary at call time; redaction covers logs,
errors, and evidence; tool subprocess environments never inherit it;
billing/admin credentials are entirely out of reach (PRD-052 rules).

## Scope

- The adapter crate/module implementing the PRD-058 contract; native
  tool projection; streaming; cancellation; error taxonomy with
  retry-after handling.
- Cache-control placement per PRD-029; usage-category normalization
  into PRD-051 with sanitized envelopes and provider request ids.
- Anthropic price-schedule entries (versioned, dated, sourced) and
  capability-profile defaults for `anthropic-api` workers.
- Deterministic fixture suite per the acceptance criteria; wiremock
  transport fakes; no live calls.
