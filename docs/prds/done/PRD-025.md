# PRD-025: Repository Backlog Profiles

**Status:** Ready for implementation
**Date:** 2026-08-08
**Depends on:** PRD-006, PRD-023
**Architectural direction:** Repository Is Truth; Determinism Before Intelligence; Fail Closed On Unknown State
**Delivery boundary:** Independently mergeable extension of discovery, identity, and context compilation so a repository with a different backlog convention is drivable without weakening any fail-closed guarantee

## Objective

Let Familiar drive a repository whose backlog does not follow the canonical `docs/prds/PRD-<n>.md` convention, by making the backlog layout and PRD grammar a **profile**: a closed, named parser selected per repository in the operator's configuration — never inferred, never user-defined, never read from the target repository.

Familiar's doctrine says it should outlive every repo convention it drives. Today it enforces exactly one convention: its own.

## Motivation

The first external repository Familiar was pointed at (spectra, ~40 pending PRDs, 174 archived) was undrivable for structural reasons, not capability ones. Its backlog lives in `docs/prd/todo/` with archived work in `docs/prd/done/`; files are named `0133-enterprise-operations.md`; headings read `# PRD 0133 — Title`; epic children carry letter-suffixed identities (`0139a` … `0139d`) that a `u64` cannot represent at all; and ordering-by-identity, not a `**Depends on:**` field, is that repository's eligibility doctrine. Every one of these is inert layout data — none of it touches execution authority — yet each one fails closed against the hardcoded grammar.

The wrong fixes are known and rejected: renumbering an established backlog destroys cross-references in commits and documents; symlink bridges are already forbidden by discovery; wrapper stubs would feed the context compiler wrappers instead of specifications. The right fix is the one PRD-023 already proved on a smaller axis: parameterize what varies (location, now grammar), keep what must not vary (fail-closed discovery, deterministic selection, graph validation) invariant.

## Semantics

- **A backlog profile is a closed, named grammar.** This PRD ships exactly two: `canonical` (byte-identical to today's behavior in every observable) and `numbered-slug` (the spectra convention). There is no user-defined grammar, no regex configuration, no content sniffing. An unrecognized profile name fails closed at configuration load.
- **Profile selection is operator authority, not repository content.** A `[repositories."<worktree>"]` table in the operator's configuration binds an absolute worktree path to a profile and its directories. The target repository cannot choose how it is parsed. A repository with no entry resolves to `canonical` at the canonical locations — existing behavior, unchanged.
- **PRD identity becomes number plus optional suffix.** `PrdId` carries a `u64` and an optional single ASCII lowercase letter. The canonical grammar never produces a suffix, so its identity space, ordering, display, and persistence are unchanged in every observable.
- **Ordering is total and epic-aware:** ascending by number; within an equal number, suffixed identities in letter order strictly before the unsuffixed identity. `0139a < 0139b < 0139 < 0140`. Rationale: in the motivating convention an unsuffixed PRD sharing its number with suffixed siblings is an epic umbrella, completed after its children; selecting it first would execute a close-out document before the work it closes.
- **The `numbered-slug` grammar, closed:** active files are `<digits><suffix?>-<slug>.md` directly inside the profile's active directory; `<digits>` is one to six ASCII digits, `<suffix>` one optional ASCII lowercase letter, `<slug>` nonempty. The first nonblank line must be a level-one heading `# PRD <identity> <separator> <title>` where `<identity>` matches the filename identity numerically and by suffix, `<separator>` is an em-dash or colon, and `<title>` is nonempty. Everything else about the file is opaque content. No `**Depends on:**` field is parsed: the dependency set is empty by grammar, and eligibility is identity order — the motivating repository's own lowest-first doctrine, now enforced rather than assumed.
- **Locations generalize PRD-023, they do not fork it.** A profile declares an active directory and an archived directory (repo-relative, traversal-free, distinct; canonical defaults: `docs/prds` and `docs/prds/done`). Location-is-truth semantics transfer whole: archived means completed, corrections are recorded as status events under a system actor, selection and admission never touch archived work, duplicate identities and dual-location copies fail closed naming both paths, and files in the archived directory that do not parse under the profile's grammar are tolerated exactly as PRD-023 tolerates wave-one documents.
- **Context compilation follows the profile.** The compiler's PRD-root containment check uses the profile's active directory. Reference-root discovery gains the profile's declared reference roots — a closed list of `(prefix, kind)` pairs in the repository entry, defaulting to today's `docs/adr/`, `docs/contracts/`, `docs/supporting/` for `canonical` and for any entry that declares none. Reference roots are read-only context data; declaring one grants no execution authority.
- **Persistence round-trips the full identity.** Stored backlog rows carry number and suffix, and every ordering the store performs agrees with the domain ordering above. Existing rows (all suffixless) migrate byte-deterministically; a fresh database over an archived-layout repository still needs no bootstrap, per PRD-023.
- **Display preserves the repository's own spelling.** Internal identity is numeric; anything human-facing — `next` output, reports, diagnostics — renders the identity as the repository writes it (`PRD-24` under canonical, `PRD 0139a` under numbered-slug, zero-padding taken from the filename), so an operator can grep their own backlog with Familiar's output.

## Scope

This PRD includes:

1. The `PrdId` extension (number + optional suffix), its total order, and profile-aware rendering.
2. The two profile grammars in core discovery, with `canonical` proven byte-identical to today by regression.
3. Profile-parameterized locations threaded through discovery, graph validation, reconciliation, selection, and admission — PRD-023 semantics preserved under both profiles.
4. The `[repositories."<worktree>"]` configuration table (profile name, active/archived directories, reference roots), fail-closed validation, and deterministic resolution by canonicalized worktree path with duplicate-resolution conflicts refused.
5. Context-compiler awareness of profile locations and declared reference roots.
6. A storage migration carrying suffix in backlog and bootstrap rows, with deterministic rewrite of existing rows and order-agreement between SQL and domain.
7. Profile-aware `next`, `run`, `drive`, `backlog`, and `report` verbs, including identity rendering.
8. Focused tests over temporary repositories in both conventions.

## Non-goals

This PRD does not:

- add user-defined or regex-configurable grammars — profiles are code, shipped and versioned with Familiar;
- read any configuration from the target repository, or let repository content influence parsing, selection, or authority;
- add per-repository execution configuration — verification commands, allowed paths, scope classes, agents, and budgets remain global (PRD-026);
- infer dependencies for grammars that do not declare them, or scan PRD prose for ordering hints;
- move, rename, or rewrite any PRD file in any repository — archiving remains a human `git mv`;
- support more than one active/archived directory pair per repository, recursive directory scanning, or per-PRD profile overrides; or
- modify prior PRDs, architecture documents, ADRs, contracts, or philosophy.

## Behavior

```toml
[repositories."/home/trollboy/Projects/spectra"]
profile = "numbered-slug"
active_dir = "docs/prd/todo"
archived_dir = "docs/prd/done"
reference_roots = [
  { prefix = "docs/prd/", kind = "prd" },
  { prefix = "docs/runbooks/", kind = "supporting" },
]
```

`familiar-ai next` run inside that worktree discovers `docs/prd/todo`, seeds the 174 archived PRDs as completed by location, orders `0139a` through `0139d` ahead of `0139`, and selects the lowest pending identity. A malformed heading, a duplicated identity, an unknown profile name, a traversal in a configured directory, or two repository entries resolving to the same worktree each fail closed with an exact diagnostic naming the offending value. A repository with no entry behaves byte-identically to today.

## Acceptance Criteria

1. A temporary repository in the numbered-slug convention — todo/done split, em-dash headings, letter-suffixed children — is discovered, validated, bootstrapped from location, and selected from, with children ordered strictly before their umbrella and the umbrella before the next number.
2. Letter-suffixed identities round-trip through discovery, persistence, selection, claim, and report rendering, and SQL ordering agrees with domain ordering for a fixture interleaving suffixed and unsuffixed identities.
3. The canonical profile is byte-identical to today: existing discovery, bootstrap, selection, admission, recovery, and driver suites pass unchanged, and a canonical-layout fixture with no repository entry produces identical selection and identical rendering.
4. Grammar violations under numbered-slug — heading/filename identity mismatch, missing em-dash or colon, empty title or slug, seven-digit number, multi-letter suffix — each fail closed with an exact diagnostic; unparseable files in the archived directory alone are tolerated.
5. No `**Depends on:**` parsing occurs under numbered-slug: a file containing the field is not treated as declaring dependencies, and eligibility is pure identity order.
6. Configuration validation refuses an unknown profile name, traversal or absolute paths in directories, identical active and archived directories, and two entries resolving to one canonicalized worktree — each before any repository access.
7. Context compilation for a numbered-slug PRD enforces containment against the profile's active directory and resolves declared reference roots; canonical repositories keep today's roots untouched.
8. The storage migration rewrites existing rows deterministically, preserves every current status and claim, and a pre-migration database dump replayed through the migration is byte-stable across two runs.
9. PRD-023 invariants hold under both profiles: archived-location completion with visible correction events, dual-location and duplicate-identity conflicts named by both paths, selection refusing archived work by exact diagnostic.
10. All tests use temporary repositories and databases; formatting, focused Clippy, focused tests, and the workspace suite pass, or demonstrably pre-existing failures are reported with exact evidence.
11. The change is confined to the expected files and is independently mergeable.

## Test Strategy

- Grammar: table-driven accept/reject fixtures per profile, including every rejection in criterion 4 pinned to its exact diagnostic.
- Ordering: property-style fixture over interleaved identities asserting domain order, SQL order, and selection agree; the epic fixture (`0139a`–`0139d`, `0139`, `0140`) pinned end-to-end through `next`.
- Locations: mixed todo/done fixtures under numbered-slug replaying the PRD-023 suite's scenarios — corrections, conflicts, fresh-database selection without bootstrap.
- Configuration: load-time refusals for each invalid shape; resolution by canonicalized path including a symlinked-worktree duplicate.
- Migration: populated pre-migration database migrated and diffed for determinism; suffixless round-trip equivalence for canonical rows.
- Regression: the full existing backlog, bootstrap, recovery, driver, and report suites unchanged; canonical byte-identity fixture per criterion 3.

## Definition of Done

PRD-025 is done when the convention a repository happens to use is a described fact rather than a compatibility wall: the operator names a profile and two directories, and discovery, identity, ordering, completion-by-location, context compilation, and every verb work under that description with exactly the fail-closed rigor the canonical grammar enjoys today — while a repository nobody described behaves byte-for-byte as it always has.
