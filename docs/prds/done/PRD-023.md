# PRD-023: Location Is Truth for Completed PRDs

**Status:** Ready for implementation
**Date:** 2026-08-05
**Depends on:** PRD-011, PRD-022
**Architectural direction:** Repository Is Truth; Determinism Before Intelligence; Memory Must Be Durable
**Delivery boundary:** Independently mergeable extension of discovery so an archived PRD is a completed PRD

## Objective

Make the filesystem self-evident about what is finished: discovery reads `docs/prds/done/` in addition to the active directory, treats every PRD found there as completed by virtue of its location, and keeps those entries in the dependency graph.

Moving a finished PRD into `done/` becomes the completion record a human can see, review in a diff, and clone. A fresh database on a fresh checkout needs no bootstrap manifest and no reconciliation, because the repository already says what is done.

## Motivation

Today completed PRDs must stay in the active directory, because `validate_graph` resolves dependencies only among discovered PRDs: archiving PRD-013 would make every later PRD that depends on it fail with `MissingDependency`, halting `next`, `run`, and `drive` entirely. Completion therefore lives only in the database — and a database can drift from reality, which is exactly what happened when a fresh database listed ten merged PRDs as `pending` and selected an already-implemented one.

PRD-022 adds an audited verb to repair that drift. This PRD removes the reason drift exists. The two are complementary: 022 is the escape hatch for state that has already diverged; 023 makes the common case not diverge, and makes the active directory an honest list of remaining work.

## Semantics

- **Discovery** returns PRDs from both `docs/prds/` (active) and `docs/prds/done/` (archived), each carrying its location. Archived PRDs participate fully in dependency resolution and graph validation.
- **Location is authoritative for completion**: an archived PRD is `completed`. Reconciliation records that status, and a stored status that disagrees is corrected to match the location, with the correction recorded as a status event under a system actor so the change is visible rather than silent.
- **Active PRDs keep database-tracked status** exactly as today: pending, in_progress, completed, or blocked. An active PRD already `completed` in the database stays completed — archiving is encouraged, never required.
- **Selection never chooses an archived PRD**, and admission refuses one by exact diagnostic, so `run`, `next`, and `drive` operate only on active work.
- **Nested `done/` is not recursive** beyond one level, and a PRD present in both locations is a fail-closed conflict naming both paths — Familiar does not guess which copy is authoritative.
- **Numbering remains globally unique** across both locations; duplicate identifiers are a fail-closed conflict as they are today.
- **The bootstrap manifest keeps working unchanged** for repositories that use it; it simply becomes unnecessary for repositories that archive.

## Scope

This PRD includes:

1. Discovery over both locations, with a location field on each discovered PRD.
2. Graph validation across the union, so dependencies on archived PRDs resolve.
3. Reconciliation treating archived location as authoritative completion, recording corrections as status events under a system actor.
4. Selection and admission excluding archived PRDs with exact diagnostics.
5. Fail-closed handling of duplicate-location and duplicate-identifier conflicts.
6. Focused tests over temporary repositories covering both locations, corrections, conflicts, and unchanged active-only behavior.

## Non-goals

This PRD does not:

- move any PRD file itself — archiving is a human `git mv`, and no command performs it;
- change PRD-011 admission, claim, or completion-evidence semantics for active PRDs;
- change PRD-012 recovery or PRD-022 recorded completion;
- alter the bootstrap manifest, its lineage guard, or its behavior;
- read `done/` recursively, interpret subdirectories as meaningful, or infer status from filenames;
- rewrite or relocate the wave-one documents already in `done/` (they carry a different naming scheme and no wave-two dependency references them); or
- modify prior PRDs, architecture documents, ADRs, contracts, or philosophy.

## Acceptance Criteria

1. A PRD in `docs/prds/done/` is discovered, resolves as a dependency for active PRDs, and validates in the graph.
2. Archiving a completed PRD leaves `next`, `run`, and `drive` working, with dependents still eligible.
3. An archived PRD is recorded `completed`; a stored status disagreeing with its location is corrected, and the correction is recorded as a visible status event under a system actor.
4. Selection never returns an archived PRD, and admission refuses one with an exact diagnostic.
5. The same PRD present in both locations, or duplicate identifiers across locations, fails closed naming both paths.
6. Active-only repositories behave byte-identically to today, including bootstrap-manifest repositories.
7. Wave-one documents already in `done/` are handled without error and without being interpreted as wave-two entries.
8. A fresh database over a repository whose finished PRDs are archived requires neither bootstrap nor reconciliation to select the correct next PRD.
9. All tests use temporary repositories and databases; formatting, focused Clippy, focused tests, and the workspace suite pass, or demonstrably pre-existing failures are reported with exact evidence.
10. The change is confined to the expected files and is independently mergeable.

## Test Strategy

- Discovery: fixtures with active-only, archived-only, and mixed layouts; location recorded per PRD; one-level `done/` only.
- Graph: an active PRD depending on an archived one validates and is selectable; the archived one never is.
- Reconciliation: archived PRD stored as `pending` is corrected to `completed` with a status event under a system actor; an active PRD's tracked status is untouched.
- Conflicts: same path in both locations, and duplicate identifiers across locations, each fail closed naming both paths, with no row mutated.
- Regression: existing backlog, bootstrap, admission, recovery, and driver suites pass unchanged; an active-only fixture produces byte-identical selection to today.
- Fresh-database test: archived layout plus empty database selects the correct next PRD with no bootstrap manifest present.

## Definition of Done

PRD-023 is done when moving a finished PRD into `docs/prds/done/` is all it takes to record completion — dependents keep resolving, selection ignores archived work, conflicting locations fail closed, a fresh clone needs no seeding, and the active directory finally reads as exactly the work that remains.
