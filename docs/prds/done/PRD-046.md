# PRD-046: Dogfooding Bug Ledger

A living ledger of defects observed while Familiar drives its own backlog.
Each entry names the bug and its disposition. This PRD is a triage record,
not authorization to combine unrelated scheduling, persistence, review, and
contract changes in one implementation. The table below is authoritative;
the detailed reports are retained as historical context.

## Detailed reports (historical)

### B1 — Cost/token warrant silently disables parallelism
**Bug:** `component_parallelism` (drive.rs) returns 1 whenever the session
warrant sets `max_cost_microusd > 0` or `max_tokens > 0`, so
`--max-cost-microusd` quietly turns a parallel session serial with no
message. Observed 2026-08-30: session `drive-…049015…` ran serial despite
`--max-parallel-components 3`.
**Fix:** either implement per-component cost attribution so the ceiling and
parallelism compose, or fail loudly / warn that the two flags conflict.
Interim: never pass a cost or token ceiling when parallelism is wanted.
PRD-053 specifies the composing fix: per-component reservations drawn from
the session warrant, settled against attributed estimates.

### B2 — One config-class attempt failure kills the whole session
**Bug:** an attempt failing with `RunError::Config` classifies as
`unclassified_result`, which terminates the session (`worker_should_restart`
treats it as crash-like) instead of retaining that PRD and moving to the
next. One bad PRD or transient config condition ends an overnight run.
**Fix:** retain the failing PRD with its reason and continue the session;
reserve session termination for storage failures and genuine crashes.

### B3 — Repository-scoped config lost inside drive sessions and lease worktrees
**Bug (diagnosed 2026-08-30):** two faces of one class. (a) drive scrubbed
the entire `repositories` map after folding effective review/execution
config — safe before PRD-042, but `risk_vocabulary` is not folded, so every
per-attempt discovery resolved an empty vocabulary and failed closed
(serial mode always; worktree mode survived only via the lease-path
insert). (b) A lease worktree's config entry exists only in the creating
session's memory: `resume`, `resume all`, and later sessions resolve the
lease path against file config, miss, and hit the same empty-vocabulary
failure (observed on PRD-35's surviving checkpoint).
**Fix:** (a) **fixed** — drive retains the pinned repository's entry
instead of clearing (commit "keep the pinned repository's config through a
drive session"). (b) **open** — resolve a worktree to its parent
repository's config via the git common dir (`RepositoryIdentity.key`)
instead of by worktree path alone; until then, resuming a lease checkpoint
needs a temporary config entry for the lease path.

### B4 — Timed-out remediation wedges the checkpoint permanently
**Bug:** a remediation agent killed by timeout leaves its edits in the
tree but never updates the checkpoint snapshot, producing a permanent
`hash_mismatch` (observed on PRD-043; required manual salvage). In-repo
serial execution puts the wedge in the main working tree.
**Fix:** remediation must be transactional: checkpoint the tree after a
successful remediation, and revert to the pre-remediation snapshot when the
agent fails or times out.

### B5 — Failed review/remediation stages misreport as TokenLimitExhausted
**Bug:** `failed_stage` records unknown usage; `add_usage` with unknown
usage against a finite token ceiling stops the cycle as
`TokenLimitExhausted` even when the real cause was agent failure or
timeout, hiding the true stop reason and consuming no retry.
Partially fixed for validation-rejected reviews (4ac7013 keeps known
usage); the agent-failure and remediation-timeout arms still mislabel.
**Fix:** stop with the honest reason (`AgentFailure` / a new
`RemediationFailed`) when usage is unknown because the stage failed, and
only report `TokenLimitExhausted` when the ledger actually exceeds the
ceiling.

### B6 — Every resume re-bills a full review replay
**Bug:** a blocked checkpoint resumes by re-running verification and the
complete opus review (~$2-3, 2-3 min) even when only the completion
bookkeeping failed after a clean review; review nondeterminism then
produces different findings each replay (PRD-043 saw four; PRD-035's
UTF-8 finding flipped medium → high → high across three replays, changing
whether remediation fires at all).
**Fix:** checkpoint the validated clean review result so completion-only
failures retry completion without re-executing the reviewer.

### B7 — Planner and BacklogManager use layout-less discovery
**Bug:** `plan.rs:290/:853` and the `BacklogManager` path call
`.discover()`, which uses `BacklogLayout::default()` — empty risk
vocabulary and default directories. Any repository with structured PRDs
and a configured vocabulary will fail these paths (same failure class as
B3; latent until those commands run here).
**Fix:** thread `repository_config.layout()` through every discovery call
site; consider removing the layout-less `discover()` from the trait to
make the mistake impossible.

### B8 — Review token ceiling counts cache reads at full weight
**Bug:** `review.max_total_tokens` compares raw totals; one implementation
recorded 7.64M tokens of which 98% were cache reads (~144k fresh), so any
realistic ceiling either trips instantly or bounds nothing meaningful.
Interim config workaround: ceiling raised to 25M (2026-08-29), then
disabled entirely (2026-08-30) after PRD-035's implementation recorded
72.2M total (98.7% cached, ~916k fresh, ~$30.62) — raw totals cannot
simultaneously permit normal work and stop runaways; the 30-minute cycle
duration is the only effective rail until this is fixed.
**Fix:** denominate budget ceilings in uncached tokens or cost; ties into
the wave-three economy work and PRD-032's empirical scoring. Specified by
PRD-051 (distinct cache categories, versioned price schedules) plus
PRD-053 (uncached-token/cost warrant denominations).

### B11 — Post-completion checkpoint events violate UNIQUE on replay
**Bug:** after a successful backlog completion, the checkpoint phase
transitions insert `execution_checkpoint_events` rows whose event ids
collide with rows recorded by earlier resume attempts
(`UNIQUE constraint failed: execution_checkpoint_events.event_id`,
observed at PRD-035's completion). Everything durable had already
committed, so the failure is cosmetic — but the command exits nonzero and
the completion looks failed to the caller.
**Fix:** make the post-completion transition inserts idempotent
(INSERT OR IGNORE, or event ids derived from phase + attempt), and treat
already-recorded phases as success.

### B12 — Supersession is invisible to the machine
**Bug:** the contract v1 status set has no `superseded` value and no
`superseded_by` field, so a superseded prose PRD left in the active
directory is simply *pending*: drive session `…056686…` claimed PRD-040
(the decomposed umbrella) and only the implementation model's voluntary
reading of the body prose prevented duplicate work colliding with
PRD-044/045. Eligibility protection by model conscientiousness is luck,
not contract.
**Fix:** (a) **done 2026-08-30** — the risk materialized: after the
empty-diff review's F1 finding, the remediation agent began implementing
the umbrella for real (86+ insertions across registry/config/
coordinator/tier before intervention). The session was stopped, the claim
released (`human:trollboy`), and PRD-040.md archived to done/ —
location-is-truth now makes it permanently ineligible. (b) extend the
contract with `status: superseded` + `superseded_by: [ids]`, never
eligible, with metadata-check validating the successors exist — still open;
(c) doctrine: a decomposition archives its umbrella in the same commit
that queues the children.

### B13 — history_failed discards its cause and wedges the execution row
**Bug (observed 2026-08-30, session `…056686…`):** PRD-036's finalize
write failed after a successful implementation stage; the attempt retained
as `history_failed` but the underlying storage error is never printed at
the retain site (`run.rs` retained_traced records only the reason token;
the detail would only surface in drive's end-of-session reap, which never
ran because the session was stopped). The execution_history row
(`…650797-…-000002`) is permanently wedged at `outcome='running'` with no
ended_at, and the attempt's real usage/cost is lost. Suspected cause: SQLite
write contention between parallel components exceeding the 5s
busy_timeout — unconfirmed because the cause was discarded.
**Fix:** print the storage error at the retain site (same discipline as
the B9 fix); make finalize retry or queue on SQLITE_BUSY; add a sweeper
that closes `running` rows whose process is gone (`runner_interrupted`).
PRD-051's stage-boundary usage observations bound the evidence loss when
finalize fails; the retry and sweeper remain this entry's fix.

### B14 — Implementer may end its turn at a phase boundary with questions
**Bug (observed 2026-08-30, PRD-036 attempt):** the headless implementer
completed Phase 1 discovery, produced five clarifying questions, and
ended the turn (`end_turn`, exit 0, zero edits, $2.73). Nothing in the
pipeline detects "clean exit, empty diff" before spending a verification
round and an opus review on it — the same empty-diff path PRD-040's
review walked. There is no operator to answer, so the questions are dead
air and the attempt burns a full cycle.
**Fix:** (a) prompt: state explicitly that no human is present and the
agent must resolve ambiguity itself, recording assumptions in the
implementation report; (b) pipeline: treat a zero-edit implementation exit
as `implementation_incomplete` and retain immediately, before
verification/review spend. Interim: PRD-036 now carries an Owner Guidance
section answering the specific questions.

### B10 — Flaky signal test randomly fails required verification
**Bug:** `codex::tests::crash_signal_is_preserved_as_terminal_process_evidence`
(familiar-ai-agent) intermittently fails inside the Docker tester under
load (observed twice 2026-08-30; the PRD-043 implementer also hit it and
called it "a transient race"), while passing locally and in manual
reproduction. A flake in a required check produces random
`VerificationUnsuccessful` stops for unrelated PRDs.
**Fix:** diagnose the shell-signal race properly (suspects: shell TERM
handling vs. process-group/watchdog interaction under io load) or make
the assertion tolerant of the equivalent 128+SIGTERM exit encoding.
Interim: rerun the cycle; the flake clears.

## Fixed (retained for context)

- **B9 — secret scanner deadlocked redaction PRDs.** `contains_secret`
  matched bare marker names, so PRD-035's redaction implementation — which
  quotes the scanner's own marker list — was structurally unreviewable
  (`EvidenceFailure`, cause discarded by two more `Err(_)` arms). Fixed
  2026-08-30: markers count only when adjoined to a token-like value of
  16+ chars (private-key headers stay unconditional), and both
  EvidenceFailure arms print their cause ("value-shaped secret detection
  unblocks redaction PRDs").
