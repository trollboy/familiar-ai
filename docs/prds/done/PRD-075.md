# PRD-075: Audited Registry Migration and Whole-Configuration Validation

## Objective

Close FAM-BUG-006 completely. The corruption guard already landed — a
registry enable now refuses before writing when a legacy `[agents]`
section is present — but the refusal is a dead end: there is no supported
path from legacy agents configuration to the worker registry except
hand-editing, which is how the M1's configuration got corrupted and then
manually recovered. Two fixes, one shallow and one deep: an explicit,
audited, lossless migration command; and the generalized invariant the
bug exposed — every configuration mutation validates the *complete*
proposed configuration before persisting, because validating a section in
isolation is how one successful command bricked every subsequent load.

## Design

- **Whole-configuration validation as the mutation invariant.** The
  shared mutation path (PRD-047's comment-preserving editor) gains one
  rule: build the complete proposed configuration, run full validation on
  it, and only then persist atomically. Section-local validation remains
  as a fast pre-check; it is never the last check. The FAM-BUG-006
  reproduction — first `model enable` against a config with `[agents]` —
  is the pinned regression.
- **The migration command.** `config migrate agents` (exact name at
  implementation discretion, recorded in the contract doc) converts the
  legacy section losslessly: each role's adapter, model, and executable
  map into registry workers such that the resolved worker plan for
  implementation, reviewer, and remediation is identical before and
  after — proven by comparison, not inspection. Backup first, comments
  preserved, decision-row audit with actor, atomic rename; interruption
  leaves the original untouched.
- **The refusal teaches.** The existing guard's diagnostic names the
  migration command verbatim, so the operator's path is
  refuse → migrate → retry, three commands with an audit trail, instead
  of an evening of hand-recovery.
- **Idempotent.** No agents section, or an already-migrated
  configuration, is a diagnosed no-op.

## Scope

The whole-configuration validation rule in the shared mutation path, the
migration command with backup/audit/atomicity, the enriched refusal
diagnostic, contract documentation of the migration, and regressions in
a dedicated test file (bug-shape regression, resolved-plan equivalence,
interrupted-migration untouched-original, no-op idempotence, comment
preservation).

Out of scope: removing `[agents]` support (legacy configurations keep
loading until the owner retires them), any change to worker selection
semantics (PRD-044 owns those), and inventory/readiness display
(PRD-057).

## Assumptions (recorded at specification time, 2026-08-31)

- The resolved-worker-plan comparison reuses PRD-044's selection
  machinery as the equivalence oracle rather than re-deriving mapping
  rules in the test.
- The manual migration already performed on the M1 machine is left as
  is; this command serves every subsequent machine and the regression
  serves the invariant.
