# PRD-060: OpenAI Raw-API Inference Adapter

## Objective

Implement the OpenAI Responses API as a PRD-058 raw runtime
(`openai-api`) so Familiar's loop can drive GPT-family models
directly — with distinct cached-input and reasoning-output
accounting, resolved-model identity, and reconciliation against the
PRD-054 organization collectors.

## Design (provider details verified 2026-08-30; re-verify at implementation)

**Protocol.** Requests target the Responses API — the current
official surface for new agentic integrations — with input items,
native tool definitions, `stream`, schema-constrained structured
output (`text.format`/JSON-schema), and `reasoning.effort` controls.
Model tool calls arrive as function-call output items carrying
`call_id`, `name`, and `arguments`; results return as call outputs
keyed by `call_id`. Output items carry status
(in-progress/completed/incomplete), which the adapter maps onto
PRD-058 stop semantics honestly.

**Conversation state.** Familiar owns the loop (PRD-058); the adapter
resends explicit input items. `previous_response_id`-style
server-side continuation is an isolated adapter capability that may
optimize transport but is never the source of truth — checkpoints and
resume derive from Familiar's own state, so a provider-side session
cannot strand recovery.

**Usage.** The usage object maps onto PRD-051 categories:
`input_tokens` (with `input_tokens_details.cached_tokens` splitting
cached from uncached input), `output_tokens`, and
`output_tokens_details.reasoning_tokens` as the distinct
reasoning-output category. The provider reports no cache-write
category; none is fabricated — provider capability differences are a
property of the row, not a hole to fill. The response `id` persists
as the provider request identity in the sanitized envelope.

**Identity.** The requested model may be a moving alias; the
response's resolved model is recorded per PRD-057, and price
schedules key on resolved identity where available. Price-relevant
dimensions from the verified pricing surface — service tier,
batch/flex/fast modes, long-context tiers — are recorded when present
and carried into estimates by the versioned schedules.

**Billing.** Runtime `openai-api` with a project API key is
`local-estimate` mode reconcilable against PRD-054's organization
usage (`/v1/organization/usage/completions` dimensions) and costs
collectors where an Admin source exists. A project key never grants
reporting authority (PRD-054's rule), and nothing from Codex or
ChatGPT plans — plan credits, allowance, `turn.completed` telemetry —
applies to raw API calls; those are different PRD-057 empirical
identities and billing modes.

**Security.** Inference and Admin credentials are separate external
references with separate exposure rules; redaction covers logs,
errors, and evidence; tool subprocesses inherit nothing.

## Scope

- The adapter implementing the PRD-058 contract over the Responses
  API; native tool projection; streaming; cancellation; error
  taxonomy (`rate_limit_exceeded`, server errors, invalid requests)
  with retry metadata.
- Usage normalization into PRD-051 (cached-input and reasoning-output
  distinct) with sanitized envelopes and response identity.
- OpenAI price-schedule entries (versioned, dated, sourced) covering
  the verified dimensions; capability-profile defaults for
  `openai-api` workers.
- Deterministic fixture suite per the acceptance criteria; wiremock
  transport fakes; no live calls.
