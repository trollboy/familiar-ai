# PRD-047: Provider and Model Configuration CLI

## Objective

Give Familiar its first config-writing surface: kind-tagged provider
endpoints and model enablement managed by CLI, with probe-before-persist
validation, BYO-auth diagnostics, comment-preserving TOML edits, and a
durable decision audit trail. Familiar never stores or handles a
credential.

## Design

A **provider** is a named, kind-tagged reference to a credentialed
endpoint: `kind = "inference"` in this PRD (later kinds arrive in
PRD-048/050, and the `billing` kind in PRD-052/054, without schema
change).
A provider carries an **auth descriptor** that is purely diagnostic — `cli-login: claude`,
`env: SOME_KEY`, `ssh-agent`, or `none` — naming what the operator must
have arranged. **BYO-Auth**: the operator installs and authenticates
CLIs, exports env vars, and manages ssh keys; Familiar only detects,
verifies, and names the remedy.

Enabled models become workers in the PRD-031/043 registry, addressable
as `provider/model`, with capabilities supplied at enablement.

Interaction grammar (COMMAND / SUCCESS / FAILURE / explainer):

    familiar-ai config provider add ollama --host 192.168.1.112:5000
    Added ollama (inference) at 192.168.1.112:5000 — 3 models discovered.
    ollama: host unreachable — nothing added.
    # host optional: assumes localhost and the provider's default port
    # (ollama: 11434). Probe runs first; persistence only on success.

    familiar-ai config provider list [--refresh]
    codex [ sonnet-5.6, gpt4 ]  (verified 2m ago)
    ollama [ qwen3, llama2 ]    (verified 3d ago — --refresh to re-probe)

    familiar-ai config provider verify azure-inference
    azure-inference: az CLI not authenticated — run `az login`.
    # verify never mutates; it re-probes and updates verified_at on success.

    familiar-ai config model enable ollama/qwen3 --capabilities implementation
    familiar-ai config model disable ollama/qwen3

## Scope

- `config provider add|remove|verify|list` and `config model
  enable|disable|list`, with kind, host, and auth-descriptor fields on
  `RepositoryConfig`-level provider entries (providers are machine-global;
  workers and routing stay repository-capable).
- Probe implementations per provider type: executable presence, auth
  state via the descriptor, endpoint reachability, and model discovery
  (ollama `/api/tags`; CLI probe for CLI-backed providers). Discovery is
  cached with `verified_at`; `list` never blocks on the network unless
  `--refresh` is passed.
- TOML round-trip through `toml_edit` preserving every existing comment;
  inserted entries carry a provenance prefix comment:
  `# added by familiar-ai config provider add — human:<identity> <UTC>`.
- One decision row per config mutation (command, actor, before/after
  content hash) so `config history` can distinguish tool edits from hand
  edits.
- Secrets discipline: commands accept no credential positionally; auth
  is referenced, never captured. Key-like input is rejected with a
  pointer to the BYO-auth contract.
