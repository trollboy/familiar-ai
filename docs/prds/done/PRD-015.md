# PRD-015: Project Identity Rename to familiar-ai

**Status:** Ready for implementation
**Date:** 2026-08-03
**Depends on:** PRD-013, PRD-014
**Architectural direction:** Repository Is Truth; Determinism Before Intelligence; Small, Bounded Work Wins
**Delivery boundary:** Independently mergeable mechanical rename of machine identity with deterministic local-state migration

## Objective

Rename the project's machine identity from `familiar` to `familiar-ai` across the Cargo workspace, crate names and directories, binary names, environment-variable prefix, XDG/application path identifiers, runtime file names, and container identifiers — with a deterministic, auditable, fail-closed migration of existing local state so no configuration, database, or backlog history is silently orphaned.

The human-facing product name **"Familiar"** in documentation prose is unchanged. This PRD renames namespaces and identifiers, not the product's voice. The GitHub repository and local working-directory rename are performed manually outside this PRD and are prerequisites, not deliverables.

## Motivation

`familiar` is a generic identifier: it collides on package registries, is unsearchable as a project name, and conflicts with unrelated tools on shared systems (`~/.config/familiar`, a `familiar` binary on PATH). `familiar-ai` is distinguishable everywhere the machine identity appears while leaving the product's name and metaphor intact.

The dangerous part of a rename is not the string substitution — it is the silent orphaning of durable state. Familiar's canonical local state (configuration, the SQLite database holding backlog claims, execution history, review cycles, and bootstrap audit records) lives under paths derived from the old identifier. A rename that does not migrate that state would present a fresh, empty Familiar while the real history sits abandoned one directory over — a violation of Memory Must Be Durable and an unacceptable silent loss. Migration is therefore in scope and fail-closed.

This PRD depends on PRD-013 and PRD-014 deliberately: both name `crates/familiar-*` paths in their Expected Files contracts, and executing the rename first would strand their specifications. Sequencing after them keeps every active PRD's contract accurate at its own execution time.

## Scope

This PRD includes:

1. Renaming all workspace member crates and their directories from `familiar-*` to `familiar-ai-*`, including the excluded `familiar-tray`, with library names `familiar_ai_*` and all `use`/path references updated mechanically.
2. Renaming the CLI binary `familiar` to `familiar-ai` and the `familiar-mcp` binary to `familiar-ai-mcp`.
3. Changing the configuration environment prefix from `FAMILIAR_` to `FAMILIAR_AI_`, with fail-closed detection of stale old-prefix variables.
4. Changing every `AppPaths` identifier from `familiar` to `familiar-ai`: config, data, state, runtime, and log directories on both Linux (XDG) and macOS, plus `familiar-ai.pid`, `familiar-ai.sock`, and the `/tmp/familiar-ai-<uid>` fallback.
5. A deterministic one-time local-state migration executed at startup path resolution: old location exists and new does not → atomically rename the directory and emit one audit line; both exist → fail closed with an exact diagnostic naming both paths; neither → fresh initialization as today.
6. Renaming container and compose identifiers (`Dockerfile`, `docker-compose.yml`) and the MCP server identity string reported during handshake.
7. Focused tests for the migration state machine, the env-prefix cutover, renamed paths, and binary names, plus mechanical updates to every existing test asserting the old identifiers.

## Non-goals

This PRD does not:

- change any behavior, schema, workflow, CLI semantics, output format, or configuration key beyond the identifier strings themselves;
- rewrite Git history, tags, or prior commits;
- edit prior PRDs, `docs/prds/done/`, philosophy, architecture documents, ADRs, or contracts — historical documents keep historical paths as accurate records of what was true when written;
- rebrand documentation prose: the product remains "Familiar" wherever a human reads it, including `docs/north-star.md`;
- publish any crate to crates.io or reserve names there;
- perform the GitHub repository rename or the working-directory rename (manual, already done);
- migrate or modify SQLite *content* — the database file moves with its directory, byte-identical; no schema migration is added;
- add dual-read compatibility, alias binaries, symlinks, or a deprecation window: the cutover is single-release and explicit; or
- touch `.claude/`, editor configuration, or any per-user tooling outside the repository and the defined AppPaths.

## Rename Map

| Surface | Old | New |
|---|---|---|
| Crate packages/dirs | `familiar-agent` … `familiar-tray` | `familiar-ai-agent` … `familiar-ai-tray` |
| Library namespaces | `familiar_agent` … | `familiar_ai_agent` … |
| CLI binary | `familiar` | `familiar-ai` |
| MCP binary | `familiar-mcp` | `familiar-ai-mcp` |
| Env prefix | `FAMILIAR_` (figment, `__` split) | `FAMILIAR_AI_` (same split) |
| XDG/app dirs | `…/familiar` | `…/familiar-ai` |
| Runtime files | `familiar.pid`, `familiar.sock`, `/tmp/familiar-<uid>` | `familiar-ai.pid`, `familiar-ai.sock`, `/tmp/familiar-ai-<uid>` |
| Container identity | compose service/image names | `familiar-ai` forms |
| MCP handshake identity | `familiar-mcp` server name/version string | `familiar-ai-mcp` |

Actor strings embedded in *new* audit records (for example `system:familiar-run:<id>`) switch to `system:familiar-ai-run:<id>`. Existing stored records are never rewritten; consumers must not assume a single actor spelling across history.

## State Migration Semantics

Migration happens during `AppPaths` resolution, before any storage open, per directory (config, data, state, log; runtime and `/tmp` fallback dirs are ephemeral and are recreated, not migrated):

1. New path exists → use it; old path is ignored entirely (already migrated or fresh install; no re-checks, no merging).
2. New absent, old present → `fs::rename` the old directory to the new path (same filesystem by construction). On success, emit exactly one stderr line per migrated directory: `identity migration: <old> -> <new>`. On any rename error, fail closed with the exact source error; never fall back to copying, merging, or partial migration.
3. Both present → fail closed with a diagnostic naming both paths and instructing the human to resolve manually. Familiar must not guess which state is authoritative.
4. Neither present → create the new path lazily exactly as today.

Environment cutover: if any `FAMILIAR_`-prefixed variable (that is not `FAMILIAR_AI_`-prefixed) is set at startup, configuration loading fails with a diagnostic listing the stale variable names and the required new prefix. Silently ignoring old-prefix variables would constitute silent configuration loss.

Explicit `daemon.pid_file`, `daemon.socket_path`, and `database.path` overrides in user configuration are user-owned absolute paths and are not migrated or rewritten; they continue to be honored verbatim.

## Acceptance Criteria

1. Every workspace member compiles under its `familiar-ai-*` package name in a `crates/familiar-ai-*` directory, with no `familiar_`-prefixed (non-`familiar_ai_`) library identifier remaining anywhere in Rust source.
2. `cargo build --workspace` produces a `familiar-ai` CLI binary and a `familiar-ai-mcp` binary, and no `familiar` or `familiar-mcp` binary target remains.
3. All CLI subcommands (`next`, `run`, `history`, `usage`, `backlog …`) behave byte-identically to before the rename apart from the binary name and defined identifier strings.
4. `AppPaths` resolves every directory and runtime file under `familiar-ai` identifiers on both Linux and macOS, including the `/tmp/familiar-ai-<uid>` fallback.
5. On first run with state only under old-identifier paths, each persistent directory is atomically renamed to its new path with one audit line each, and all prior backlog, execution-history, review, and bootstrap records are readable unchanged afterward.
6. When both old and new state directories exist, startup fails closed naming both paths, and no file is moved, merged, deleted, or opened for write.
7. When neither exists, fresh initialization proceeds exactly as before the rename.
8. Configuration loads only from the `FAMILIAR_AI_` prefix; any stale `FAMILIAR_`-prefixed variable causes a fail-closed diagnostic listing the offending names.
9. Explicitly configured absolute `pid_file`, `socket_path`, and `database.path` values are honored verbatim and excluded from migration.
10. New audit records use `familiar-ai` actor spellings while previously stored records remain byte-for-byte unchanged and fully readable.
11. Docker and compose builds succeed under `familiar-ai` identifiers, and the MCP handshake reports the `familiar-ai-mcp` identity.
12. Documentation prose retains "Familiar" as the product name; prior PRDs, done PRDs, ADRs, contracts, philosophy, and architecture documents are byte-for-byte unchanged.
13. `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, and `cargo test --workspace` pass, with any demonstrably pre-existing failure reported separately with exact evidence.
14. The change is confined to the expected files and is independently mergeable.

## Test Strategy

- **Migration state machine:** unit tests over a temporary root covering all four cases (new-only, old-only, both, neither) per directory kind; assert atomic rename (same inode contents, SQLite file byte-identical via hash), exactly one audit line per migrated directory, fail-closed both-present behavior with no writes, and rename-error propagation without partial state.
- **Environment cutover:** stale `FAMILIAR_` variable fails configuration with the variable named; `FAMILIAR_AI_…` overrides behave exactly as the old prefix did (port the existing env-override tests, including the `__` split mapping).
- **Paths:** port every existing `paths.rs` test to the new identifiers on both platforms; assert pid/socket/tmp-fallback names.
- **End-to-end continuity:** integration test that seeds a database with backlog, claim, execution-history, and bootstrap rows under old-identifier paths, runs a CLI command through the new binary, and asserts migration plus unchanged query results and history output.
- **Rename completeness:** a test (or CI grep gate) asserting no `familiar_`-non-`ai` Rust identifier, no `"familiar"` path-identifier literal, and no old binary target name remains in `crates/`; documentation directories are explicitly excluded from the gate.
- **Regression:** the full existing workspace suite passes with only mechanical identifier updates — no assertion semantics change.

## Definition of Done

PRD-015 is done when:

1. The entire machine identity — crates, namespaces, binaries, env prefix, app paths, runtime files, container and MCP identities — is `familiar-ai`, verified by the completeness gate.
2. Existing local state migrates atomically and audibly on first run, fails closed on ambiguity, and every prior record remains readable unchanged.

4. Behavior, schemas, workflows, and documentation prose are otherwise unchanged, and historical documents are untouched.
5. Formatting, Clippy with warnings denied, focused migration tests, and the full workspace suite pass, or pre-existing failures are recorded with exact evidence.
6. The change is confined to the expected surface and merges independently after PRD-013 and PRD-014.
