# PRD-007: Deterministic Context Budgeting

**Status:** Ready for implementation  
**Date:** 2026-08-03  
**Architectural direction:** Context Is Precious; Determinism Before Intelligence  
**Delivery boundary:** Independently mergeable deterministic budgeting between context compilation and prompt rendering

## Objective

Introduce a deterministic `ContextBudgeter` that accepts the `ExecutionContext` produced by `familiar-context` and a configured hard token budget, then returns a `BudgetedExecutionContext` and an inspectable `ContextBudgetReport` without invoking an LLM.

The requested PRD is mandatory. The budgeter ranks only the directly referenced documents already present in `ExecutionContext`, selects whole documents under the configured ceiling, records every inclusion and exclusion with an exact reason, and preserves every selected document's source content unchanged. `familiar run` applies the budgeter after context compilation and before prompt rendering.

If budgeting is disabled, the run path remains behaviorally identical to the current implementation. If budgeting is enabled with a budget large enough for the complete `ExecutionContext`, prompt bytes and all existing execution behavior also remain unchanged.

## Motivation

PRD-006 established a structured, deterministic `ExecutionContext`, explicit provenance, and per-document estimates, but deliberately did not decide what to omit when context is bounded. The current renderer therefore sends every directly referenced document regardless of total size.

Unbounded document context increases cost, latency, and the chance of exceeding an agent or provider context window. That problem does not require semantic inference. The available inputs already distinguish the mandatory PRD from directly referenced contracts, ADRs, and supporting documents. Familiar can apply an explicit policy to those facts, make the result reproducible, and explain every decision.

This increment creates that policy boundary while preserving the repository as truth. It does not summarize or alter source, and it keeps budgeting independent of prompt rendering and agent execution.

## Scope

This PRD includes:

1. A public deterministic `ContextBudgeter` in `familiar-context`.
2. A configured optional hard ceiling expressed in estimated tokens.
3. A `BudgetedExecutionContext` containing the unchanged repository metadata, mandatory PRD, selected whole directly referenced documents, and checked total estimate.
4. A complete `ContextBudgetReport` covering the PRD and every directly referenced document from the input context.
5. Explicit deterministic priority classes: requested PRD, direct contracts, direct ADRs, and direct supporting documents, with lexical repository-relative path as the stable tie-breaker.
6. Whole-document greedy selection using the existing `familiar_tokens::estimate_tokens` semantics already recorded on `ContextDocument`.
7. Categorized failure when the PRD alone exceeds the hard ceiling or when input estimates are inconsistent or arithmetic overflows.
8. Integration into `familiar run` after `ContextCompiler::compile` and before `render_prompt`.
9. Preservation of current behavior when budgeting is disabled or all input documents fit.
10. Focused unit, configuration, prompt-compatibility, and run-boundary tests.

The budgeter owns selection and reporting only. `ContextCompiler` continues to own repository resolution, validation, direct-reference discovery, source reads, classification, inclusion provenance, ordering, and token estimation. The daemon continues to own configuration loading, prompt rendering, execution history, agent invocation, streaming, pricing, and exit propagation.

- use local Ollama or any remote model;
- summarize, rewrite, compress, normalize, or otherwise transform document content;
- truncate or partially include a document;
- create embeddings or use vector, semantic, fuzzy, keyword, or full-text search;
- infer relevance, priority, or relationships from document content;
- discover additional documents or follow recursive or transitive references;
- route between models, coding agents, or reviewers;
- execute an agent, command, test, build, formatter, or verification step inside the budgeter;
- persist a budgeted context, report, prompt, or other context artifact;
- add a database schema or migration;
- hash, cache, deduplicate by content, or create immutable context artifacts;
- modify a source document or repository file during budgeting;
- change the existing deterministic token estimator;
- budget prompt template text, fixed execution constraints, headings, separators, metadata, protocol overhead, output tokens, or provider billing tokens;
- add per-kind sub-budgets, reserved-token policies, dynamic budgets, model-specific limits, or fallback budgets;
- add a new CLI command, flag, report output, database field, MCP operation, dashboard surface, or history presentation;
- change direct-reference discovery or PRD-006 validation semantics; or
- modify philosophy, architecture documents, ADRs, contracts, or prior PRDs.

## Architecture

The implementation extends the existing deterministic context pipeline with one pure selection stage:

```text
familiar run <prd-path>
          |
          v
ContextCompiler::compile
          |
          v
ExecutionContext
  - requested PRD
  - lexically ordered direct documents
  - exact content and token estimates
          |
          v
ContextBudgeter::budget(configured hard ceiling)
  - validate estimates
  - require the PRD
  - rank direct documents by explicit policy
  - select whole documents greedily
  - record every decision
          |
          v
BudgetedExecutionContext + ContextBudgetReport
          |
          v
existing prompt renderer
          |
          v
existing history + CodingAgent execution
```

`ContextBudgeter` is a deterministic domain service in `familiar-context`. It must not depend on `familiar-agent`, `familiar-llm`, storage, MCP, daemon orchestration, a network service, or host process execution. Given equal `ExecutionContext` and `ContextBudget`, it returns an equal result.

Selection order and render order are deliberately distinct:

- **Selection order** applies the priority rules in this PRD and is recorded in the report.
- **Render order** preserves the input `ExecutionContext.documents` order among selected documents.

PRD-006 defines the input document order as lexical repository-relative path order, and the current renderer consumes that order. Preserving it ensures that disabling budgeting or supplying a sufficiently large budget produces byte-for-byte identical prompts. Selection membership is determined only by the priority order; restoring selected documents to input order must never change which documents were selected.

The budget applies to document content only, matching `ExecutionContext.estimated_tokens`. The report makes this scope explicit so the configured value is not misrepresented as a model context-window or billing-token guarantee.

## Public Types

Exact Rust field names and module layout may follow repository conventions, but the public semantic contract must be equivalent to:

```rust
#[derive(Debug, Default, Clone, Copy)]
pub struct ContextBudgeter;

impl ContextBudgeter {
    pub fn budget(
        &self,
        context: ExecutionContext,
        budget: ContextBudget,
    ) -> Result<BudgetedExecutionContext, ContextBudgetError>;
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct ContextBudget {
    pub hard_ceiling_tokens: u64,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct BudgetedExecutionContext {
    pub repository: RepositoryContext,
    pub prd: ContextDocument,
    pub documents: Vec<ContextDocument>,
    pub estimated_tokens: u64,
    pub report: ContextBudgetReport,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ContextBudgetReport {
    pub hard_ceiling_tokens: u64,
    pub input_estimated_tokens: u64,
    pub included_estimated_tokens: u64,
    pub excluded_estimated_tokens: u64,
    pub decisions: Vec<ContextBudgetDecision>,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ContextBudgetDecision {
    pub path: String,
    pub kind: DocumentKind,
    pub estimated_tokens: u64,
    pub priority: ContextPriority,
    pub selection_index: u64,
    pub outcome: ContextBudgetOutcome,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
pub enum ContextPriority {
    RequestedPrd,
    DirectContract,
    DirectAdr,
    DirectSupporting,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ContextBudgetOutcome {
    Included(ContextInclusionReason),
    Excluded(ContextExclusionReason),
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ContextInclusionReason {
    RequestedPrdMandatory,
    FitsWithinRemainingBudget {
        remaining_before_tokens: u64,
        remaining_after_tokens: u64,
    },
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ContextExclusionReason {
    ExceedsRemainingBudget {
        required_tokens: u64,
        remaining_tokens: u64,
    },
}
```

The API may borrow and clone selected values instead of consuming `ExecutionContext`, provided ownership is explicit and output semantics are identical. Validated newtypes for token counts and repository-relative paths are acceptable.

The report contract is:

- it contains exactly one decision for the PRD and exactly one for every element of `ExecutionContext.documents`;
- `decisions` is in selection order, with the mandatory PRD first and then referenced documents in priority order;
- `selection_index` is zero-based and matches the entry's position after checked conversion;
- every outcome is a closed, typed reason rather than free-form text;
- each decision repeats only inspectable metadata, not document content;
- `included_estimated_tokens` equals `BudgetedExecutionContext.estimated_tokens`;
- `input_estimated_tokens` equals the validated input context total;
- `excluded_estimated_tokens` is the checked sum of excluded document estimates; and
- included plus excluded estimates equal the validated input total.

`ContextBudgetError` must distinguish at minimum:

- `PrdExceedsHardCeiling`, carrying the PRD path, PRD estimate, and configured ceiling;
- invalid PRD kind or inclusion provenance;
- invalid directly referenced document kind or provenance;
- duplicate document path, a referenced document path equal to the PRD path, or another malformed input context;
- a per-document estimate that does not match the existing deterministic estimator applied to exact content;
- an aggregate input estimate that does not match the checked sum of its documents;
- token arithmetic overflow; and
- report index conversion overflow.

Errors identify the affected path where applicable and must contain no agent, provider, prompt-rendering, persistence, or execution concerns.

## Configuration

Add one optional execution-context setting to `familiar-core::Config`, using repository naming conventions:

```toml
[execution_context]
# hard_ceiling_tokens = 12000
```

The semantic configuration is:

```rust
pub struct ExecutionContextConfig {
    pub hard_ceiling_tokens: Option<u64>,
}
```

Rules:

1. `None` means budgeting is disabled. This is the default and preserves current behavior.
2. `Some(value)` enables budgeting with exactly that hard ceiling; zero is valid configuration and necessarily fails for every non-empty PRD.
3. No implicit default ceiling, environment-sensitive ceiling, model lookup, or automatic adjustment is permitted.
4. Existing Figment environment mapping makes `FAMILIAR_EXECUTION_CONTEXT__HARD_CEILING_TOKENS` the corresponding override; no separate environment parser is introduced.
5. Invalid syntax or values outside `u64` fail through existing configuration loading before compilation or execution.
6. Configuration contains no model, provider, agent, summarization, Ollama, or fallback setting for budgeting.

When disabled, `familiar run` passes the original `ExecutionContext` directly to the existing renderer. It must not construct a synthetic maximum budget or run the budget algorithm. This avoids architecture-dependent sentinel values and guarantees the existing path remains unchanged.

## Budgeting Algorithm

For enabled budgeting, the algorithm is exact and ordered:

1. Validate the `ExecutionContext` structural invariants, inclusion provenance, uniqueness, every per-document token estimate, and its aggregate estimate. Recompute estimates with `familiar_tokens::estimate_tokens` over exact document content and use checked conversion and addition.
2. Read `hard_ceiling_tokens` exactly as configured. No prompt reserve or correction factor is subtracted.
3. Create the PRD report decision at selection index zero with priority `RequestedPrd`.
4. If `prd.estimated_tokens > hard_ceiling_tokens`, return `PrdExceedsHardCeiling` immediately. Return no partial context and do not render a prompt, open execution history, or invoke an agent.
5. Include the complete PRD with reason `RequestedPrdMandatory`. Set `used_tokens` to the PRD estimate.
6. Rank all directly referenced documents by the tuple `(priority, path)`, where priority is:
   1. `DocumentKind::Contract` -> `DirectContract`;
   2. `DocumentKind::Adr` -> `DirectAdr`;
   3. `DocumentKind::Supporting` -> `DirectSupporting`.
7. Compare paths by their existing canonical `/`-separated repository-relative string using Rust bytewise lexical `Ord`. No locale, filesystem enumeration order, case folding, natural-number sorting, or platform separator conversion participates.
8. Visit each ranked document exactly once. Compute `remaining = hard_ceiling_tokens - used_tokens` with checked arithmetic.
9. If the document's complete estimate is less than or equal to `remaining`, include it, record `FitsWithinRemainingBudget` with the before and after values, and add its estimate to `used_tokens` with checked arithmetic.
10. Otherwise exclude it and record `ExceedsRemainingBudget` with the exact required and remaining values. Continue evaluating later documents; a later whole document may fit even when an earlier, larger document does not.
11. Construct `BudgetedExecutionContext.documents` by filtering the original `ExecutionContext.documents` to selected paths without reordering them.
12. Compute and validate all report totals with checked arithmetic. Assert that the output estimate is at most the hard ceiling and that included plus excluded estimates equal the input estimate.
13. Return the complete budgeted context and report.

No document is truncated, partially included, replaced, summarized, or reconsidered. There is no optimization, backtracking, bin packing, randomization, content inspection, or hidden tie-breaker.

The ceiling is hard with respect to the estimator and scope defined here:

```text
BudgetedExecutionContext.estimated_tokens <= hard_ceiling_tokens
```

Because template and protocol tokens are intentionally outside scope, the ceiling is not a guarantee about the final provider request size.

## Inclusion and Exclusion Reasons

Every input document receives exactly one outcome.

| Document | Outcome | Exact reason |
|---|---|---|
| Requested PRD that fits | Included | `RequestedPrdMandatory` |
| Direct contract that fits when visited | Included | `FitsWithinRemainingBudget { remaining_before_tokens, remaining_after_tokens }` |
| Direct ADR that fits when visited | Included | `FitsWithinRemainingBudget { remaining_before_tokens, remaining_after_tokens }` |
| Direct supporting document that fits when visited | Included | `FitsWithinRemainingBudget { remaining_before_tokens, remaining_after_tokens }` |
| Any direct document that does not fit whole | Excluded | `ExceedsRemainingBudget { required_tokens, remaining_tokens }` |

An oversized PRD is a budgeting failure, not an exclusion outcome, because a successful result may never exclude the requested PRD. Malformed input or arithmetic failure is also an error rather than a fabricated document decision.

The original `ContextDocument.inclusion` remains unchanged in every selected document. It explains why compilation discovered the document. `ContextBudgetOutcome` separately explains why budgeting retained or omitted it. The two provenance layers must not overwrite or conflate each other.

## Data Flow

1. `familiar run <prd-path>` loads `Config` through the existing path.
2. The run pipeline resolves the current directory and calls `ContextCompiler::compile` exactly as established by PRD-006.
3. If `execution_context.hard_ceiling_tokens` is `None`, run renders the original `ExecutionContext` without budgeting.
4. If a ceiling is configured, run passes the complete `ExecutionContext` and ceiling to `ContextBudgeter`.
5. The budgeter validates estimates and structure, selects whole documents, and returns `BudgetedExecutionContext` with its in-memory report.
6. Run passes the budgeted PRD and selected documents to the existing renderer. The renderer does not rank, estimate, omit, truncate, summarize, or inspect the report.
7. Only after successful compilation, optional budgeting, and prompt rendering does the existing execution-history and agent flow continue.
8. The report remains available to the in-process caller for inspection and tests but is not persisted or printed by this PRD.

The renderer should consume a small shared view or trait implemented by both context forms, or the disabled path may use the existing type directly. It must not duplicate prompt templates. The implementation choice must retain one renderer and preserve exact current prompt bytes whenever all documents are selected.

## Failure Semantics

Budgeting failures are pre-execution failures.

- If the PRD alone exceeds the configured ceiling, `familiar run` returns a non-zero exit before prompt rendering, database opening or migration, execution-history insertion, agent construction/invocation, or output streaming.
- The error message identifies the PRD path, its estimated tokens, and the configured hard ceiling.
- Invalid input invariants, inconsistent estimates, and arithmetic failures follow the same boundary and invoke no agent.
- A directly referenced document that does not fit is not an error. It is excluded whole and recorded in the successful report.
- An exact fit succeeds.
- A zero-token document fits without changing remaining budget and still receives an explicit decision.
- Budgeting performs no filesystem write, source mutation, persistence, process execution, or network call.
- Existing context-compilation, configuration, storage, agent, finalization, and exit-code errors retain their current categories and behavior.
- No execution-history row is created for a context-budget failure, matching the current pre-history compilation-failure boundary.

`RunError` may add a distinct context-budget variant that transparently displays `ContextBudgetError`. It must not collapse a budget failure into agent or storage failure.

## Acceptance Criteria

1. A public `ContextBudgeter` accepts an `ExecutionContext` and `ContextBudget` and returns a `BudgetedExecutionContext` without using an LLM or external process.
2. Every successful result contains the requested PRD, unchanged and exactly once.
3. The output's checked document-content estimate never exceeds the configured hard ceiling.
4. The PRD alone exceeding the ceiling returns a categorized error before prompt rendering, history creation, or agent execution.
5. Direct documents are selected by contract, ADR, supporting priority, then bytewise lexical canonical repository-relative path.
6. Selection is deterministic for equal inputs and is independent of input vector order, filesystem enumeration, locale, platform, time, random state, network state, model availability, and document prose.
7. Each document is included whole or excluded whole; no content is truncated, summarized, rewritten, normalized, or partially copied.
8. Selected `ContextDocument` values, including content and original compilation inclusion provenance, compare equal to their input values.
9. The report contains exactly one selection-ordered decision for the PRD and every direct input document, with one closed typed inclusion or exclusion reason each.
10. Inclusion reasons record exact remaining budget before and after selection; exclusions record exact required and remaining tokens.
11. Report totals are checked, internally consistent, and reconcile exactly to the validated input context total.
12. Per-document and aggregate estimates are validated against `familiar_tokens::estimate_tokens`; inconsistent input fails rather than weakening the ceiling.
13. An oversized referenced document is excluded and later ranked documents continue to be considered.
14. Exact-fit PRDs and referenced documents are included; zero-token documents receive deterministic outcomes.
15. `BudgetedExecutionContext.documents` preserves the original lexical render order among selected documents even though report decisions use priority selection order.
16. `familiar run` applies enabled budgeting after context compilation and before the existing renderer.
17. With budgeting disabled by default, existing prompt bytes, CLI syntax, stdout, stderr, execution, history, usage, pricing, and exit behavior remain unchanged.
18. With a configured ceiling greater than or equal to the validated complete context estimate, all documents are selected and the rendered prompt is byte-for-byte identical to the disabled/current prompt.
19. An enabled budget that excludes documents changes only which complete referenced-document sections are rendered; the fixed constraints, PRD section, selected source bytes, headings, separators, and relative order remain unchanged.
20. The budgeter has no dependency on agent, LLM, Ollama, embedding, router, storage, MCP, dashboard, or network code.
21. No context, report, prompt, hash, cache, or other artifact is newly persisted.
22. No source file is modified and no agent is executed by the budgeter.
23. No schema, migration, CLI option, MCP surface, architecture document, ADR, contract, philosophy document, or prior PRD changes.
24. The implementation is one independently mergeable deterministic budgeting increment.

## Test Strategy

### Budgeter unit tests

- Budget the same context repeatedly and assert equal output and report.
- Permute the input direct-document vector and assert identical selected membership and selection-ordered decisions after normalizing only the output render order to each validated input contract; production compiler input remains lexical.
- Assert the PRD is mandatory, first in the report, and unchanged in the output.
- Assert contracts rank before ADRs, ADRs before supporting documents, and lexical paths break ties.
- Assert a lower-priority document is excluded when an earlier higher-priority document consumes the available budget.
- Assert an oversized higher-priority document is excluded while a later smaller document that fits is included.
- Assert exact-fit, one-token-short, zero ceiling, empty document, Unicode, and zero-token cases.
- Assert no document content or compilation inclusion reason changes.
- Assert output documents retain input lexical render order among selected paths.
- Assert the report covers every input document exactly once with exact priority, index, outcome, and before/after or required/remaining values.
- Assert included, excluded, and input totals reconcile and the output total equals the included total.
- Assert duplicate paths, PRD path reuse, wrong kinds, wrong inclusion provenance, mismatched per-document estimates, mismatched aggregate estimate, and checked arithmetic/index overflow return categorized errors.
- Assert estimates for ASCII, Unicode, empty, and boundary fixtures exactly match `familiar_tokens::estimate_tokens`.
- Use focused injectable validation helpers for otherwise impractical integer-overflow cases; do not allocate enormous documents.

### Configuration tests

- Assert absent `[execution_context]` and absent `hard_ceiling_tokens` deserialize to disabled budgeting.
- Assert an explicit ceiling, zero, config-file value, and `FAMILIAR_EXECUTION_CONTEXT__HARD_CEILING_TOKENS` override deserialize correctly through existing Figment behavior.
- Assert invalid and out-of-range values fail through existing configuration errors.
- Assert unrelated existing configuration remains unchanged.

### Run and prompt tests

- Preserve existing complete prompt fixtures byte for byte when budgeting is disabled.
- Configure a ceiling equal to the complete context estimate and assert the prompt is byte-for-byte unchanged.
- Configure a larger ceiling and assert the same compatibility.
- Configure a selective ceiling and assert only whole excluded document sections disappear while the PRD and selected sections retain exact bytes and lexical render order.
- Use mixed contract, ADR, and supporting fixtures whose lexical and priority orders differ, and assert selection follows priority while rendering preserves lexical order.
- Assert PRD-over-budget failure occurs before renderer observation, database/history creation, and fake-agent invocation.
- Assert successful selective budgeting invokes the fake agent once with the expected worktree and exact prompt.
- Preserve fake-Codex integration expectations for arguments, stdin, streaming output, stderr, exit status, history, metrics, and pricing when budgeting is disabled and when all documents fit.
- Assert no budget report or new diagnostics are printed on successful runs.

### Verification commands

Implementation must run:

- `cargo fmt --all -- --check`;
- focused `familiar-context` budgeting and existing compiler tests;
- focused `familiar-core` configuration tests;
- focused daemon prompt, fake-agent, and pre-execution failure tests;
- the fake-Codex CLI integration suite;
- Clippy with warnings denied for affected crates and targets; and

Existing test expectations may change only to inject configuration or cover intentional document omission under an enabled selective budget. Disabled and all-fit prompt snapshots, output, execution, history, pricing, and exit expectations must not change.

## Definition of Done

PRD-007 is done when:

1. `ContextBudgeter` deterministically transforms a valid `ExecutionContext` and configured hard ceiling into a complete `BudgetedExecutionContext` and inspectable report.
2. The requested PRD is always included unchanged, and a PRD that alone exceeds the ceiling fails before prompt rendering, persistence, or execution.
3. Whole direct documents are selected by contract, ADR, supporting priority and lexical path tie-breaker without content-based inference.
4. Every input document has one exact, typed inclusion or exclusion reason, and all report totals reconcile.
5. The existing deterministic estimator is the sole token estimator and the successful output estimate is never above the configured ceiling.
6. No document is summarized, rewritten, truncated, partially included, hashed, cached, persisted, or modified.
7. No LLM, Ollama service, embedding, vector or semantic search, model or agent router, network service, or coding agent participates in budgeting.
8. `familiar run` budgets only when configured and does so between context compilation and the one existing prompt renderer.
9. Disabled and sufficiently large budgets preserve current prompt bytes and all current run, history, pricing, output, and exit behavior.
10. Focused budgeting, configuration, prompt, fake-agent, and fake-Codex tests pass; formatting and focused Clippy pass; and the workspace suite is attempted with unrelated failures reported separately.
11. No schema, migration, new CLI surface, MCP change, architecture document, ADR, contract, philosophy document, prior PRD, or unrelated subsystem changes.
12. The implementation remains independently mergeable as one bounded deterministic context-budgeting change.
