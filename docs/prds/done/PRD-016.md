# PRD-016: Linux Review Isolation

**Status:** Completed
**Date:** 2026-08-04
**Depends on:** PRD-008, PRD-014
**Architectural direction:** Trust Is Earned Through Verification; Determinism Before Intelligence; Agents Are Replaceable
**Delivery boundary:** Independently mergeable Linux enforcement of the existing denied-read-path isolation contract

## Objective

Enforce the existing `denied_read_path` isolated-review contract on Linux so enabled-review runs can execute on the primary development machine.

Today the shared isolation helper in `familiar-ai-agent` enforces denied reads only through macOS `sandbox-exec`; on every other platform an isolated launch fails closed with the unsupported-isolation error. This PRD adds a Linux enforcement mechanism using `bwrap` (bubblewrap): the child process runs in a mount namespace where the denied repository tree is masked by an empty tmpfs, so the reviewer can read nothing from it while the rest of the filesystem remains visible unchanged. The fail-closed behavior is preserved exactly for platforms and environments where enforcement cannot be established: a launch that cannot guarantee isolation never runs.

## Motivation

PRD-008 defined isolated adversarial review and PRD-011 made clean review the only path to backlog completion. PRD-014 made reviewer selection deterministic across two adapters through one shared, audited isolation helper. But `StructuredReviewAdapter` always sets `denied_read_path`, and on Linux the helper fails closed — so on the Linux development machine no enabled-review run can reach a reviewer at all. This is the single gap standing between the current system and unattended runs on the machine Familiar actually lives on: until it closes, Familiar cannot execute its own backlog with review enabled, and every completion requires macOS or a manual override. Closing it is the first item of the north star's Stage 1.

Bubblewrap is chosen over Landlock deliberately. The contract is "the child must be unable to read one specific tree, everything else unchanged." Landlock's model is an allowlist — expressing "everything except one subtree" requires enumerating and re-granting the siblings of every ancestor of the denied path, a fragile inversion that changes meaning whenever the filesystem around the repository changes. Bubblewrap expresses the contract directly: bind the filesystem through unchanged, mask the denied tree with an empty tmpfs. It also mirrors the existing macOS shape — an external, auditable wrapper binary in front of an unmodified adapter argv — so both platforms share one code path in `isolated_command`.

## Scope

This PRD includes:

1. Linux implementation of the shared `isolated_command` helper in `familiar-ai-agent`, wrapping the adapter executable with a deterministic `bwrap` invocation that masks the canonicalized denied tree with an empty tmpfs.
2. A deterministic launch-time capability probe: before the real child is spawned, the identical `bwrap` wrapper executes `/bin/true`; probe failure surfaces the existing `Launch` error with the probe's exact diagnostic, and the agent is never executed.
3. Preservation of every existing isolation-contract rule: canonicalization failures fail the launch; version probing remains skipped inside the isolation boundary; prompt delivery, streaming, timeout process-group kill, and the error taxonomy are unchanged; both the Codex and Claude Code adapters gain Linux isolation through the one shared helper with no adapter-specific code.
4. Test-environment plumbing so the positive isolation path is verifiable through Docker: the tester image installs `bubblewrap`, and the compose `test` service gains the capabilities required to create mount namespaces in the container.
5. Focused tests covering the pinned wrapper argv, the denied-read proof, and the fail-closed probe path, using fake executables and temporary directories only.

## Non-goals

This PRD does not:

- use Landlock, seccomp, chroot, containers, or any mechanism other than bubblewrap for this contract;
- change what is denied: exactly the one `denied_read_path` tree, read-masked; no write restrictions, network isolation, environment filtering, or device policy beyond what the existing contract already implies;
- alter macOS `sandbox-exec` behavior, the unsupported-platform error for other platforms, or any adapter argv;
- add configuration: the mechanism is not selectable, and no new keys, flags, or environment variables are introduced;
- introduce a general sandboxing framework, execution warrants, or per-task isolation policy;
- change review coordination, reviewer independence, verification, budgets, backlog semantics, or accounting; or
- modify prior PRDs, architecture documents, ADRs, contracts, or philosophy.

## Mechanism

On Linux, `isolated_command(executable, Some(denied))` returns a command equivalent to:

```text
bwrap --dev-bind / / --tmpfs <canonical-denied> --die-with-parent -- <executable>
```

- `--dev-bind / /` binds the existing filesystem through unchanged, preserving device nodes; the child observes the same system it would without isolation.
- `--tmpfs <canonical-denied>` masks the denied tree with an empty tmpfs: every path beneath it reads as absent, and nothing from the real tree is reachable.
- `--die-with-parent` ties the sandbox to the adapter watchdog's process-group kill so a timeout cannot orphan the inner child.
- The denied path is canonicalized first, exactly as the macOS branch does; canonicalization failure is the existing `Launch` error.
- Argv is constructed directly — no shell, no interpolation of prompt or repository-derived text — and the adapter's own argv follows the `--` separator unmodified.

The capability probe runs the identical wrapper with `/bin/true` as the command, once per isolated launch, with a bounded wait. A non-zero exit, spawn failure, or missing `bwrap` binary produces the existing `Launch` error carrying the probe's diagnostic; the adapter executable is never spawned without a proven sandbox. Environments that cannot create mount namespaces (missing bubblewrap, blocked user namespaces without privilege) therefore keep today's exact fail-closed behavior with a more precise message.

macOS continues to use `sandbox-exec` unchanged. All other platforms continue to fail closed with the existing unsupported-isolation error.

## Test Environment

The Docker tester stage installs `bubblewrap` from the distribution repositories. The compose `test` service is granted the container capabilities needed for mount-namespace creation (`SYS_ADMIN` capability with AppArmor and seccomp unconfined for this service only). This affects only the test container; production behavior depends solely on the host's own bubblewrap availability, and hosts without it keep the fail-closed path.

## Acceptance Criteria

1. On Linux, an isolated execution launches the adapter through the pinned `bwrap` wrapper, and the child cannot read any file beneath the canonicalized `denied_read_path` while files outside it remain readable.
2. The wrapper argv is exactly the pinned constant sequence with the canonical denied path and the unmodified adapter argv after `--`; no shell is involved and no prompt or repository-derived text appears in argv.
3. A launch-time probe proves sandbox creation before the adapter runs; when the probe cannot succeed, the launch fails closed with the existing `Launch` error naming the failure, and the adapter executable is never spawned.
4. Canonicalization failure of the denied path fails the launch exactly as on macOS, and version probing remains skipped inside the isolation boundary.
5. Both the Codex and Claude Code adapters obtain Linux isolation exclusively through the shared helper, with no adapter-specific isolation code and byte-identical non-isolated behavior.
6. macOS `sandbox-exec` behavior and the non-Linux/non-macOS unsupported-isolation error are unchanged.
7. Timeout enforcement still kills the whole process group with no orphaned sandbox child, and the existing error taxonomy, streaming, and accounting semantics are unchanged.
8. The Docker test environment can exercise the positive isolation path; in an environment where sandbox creation is impossible, the tests assert the fail-closed probe behavior instead of silently skipping.
9. No new configuration, dependencies beyond the `bwrap` system binary in the test image, or isolation mechanisms are introduced.
10. The change is confined to the expected files and is independently mergeable.

## Test Strategy

- **Wrapper argv:** a unit test pins the exact `bwrap` argv (flag order, canonical path placement, `--` separator, adapter argv passthrough) without executing anything.
- **Denied-read proof (Linux):** mirror of the macOS isolation test through the shared helper — a fake executable attempts to `cat` a file inside the denied tree and a file outside it; the test asserts the inner read fails while the outer read succeeds. The test first runs the capability probe: if the environment can sandbox, the positive proof must pass; if it cannot, the same test asserts the `Launch` fail-closed error with the probe diagnostic. Neither branch is a skip.
- **Probe failure:** with a `PATH` containing no `bwrap`, an isolated launch fails closed with `Launch` before any adapter process is spawned (asserted with a recording fake executable that must never run).
- **Adapter neutrality:** the denied-read proof runs through both `CodexAgent` and `ClaudeCodeAgent` with fake executables, proving the shared helper serves both.
- **Regression:** existing agent, review, and workspace suites pass unchanged; non-isolated executions are byte-identical.
- Verification pipeline: `cargo fmt --all -- --check`, focused Clippy with warnings denied, `cargo test -p familiar-ai-agent`, and `cargo test --workspace`, with demonstrably pre-existing failures reported separately with exact evidence.

## Definition of Done

PRD-016 is done when:

1. An enabled-review run on the Linux development machine reaches reviewer execution inside a proven sandbox that cannot read the repository tree, through both adapters, with no orchestration change.
2. Every environment that cannot prove the sandbox keeps today's fail-closed launch behavior, now with the probe's exact diagnostic.
3. The wrapper argv, probe, and denied-read guarantees are pinned by tests that run in the Docker pipeline, with the fail-closed branch asserted where sandboxing is impossible.
4. Formatting, focused Clippy, the agent suite, and the full workspace suite pass, or demonstrably pre-existing failures are recorded with exact evidence.
5. Only the expected files change, and the increment merges independently.
