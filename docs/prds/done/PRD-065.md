# PRD-065: Ready-Set Scheduling and Session Warrant Integrity

## Objective

Make parallel execution real and bounded: schedule from the current ready
set instead of one-per-dependency-component, confine a session to an
explicit operator-approved PRD set, resolve worktree policy through
repository identity rather than paths, and complete reviewed checkpoints
transactionally. These are the four orchestration defects (Wave 1
after-action report, defects 1–3 and 7) that block trustworthy parallel
execution of every later wave.

## Design

### Ready-set scheduling replaces component mutual exclusion

`select_batch` currently admits at most one active PRD per weakly
connected dependency component, and `dependency_components` builds
undirected adjacency over the entire discovered graph including completed
PRDs. Any backlog with shared completed ancestors is therefore one
component, and effective width is one regardless of requested
concurrency. Wave 1's intended width of six collapsed to one exactly this
way.

Dependencies are admission gates, not mutual-exclusion edges. Selection
admits every pending PRD whose dependencies are completed, bounded by the
warrant width, and serializes two ready PRDs only for a genuine conflict:

- overlapping mutable expected-file scopes, computed by the same
  expected-file set-intersection contract PRD-020 established (exact
  file, `dir/`, and `dir/**` overlap semantics), or
- an explicitly declared resource conflict.

Component identity may survive as a reporting label; it must not gate
admission. Every selection and every deferral persists a machine-readable
reason (`ready_selected`, `deferred_scope_overlap` naming the overlapping
scope and holder, `deferred_resource` naming the resource,
`deferred_width` naming the exhausted warrant). The regression suite must
encode the actual Wave 1 graph — six pending PRDs, completed shared
ancestors — and prove width six.

### The session warrant gains an explicit PRD allowlist

A count warrant cannot express an approved set: after PRD-044 completed,
a `--max-prds 3` Wave 1 session selected PRD-041 from Wave 2 and had to
be interrupted and its claim released by hand. The warrant accepts an
optional immutable PRD allowlist (repeatable `--prd` values). When
present, selection, claim, retry, and every recovery and continuation
path operate strictly inside the allowlist; the resolved set is recorded
in the durable warrant record alongside the existing ceilings, and the
flags-tighten-only rule extends to it (an allowlist may only shrink an
inherited set, never widen it). An empty intersection with the ready set
terminates with the existing nothing-eligible reason, never widens.

Width honesty is part of the same contract: when the requested
concurrency exceeds what the ready set and conflict rules can achieve,
the session reports the achievable width at start instead of silently
accepting the flag.

### Worktree policy resolves through repository identity

Per-repository configuration (`repositories.*`) is keyed by worktree
path, so a preserved lease worktree in a later process fails policy
resolution unless an operator adds a temporary path-specific entry —
which made manual parallel orchestration unsafe. Resolution moves to Git
common-directory repository identity (the canonical identity
`RepositoryIdentity` already computes), and the checkpoint pins the
resolved policy identity so `resume` in any worktree of the same
repository resolves the same policy without new configuration. Explicit
path-keyed entries remain valid input; they resolve through the same
identity and conflicting entries for one identity fail closed with a
naming diagnostic.

### Transactional approve-and-complete for reviewed checkpoints

After human review of a retained checkpoint, the advertised verbs compose
into dead ends: `backlog release` returns the entry to pending while
`backlog complete` requires an in-progress claim, and committing the
reviewed candidate makes the old checkpoint report `stale_base`. One
transactional `approve-and-complete` operation accepts a reviewed
checkpoint, binds the approved candidate hash and the resulting commit,
records the approving actor, and moves the entry to completed — atomically
with the audit row, in the PRD-046/047 decision-row style. An interrupted
operation leaves the entry in exactly one of the prior or completed
states. Recovery guidance becomes state-aware: help for a retained or
interrupted PRD prints only the commands valid for the entry's current
persisted state.

## Scope

- Rework selection in `drive.rs` (ready-set admission, conflict
  serialization, persisted selection/deferral reasons, achievable-width
  reporting).
- Reuse and, where needed, extend the PRD-020 expected-file intersection
  logic in `plan.rs`; no new scope grammar.
- Warrant allowlist: CLI flags, tighten-only inheritance, durable warrant
  record extension (migration plus repository support).
- Policy resolution by repository identity in `config.rs` and
  `worktree.rs`; checkpoint pinning of policy identity.
- `approve-and-complete` verb in the CLI with a transactional storage
  operation and state-aware recovery help.
- Regression tests including the recorded Wave 1 graph at width six and
  an injected interruption of approve-and-complete.

Out of scope: token and cost accounting (PRD-051 owns budget-category
separation, after-action defect 5), review-retry continuation policy and
escalation (PRD-041, defects 9–10), interactive scope-finding approval
(defect 6, follow-up to PRD-033), implementation-prompt and terminal-
classification corrections (defects 4, 8, 10–11), and configuration
mutation journaling (defect 12 follow-up).

## Assumptions (recorded at specification time, 2026-08-30)

- The Wave 1 dependency graph is available from the repository history and
  `docs/prds/done/` frontmatter to encode as a fixture.
- `RepositoryIdentity` (canonicalized Git common-directory key) remains
  the canonical repository identity and is computable from any linked
  worktree.
- The decision-row audit pattern from PRD-046/047 (single transaction,
  actor attribution) is the template for the approve-and-complete audit
  record.
