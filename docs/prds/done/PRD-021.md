# PRD-021: Zero-Install Linux Isolation via Landlock

**Status:** Completed
**Date:** 2026-08-04
**Depends on:** PRD-016
**Architectural direction:** Trust Is Earned Through Verification; Determinism Before Intelligence; Small, Bounded Work Wins
**Delivery boundary:** Independently mergeable mechanism swap behind the unchanged denied-read isolation contract

## Objective

Replace the Linux review-isolation mechanism — currently the external `bwrap` binary — with Landlock, the kernel's unprivileged sandboxing syscall API, so the denied-read guarantee compiles into `familiar-ai` itself with no system package, no user namespaces, and no container capabilities.

The contract, the probe-before-spawn design, the fail-closed behavior, and the denied-read test suite from PRD-016 are unchanged; only the enforcer behind them changes. macOS `sandbox-exec` and the other-platform fail-closed arm are untouched.

## Motivation

PRD-016 delivered a working Linux sandbox but with an installation footnote: hosts need `bubblewrap`, and the Docker test service needed `SYS_ADMIN` with AppArmor and seccomp unconfined to create user namespaces. Landlock needs none of that: it is a plain unprivileged syscall API present in every kernel since 5.13, unaffected by Ubuntu's user-namespace AppArmor restriction, and invocable from inside unprivileged containers. For a tool whose mission is "load your agents, Familiar loads with them," the isolation guarantee should travel inside the binary. PRD-016's pinned tests are what make this swap cheap: the guarantee stays pinned while the enforcer is exchanged.

## Mechanism

Landlock is allowlist-only, so "everything except the denied tree" is expressed by enumeration at launch time:

- **Handled accesses:** the read and execute filesystem access rights for the kernel's best available Landlock ABI (`read_file`, `read_dir`, `execute`). Write-class rights are deliberately not handled: writes stay governed by the existing `FilesystemPolicy`/permission-mode machinery, and handling execute prevents the exfiltration edge of executing an unreadable binary.
- **Ruleset construction (before fork, ordinary safe code):** canonicalize the denied path exactly as today; walk from the filesystem root to the denied path's parent; at every level grant the full handled access set to each directory entry that is not the next ancestor on the path; grant nothing to the denied path itself. The ruleset is a file descriptor prepared entirely pre-fork.
- **Application (in the child, between fork and exec):** `PR_SET_NO_NEW_PRIVS` followed by `landlock_restrict_self` — two async-signal-safe syscalls only — then exec of the unmodified adapter argv. No wrapper process exists; the adapter is the direct child, and the existing process-group timeout kill applies to it exactly as on macOS.
- **Documented semantic sharpening:** because Landlock grants cascade to subtrees, the ancestors of the denied path (for example the parent directory holding the repository) receive no rule and are therefore not listable or readable themselves, while every non-denied entry beneath them is fully granted. The child loses directory listings of the repository's ancestors — a strictly more restrictive posture than PRD-016's mask, in the fail-closed direction, and irrelevant to review execution which works in its own workspace. Entries created inside an ancestor after ruleset construction are unreadable to the child: also fail-closed.
- **Probe:** before any agent spawn, the launch verifies kernel Landlock support (ABI query) and constructs the ruleset; any failure — unsupported kernel, blocked syscalls, enumeration or rule error — surfaces the existing `Launch` error with the exact diagnostic, and the agent is never spawned. A test-only override hook (mirroring PRD-016's) forces the unsupported path deterministically.
- **Dependency:** the `landlock` crate (maintained by the kernel feature's author) is added as the one new workspace dependency; raw syscall bindings are explicitly not hand-rolled.

Removals: the `bwrap` wrapper, its probe, the bubblewrap package in the tester image, and the test service's `SYS_ADMIN`/AppArmor grants. The seccomp setting may be retained only if the container's default profile demonstrably blocks the Landlock syscalls; if retained, the compose comment must say exactly that.

## Non-goals

This PRD does not:

- change the isolation contract, the probe-before-spawn rule, adapter argv, error taxonomy, streaming, timeouts, or any adapter behavior outside the Linux arm of `isolated_command`;
- restrict writes, network, or anything beyond the read/execute denial of the one tree;
- alter macOS or other-platform behavior (Windows remains fail-closed; tracked separately);
- keep bubblewrap as a fallback — one deterministic mechanism per platform; or
- modify prior PRDs, architecture documents, ADRs, contracts, or philosophy.

## Acceptance Criteria

1. On Linux, an isolated execution runs the adapter as a direct Landlock-restricted child that cannot read or execute anything beneath the canonicalized denied path, while non-denied filesystem content granted by the enumeration remains readable; no external sandbox binary is involved.
2. The launch-time probe proves kernel support and ruleset construction before any agent spawn; every failure path surfaces the existing `Launch` error with its diagnostic, deterministically forced in tests via the override hook.
3. Ruleset construction is deterministic for a given filesystem state and is pinned by a unit test over a fixture tree (exact granted paths, exact denied omission).
4. The ancestor-listing semantics are explicit and tested: an ancestor directory of the denied path is not listable; a sibling beneath it is fully readable.
5. The PRD-016 denied-read proofs pass unchanged through both adapters (`DENIED/OK` inside the pipeline where supported; asserted fail-closed where not; never skipped), and the existing timeout, version-probe, and canonicalization rules hold.
6. Bubblewrap is removed from the tester image and the capability grants from the compose test service, with the seccomp caveat handled as specified; the test pipeline still exercises the positive proof.
7. `bwrap` appears nowhere in the implementation surface; the only new dependency is the `landlock` crate.
8. macOS and other-platform arms are byte-identical; non-isolated executions are unchanged.
9. Formatting, focused Clippy, focused agent tests, and the full workspace suite pass, with demonstrably pre-existing failures reported separately with exact evidence; coverage does not decrease.
10. The change is confined to the expected files and is independently mergeable.

## Test Strategy

- Ruleset-enumeration pin over a temp fixture tree: pinned grant list, denied path absent, next-ancestor exclusion at each level.
- Probe: override hook forces the unsupported path — `Launch` error, agent marker file never created; real-kernel probe success path exercised by the proofs below.
- Denied-read proofs (both adapters, unchanged shape): inside `DENIED`, outside `OK`; plus the new ancestor-listing test (parent unlistable, sibling readable).
- Post-enumeration creation: a file added to an ancestor after ruleset construction is unreadable — fail-closed direction pinned.
- Regression: full agent suite, timeout kill of the direct child, macOS tests untouched, workspace suite.

## Definition of Done

PRD-021 is done when Linux review isolation is a syscall-level guarantee compiled into the binary — no package to install, no capabilities to grant — proven by the same pinned denied-read suite that guarded the mechanism it replaces, failing closed with exact diagnostics everywhere the kernel cannot provide it, with bubblewrap fully retired and the whole pipeline green.
