# PRD-044: Per-PRD Worker Selection


## Objective

Route every PRD individually through the registry inside the drive loop and
retire the legacy `model_routes` path the registry silently disables.

## Scope

- At per-job preparation in the drive loop, build a `RouteRequest` from the
  PRD's declared risk classes and expected file count, select implementation
  and remediation workers, and inject them as pins in the per-job execution
  config so `resolved_worker_plan` honors them unchanged.
- Persist routing inputs alongside each worker selection record (migration).
- Remove `routed_model()`; make a configured `driver.model_routes` a
  validation error that names the registry replacement.
- Legacy `[agents]` configurations keep their current fixed behavior.
