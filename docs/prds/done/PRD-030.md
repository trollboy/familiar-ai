# PRD-030: Structured PRD Contract and Profile-Neutral Dependencies

**Status:** Completed
**Date:** 2026-08-26
**Depends on:** PRD-009, PRD-013, PRD-025

## Objective

Define one structured, machine-checkable PRD metadata contract that every
repository profile maps into, so dependencies, scope, risk, and acceptance
authority are never lost or guessed from prose.

## Scope

- Specify versioned front matter for identity, status, dependencies, expected
  files, acceptance criteria, risk classes, and optional external gates.
- Preserve profile-specific filename and heading conventions while producing
  one canonical `DiscoveredPrd` contract.
- Support suffixed identities and direct/transitive dependencies.
- Reject missing references, duplicates, self-dependencies, cycles, ambiguous
  ranges, and contradictory body metadata.
- Provide a deterministic migration/check command; do not silently rewrite
  repository documents during discovery.
- Update scheduling so no profile can discard declared dependencies.

## Acceptance Criteria

1. Canonical and numbered-slug fixtures produce equivalent dependency graphs.
2. A dependent remains ineligible until every prerequisite is completed.
3. Transitive dependencies and suffixed identities are enforced.
4. Prose that resembles metadata grants no authority.
5. Existing repositories receive exact migration diagnostics and can adopt the
   new contract incrementally under an explicit compatibility policy.
6. `next`, `run`, `drive`, and planner validation consume the same parser.
