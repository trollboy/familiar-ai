# PRD-054: OpenAI Platform and Codex Usage Accounting

## Objective

Plug OpenAI into the PRD-051 accounting family as its second provider:
Codex terminal telemetry lands in the same observation ledger with its
reasoning-output category intact, OpenAI Platform organizations become
authoritative billing sources behind the same collector interface
PRD-052 defined for Anthropic, ChatGPT plans stay credits-and-allowance
(never dollars), and every run's billing mode is classified from its
actual authentication before any monetary interpretation. No second
ledger, no second reconciliation engine — PRD-053's machinery consumes
these rows unchanged.

## Design

**Billing mode follows authentication, not assumption.** Codex signs in
three documented ways with different money semantics: ChatGPT sign-in
(consumes plan allowance/credits), an OpenAI Platform API key (metered
API dollars), and enterprise Codex access tokens (workspace
entitlements). Familiar classifies the mode through the documented
`codex login status` command **only if** its machine-readable output,
verified at implementation time, actually distinguishes ChatGPT
sign-in, API-key use, and access-token use — a generic "logged in" is
never a monetary classification. Where the probe cannot distinguish
them, the mode comes from an explicit operator declaration
corroborated by safe observable evidence (documented status or
configuration surfaces — never a read of `~/.codex/auth.json` values),
or it stays unknown. The classification is recorded on the worker
binding. ChatGPT-authenticated runs classify as
`subscription-declaration` mode with credit estimates; API-key runs as
`local-estimate` mode in canonical nanoUSD; access-token runs as workspace
entitlement, never Platform billing authority. An unclassifiable mode
is an explicit unknown that fails closed for finite monetary routing —
a run is never presumed free, and never presumed metered.

**Codex telemetry, exactly once.** The adapter already drives
`codex exec --json` and refuses to invent usage when the stream ends
before `turn.completed`. This PRD completes it: preserve
`reasoning_output_tokens` alongside input, `cached_input_tokens`, and
output (the ledger's reasoning-output category); retain a sanitized
accounting evidence envelope per PRD-051 — usage fields, model and
session identifiers, CLI version, timestamps, terminal status, and a
hash of the source event, never the complete JSONL stream, which can
carry responses, commands, diffs, and paths; persist the terminal
event exactly once per attempt so
`codex exec resume` and replay never double-count; record the Codex CLI
version and observed event-schema shape; keep partial observations from
failed, killed, or timed-out runs as partial, never zero. The JSONL
stream carries no dollar cost and none is ever inferred from it.

**Credits are their own unit.** ChatGPT publishes a credit rate card
(credits per million input, cached-input, and output tokens, varying by
model). A versioned credit schedule — same identity discipline as the
USD price schedules — may produce *estimated credit consumption*
for ChatGPT-authenticated runs. Credits never convert to dollars, never
sum with USD amounts, and never satisfy a dollar warrant. Remaining
allowance and purchased-credit balance are distinct observations; the
documented surfaces today (the interactive `/status` command and the
usage dashboard) are not machine-readable, so remaining allowance is an
explicit unsupported/unknown state — Familiar does not scrape ChatGPT
endpoints or parse browser state. The plan fee itself is an
operator-declared recurring cost, never allocated per run.

**Authoritative Platform collection.** An OpenAI organization becomes a
`kind = "billing"` provider source (PRD-047 grammar, PRD-052 collector
pattern) with its own Admin-key credential reference — a distinct
capability from any project inference key, with distinct process
exposure. Probe-before-persist issues a narrow read-only
`GET /v1/organization/costs` request (no billable model call); the
`organization_id` in the response establishes source identity, and a
credential resolving to an already-bound organization scope is rejected.
Collection follows PRD-052 semantics: UTC half-open windows over the
API's daily cost buckets (`start_time` in Unix seconds, cursor
pagination via `next_page`, completion only after the last page),
append-only rows under PRD-052's revision model — logical identity of
source, organization/project scope, dimensions, and bucket;
payload-hash deduplication; a changed provider value appends a
superseding revision; aggregates read the current-effective
projection. The cost `amount` arrives as a JSON number with
`value` and `currency`: the raw lexical response is retained verbatim
and the normalized value is parsed through exact decimal representation
into integer nanoUSD (half-to-even), never binary floating point. A
collected report is authoritative for its snapshot, not a final
invoice — later credits and restatements supersede through revisions.
`line_item`, credits, grants, and adjustments keep their provider
classification. Organization Costs is the authoritative total; the
product usage endpoints (completions first —
`GET /v1/organization/usage/completions` with project, user, API-key,
model, batch, and service-tier dimensions — others only when Familiar
actually uses the product) provide attribution and diagnostics behind
an extensible per-product collector, and one product endpoint is never
presumed to cover every charge.

**Identity is bound, never inferred.** One email is not one account;
one API key is not one organization; one organization is not one
project; ChatGPT workspace identity is not Platform organization
identity; Codex login identity is not API billing identity. Worker and
provider configuration binds the Familiar project (PRD-055),
authentication mode, Platform organization, Platform project, and
billing source explicitly; requests may carry the
documented organization/project selection headers per current
documentation. A binding that cannot be resolved unambiguously is
flagged and excluded from budget enforcement and reconciliation rather
than guessed. Azure OpenAI and other resellers are out of the Costs
API's scope: they are the PRD-051 `external-billing` mode — collector
interface reserved, no SDK, explicit unsupported state.

**Estimation dimensions.** Local API estimates use the versioned price
schedules with every price-relevant dimension the provider exposes:
resolved model/snapshot identity (aliases are identity risks — record
the resolved model whenever reported), short- versus long-context
tiers, uncached input, cached input, cache writes where separately
priced, output, service tier (standard/batch/flex/fast), and tool or
modality fees (web search, code sessions, file search, image/audio
units) when reported or priced. Reasoning tokens are preserved as their
own observed category and priced according to the current official
contract, not assumed separately billed. Schedules carry id, source
URL, effective date, and calculation version; historical estimates are
never silently recomputed.

**Security.** All PRD-047/052 rules hold: credential references only;
the Admin key is resolved at collection time inside the narrow
host-side collector and scrubbed from every spawned Codex/model
process environment (the operator's own `OPENAI_API_KEY` inference
arrangement is BYO-Auth and is never captured or logged); repository
content and `familiar.toml` cannot bind credentials or elevate billing
authority (PRD-049 gate); probes and collection are read-only and grant
no execution, merge, or delivery power. Threats designed against:
Admin-key inheritance by Codex, ChatGPT-login/API-billing confusion,
cross-organization and duplicate-project attribution, malicious
repository configuration, secret leakage through diagnostics,
model-alias price drift, replayed terminal events, partial pagination,
and provider reporting delay.

## Scope

- Codex adapter completion: reasoning-output category, sanitized
  accounting evidence envelopes with source-event hashes,
  exactly-once terminal persistence, CLI version capture, and
  the authentication-mode probe surfaced through provider
  verification/listing.
- `kind = "billing"` OpenAI organization sources: probe, org-identity
  discovery, duplicate-scope rejection, costs collection, the
  completions usage collector, and the extensible product-collector
  seam.
- Versioned credit schedules and credit-denominated estimates as a
  typed unit beside USD amounts; subscription and allowance state as
  declarations/unknowns per PRD-051.
- Explicit worker/org/project/billing-source bindings with fail-closed
  ambiguity handling in budget enforcement and PRD-053 reconciliation
  (matching on project/model/time dimensions only where evidence
  supports it).
- CLI per existing grammar: `config provider add <name> --kind billing
  --auth env:OPENAI_ADMIN_KEY` (probe-before-persist), `billing
  status`/`billing collect` covering OpenAI sources, provider listings
  showing authentication/billing mode, organization and project
  identity, authority, completeness, freshness, and coverage; exact
  remedies for missing Admin authority, expired credentials, ambiguous
  bindings, and unsupported ChatGPT spend retrieval.
- Reporting via the PRD-051/053 surfaces: per-execution unit-labeled
  amounts (dollars, credits, tokens), month-to-date per organization,
  attributed versus unattributed, and reconciliation variance — no new
  reporting subsystem.

## Ledger defect relationship

Inherits the family's ownership map unchanged: B1 and B8 remain
PRD-053/051 work (Codex cached tokens already flow into the distinct
cheaper category here); B5, B6, and B13 remain execution/recovery
fixes. This PRD adds no new defect ownership; it extends B8's distinct
categories with reasoning output for Codex.

## Assumptions (documentation retrieved 2026-08-30)

- Verified against official docs on 2026-08-30: the organization Costs
  and Usage endpoints, Admin-key requirement, Unix-seconds
  `start_time`, daily-only cost buckets (usage supports 1m/1h/1d),
  `next_page` cursor pagination, `amount.value`/`amount.currency`,
  `line_item`/`project_id`/`organization_id` fields
  (developers.openai.com cookbook, completions_usage_api); `codex exec
  --json` event set and the four-field `turn.completed` usage object
  including `reasoning_output_tokens`, and `codex exec resume`
  (learn.chatgpt.com non-interactive-mode); the three authentication
  modes, `codex login status`, and the `~/.codex/auth.json` secrecy
  warning (learn.chatgpt.com auth) — whether that command's output is
  machine-readable and distinguishes the three modes is not yet
  verified and gates its use as a classifier; the plan lineup, rolling usage
  windows, purchasable credits, and the credits-per-million-token rate
  card (learn.chatgpt.com pricing); API pricing dimensions including
  cache-write rates, long-context tiers, service tiers with Fast mode,
  and tool/modality fees (developers.openai.com api pricing).
- OpenAI schemas and Codex event shapes change frequently and carry no
  stability guarantee; implementation must re-verify exact field names
  and shapes against then-current documentation rather than freezing
  this PRD's snapshot, and the raw-retention rule exists so schema
  drift stays recoverable.
- The org usage API spells the cached category `input_cached_tokens`
  while the Codex CLI spells it `cached_input_tokens`; normalization
  maps both to the ledger's cache-read category without renaming raw
  evidence.
- No documented machine-readable spend or allowance endpoint exists for
  personal or workspace ChatGPT plans as of the retrieval date; those
  stay declared/estimated/unknown until official interfaces appear.
- OpenAI reports Platform costs in USD today; currency is persisted per
  row regardless.
