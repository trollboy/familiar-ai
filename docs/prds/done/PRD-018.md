# PRD-018: Morning Report

**Status:** Completed
**Date:** 2026-08-04
**Depends on:** PRD-017
**Architectural direction:** Autonomy Fails Closed; Determinism Before Intelligence; Memory Must Be Durable
**Delivery boundary:** Independently mergeable deterministic rendering of recorded driver sessions

## Objective

Add `familiar-ai report`: render one driver session — by default the most recent — as a single screen answering the four morning questions: what got built, what stopped and exactly why, what it cost, and what needs human judgment next.

The report is pure deterministic rendering of state Familiar already records (PRD-017 driver sessions and attempts, execution history, review cycles, backlog status). It computes nothing new, invokes no model, and never mutates anything.

## Motivation

The north star defines success for an unattended night as either an MVP or "a partial MVP plus a precise, auditable account of exactly what stopped, why, and what it cost." PRD-017 records that account durably; this PRD makes it readable in one glance. The human's morning cost is the north-star metric "human touches per accepted PRD" — a report that surfaces the exact retained reasons and the exact recovery commands keeps those touches cheap and few.

## Scope

This PRD includes:

1. A `report` CLI subcommand: no argument renders the latest driver session; an explicit session id renders that session; a missing or unknown session is a clear error, never an empty success.
2. Sections, in order, each bounded to what fits one screen without loss of the canonical data underneath:
   - header: session id, start/end (or "interrupted"), termination reason, warrant snapshot;
   - **completed**: each completed PRD with id, title, duration, and known cost;
   - **stopped**: each retained attempt with the exact retained-reason string, the terminal review stop reasons when review ran, and for scope stops the exact file/rule tuples already persisted by PRD-013;
   - **cost**: session totals split honestly into known cost and attempts-with-unknown-cost counts — unknown is reported as unknown, never as zero;
   - **needs human judgment**: every retained entry with the copy-pasteable PRD-012 recovery command forms, and any `cost_unknown`/`storage_failure` termination called out explicitly.
3. Interrupted sessions render from whatever attempt rows exist, labeled as interrupted.
4. Focused tests pinning the rendered output for fixture sessions covering every section and edge (empty session, all-completed, mixed, interrupted, unknown costs).

## Non-goals

This PRD does not:

- write, mutate, summarize-with-a-model, or send anything anywhere (no email, notifications, files, or network);
- add scheduling or run automatically after `drive` — it is an explicit read command;
- change driver, run, review, backlog, or storage write behavior, or add migrations (it reads PRD-017's schema);
- render anything not derivable from durable records; or
- modify prior PRDs, architecture documents, ADRs, contracts, or philosophy.

## Acceptance Criteria

1. `familiar-ai report` renders the latest session and `familiar-ai report <session-id>` renders a specific one; absence of any session is an explicit error.
2. Every completed PRD, every retained attempt with its exact retained reason, and scope-stop file/rule tuples appear; nothing recorded is silently omitted — where bounding truncates a list, the omitted count is printed.
3. Cost reporting never coerces unknown to zero and always separates known totals from unknown counts.
4. The needs-human-judgment section lists a concrete PRD-012 recovery command for every retained entry.
5. Interrupted sessions render their partial account, labeled.
6. Rendering is byte-deterministic for a given database state and invokes no model.
7. No state is mutated; the command works with review enabled or disabled.
8. Formatting, focused Clippy, focused tests, and the full workspace suite pass, with demonstrably pre-existing failures reported separately with exact evidence.
9. The change is confined to the expected files and is independently mergeable.

## Test Strategy

- Fixture sessions seeded through the PRD-017 repository covering: all-completed, mixed completed/retained (including a scope-broadened attempt with persisted findings), interrupted mid-attempt, unknown-cost attempts, and each termination reason — with the rendered output pinned byte-exact per fixture.
- Latest-session selection and explicit-id selection, including unknown-id error.
- A no-sessions database errors clearly.
- Determinism: rendering twice yields identical bytes.

## Expected Files

The implementation is expected to modify or add only:

- `crates/familiar-ai-daemon/src/report.rs` — rendering, with unit tests
- `crates/familiar-ai-daemon/src/lib.rs` — module export
- `crates/familiar-ai-daemon/src/bin/familiar-ai.rs` — the `report` subcommand
- `crates/familiar-ai-storage/src/` — read-only queries over driver sessions, attempts, and review findings needed by the renderer
- `crates/familiar-ai-storage/tests/` — query coverage
- `crates/familiar-ai-daemon/tests/` — end-to-end report fixtures

No new crate, third-party dependency, or migration is expected. Changes outside this list require explicit pull-request justification.

## Definition of Done

PRD-018 is done when the morning after an unattended `drive` session, one command shows on one screen what was built, what stopped with exact reasons down to scope file/rule tuples, what it cost with unknowns honestly unknown, and the exact recovery commands for everything awaiting human judgment — deterministically, from durable records, with the full verification pipeline passing.
