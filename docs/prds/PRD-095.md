# PRD-095: Declared Git and Forge Identity Per Repository

## Objective

Familiar authors commits and publishes pull requests as whatever identity the
daemon's ambient environment happens to supply. Identity is never declared,
never selected, and never checked. For a single-account box that is invisible;
for a machine with several accounts — which this one is — it is silently wrong
until a write fails, and the failure does not say why.

Make the identity a repository authors and publishes under an explicit,
declared, per-repository property, asserted before the work is done rather
than discovered when a provider call fails.

## Evidence

**1. The publication boundary embeds no account, by design and by comment.**
`DeliveryConfig::provider_argv` is documented as:

> *"Provider adapter executable and arguments; no repository or account
> identity is embedded."*

`provider_argv` ([delivery.rs:736](../../crates/familiar-ai-daemon/src/delivery.rs#L736))
prepends the configured adapter argv to `["pr", "create", ...]` and runs it.
Which account that resolves to is whatever the adapter's own global state says.
On this box `gh`'s active account is one of three, and the wrong one holds only
READ on the target repository.

**2. The failure is not legible.** A `gh pr create` issued as an account
without write access to `trollboy/familiar-ai` returns
`GraphQL: Something went wrong while executing your query` — a 500, not a 403 —
and the REST fallback returns `unexpected end of JSON input`. Neither names
permissions or identity. It reads as a provider outage and invites retries.
(The clearer `must be a collaborator (createPullRequest)` has also been seen;
nothing lets the caller rely on getting the legible one.) A delivery that fails
here fails *mid-journal*, after `pushed`, having already written a branch to the
remote.

**3. Authorship is ambient too.** `ProcessRunner::run`
([delivery.rs:146](../../crates/familiar-ai-daemon/src/delivery.rs#L146))
spawns with `current_dir`, piped stdio, and nothing else — it inherits the
daemon's whole environment and sets no `GIT_AUTHOR_*` or `GIT_COMMITTER_*`. So
`git commit -m "feat: implement PRD-x"`
([delivery.rs:306](../../crates/familiar-ai-daemon/src/delivery.rs#L306))
is attributed to whatever `user.name`/`user.email` resolution finds. Familiar's
own commits are signed with an identity nobody chose.

There is already an in-repo precedent for the fix: `SandboxedToolExecutor`'s
`run-command` does deny-by-default environment construction (`env_clear()` plus
an explicit allowlist) precisely so the daemon's environment is never inherited
wholesale. Delivery does the opposite.

**4. Multi-repo makes one ambient identity structurally wrong.** Repository
policy already resolves per repository, through Git common-directory identity
([config/mod.rs:384](../../crates/familiar-ai-core/src/config/mod.rs#L384)).
A daemon serving two repositories owned by different accounts has no single
correct ambient identity; today it uses one anyway.

## Approach

Declare the identity on `RepositoryConfig`, next to the delivery authority that
already lives there, and resolve it on the same per-repository path. Pass it to
each invocation — environment or argv — rather than mutating anything global.
Assert it before the journal advances past `pushed`, so a wrong identity costs
a diagnostic instead of a half-finished delivery.

## Why global switching is not the fix

The manual workaround is `gh auth switch`, and it must not be automated.
It mutates machine-global state: every other Familiar process, every other
shell, and every concurrent session sees the change. Familiar's whole execution
model is concurrent workers against multiple worktrees, so a global toggle
around a critical section is a race by construction — two deliveries to
differently-owned repositories overlapping would each publish under the other's
account depending on scheduling. Per-invocation selection has no such window.
This is why the no-global-mutation assertion is an acceptance criterion and not
a style note.

## Scope note

Deliberately **not** in scope:

- Credential storage or SSH key management. Identity here is a descriptor —
  a name, an email, an account handle — and `credential_references` plus the
  credential-authentication contract keep owning the secret side. A PRD that
  needed to store a token would be a different PRD.
- Rewriting or re-attributing commits already authored under an ambient
  identity.
- Signing (GPG/SSH commit signatures). Related, and a reasonable follow-on
  once identity is declared, but it introduces key management this PRD is
  explicitly avoiding.
- Any change to which account the operator's interactive shell uses.

## Acceptance evidence

`crates/familiar-ai-daemon/tests/delivery_identity.rs`, driven through the
existing `CommandRunner` seam so no test performs a live forge call: a
two-repository session where each repository's delivery records its own
declared identity, the fail-closed absence case, the mismatch diagnostic
naming declared and observed identity, and an assertion over every recorded
argv that no `git config --global` or `gh auth switch` was ever issued.
