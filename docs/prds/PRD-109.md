# PRD-109: One PRD lifecycle, derived and shown everywhere

## Objective

A PRD's state is currently spelled in two vocabularies that were never
reconciled. The file's front matter says `draft`, `ready`, `in_progress`,
`completed` or `blocked`, written by a human. The backlog ledger says
`pending`, `in_progress`, `completed` or `blocked`, written by Familiar,
per host. Beneath both sit attempt outcomes (`completed`, `retained` with a
reason) and checkpoint phases (`implemented`, `reviewed`, `approved`,
`completed`). The queue audit of 2026-09-22 found the same PRD
`in_progress` on one machine, `pending` on the other, and `ready` in the
file, and FAM-BUG-074 had to teach selection to read the file because the
ledger could not be trusted across hosts.

The owner's ask, for the desktop UI being built on the other machine: one
flow.

```
Draft → Ready → Implementing → Testing → Reviewed → Approved → Completed
                     │             │          │
                     └─────────────┴──────────┴──→ AwaitingFeedback ──→ back to the paused stage, or Blocked
                     │             │          │
                     └─────────────┴──────────┴──→ Failed ──→ Ready (retry) or Blocked
Blocked: from any state before Completed; human-owned
```

## Design

- **Derived, never stored.** The lifecycle is a pure function of records
  that already exist. No schema changes, no new column to keep in sync,
  no Familiar write into a PRD file (PRD-108 names that a non-goal and this
  PRD keeps it). The function lives in `familiar-ai-core` next to the
  backlog types and is the only place the ten names are spelled.
- **Human-owned versus machine-owned.** Draft, Ready and Blocked come from
  the file, because the file is the one record both hosts share. Every
  other state comes from the ledger, the latest attempt, the checkpoint and
  the pending gates on the host answering the question. A state the file
  owns wins over a stale ledger row; a Completed row or an archived
  location wins over everything.
- **AwaitingFeedback is the permission-gate definition.** Under the 1.0
  rule the only legitimate stop is a decision that is the user's to make.
  This state is that set and nothing else, which makes the firing table a
  one-line query: everything in Failed is a defect.
- **Closed and enforced.** A retained reason or stall class that maps to
  neither AwaitingFeedback nor Failed is refused at startup by name, so a
  new reason cannot slip in as a silent Failed.

## Derivation table

| Inputs, first matching row wins | Lifecycle |
|---|---|
| file archived, or ledger `completed` | Completed |
| file `blocked` or ledger `blocked` | Blocked |
| file `draft` | Draft |
| checkpoint `approved` | Approved |
| checkpoint `reviewed`, disposition clean or `ReadyForHumanApproval` with no pending gate | Reviewed |
| pending scope decision, human review required, or risk acceptance owed | AwaitingFeedback |
| latest attempt `retained`, reason not a human gate | Failed |
| attempt running, phase at or past verification | Testing |
| attempt running or ledger `in_progress`, earlier phase | Implementing |
| file `ready` or absent, ledger `pending` | Ready |

Where a ledger row is `in_progress` on another host, PRD-091's lease is
the authority for whether anything is actually running; without a live
lease the row is treated as stale and the file's state wins, which is the
FAM-BUG-074 rule restated.

## Scope

The enum and derivation in core; the typed field on the operator snapshot,
`stewardship backlog`, `next` and the report; the desktop and GTK views
rendering it; the contract document; the structured-PRD contract
amendment; regressions in a dedicated test file.

Out of scope: renaming or migrating any existing status column or enum;
writing any state into PRD files; changing what makes a PRD eligible,
which FAM-BUG-074 and PRD-093 own; and the multi-host lease itself
(PRD-091).

## Assumptions (recorded at specification time, 2026-09-22)

- PRD-108 lands first. It owns the reconciler and the snapshot this field
  rides on, and two of its expected files are this PRD's too.
- Ten states are enough. If a surface needs a finer distinction it renders
  the raw inputs beside the lifecycle rather than adding an eleventh state.
