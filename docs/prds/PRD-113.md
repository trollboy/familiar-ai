# PRD-113: A second desktop is a failure, not a success

## Objective

On 2026-09-27 the supervised desktop started, found a stray
`familiar-ai-desktop` process holding the single instance, handed off to
it and exited 0 (FAM-BUG-115). systemd's `Restart=on-failure` treated that
as success and the tray stayed absent until an operator killed the stray
and restarted the unit by hand. The owner's rule is that no tray icon is a
failure case; the supervisor must be able to see it as one.

## Scope

- A pid file at `<state dir>/desktop.pid`, written by the desktop after
  its single-instance plugin has admitted it, removed on orderly exit.
- A startup check, before `tauri::Builder`, that reads the pid file and
  decides live / stale / absent; a live owner makes this process print
  `another Familiar desktop (pid N) owns the tray` and exit 2.
- The check is a function that takes the file's contents and a
  process-liveness probe, so the three cases are unit-testable without a
  display.

## Out of scope

- Killing or replacing the other instance.
- Changing the supervisor definitions (`Restart=on-failure` is right once
  the exit is non-zero; `StartLimitIntervalSec` already bounds retries).
- macOS launchd behavior beyond what the shared supervisor code already
  does with a non-zero exit.

## Evidence

`docs/running_bugs.md`, FAM-BUG-115; `journalctl --user -u
familiar-ai-desktop.service` for 2026-09-26 20:55 EDT.
