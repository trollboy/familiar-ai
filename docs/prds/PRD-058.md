# PRD-058: Familiar-Owned Raw-Model Agent Runtime

## Objective

Give Familiar its own agent loop so raw inference endpoints — hosted
Anthropic/OpenAI/xAI APIs or local backends — become real workers
under PRD-057 raw runtimes: Familiar composes prompts, offers
canonical tools, validates and authorizes every call, executes under
sandbox policy, records deterministic evidence and honest usage, and
checkpoints for resume — inside the PRD-056 execution lifecycle,
warrants, and accounting.

## Problem

Every current worker is an external harness (Claude Code, Codex) that
owns its own conversation loop, tools, and permissions. PRD-057
defines raw runtimes (`anthropic-api`, `openai-api`, `xai-api`,
`ollama`, `llama-cpp`, `mlx`, `vllm`) but nothing can drive them: a
raw model has no coding-agent runtime, and the only in-repo inference
client (the local OpenAI-compatible backend serving summaries) has no
loop, no tools, no accounting. Without a Familiar-owned loop, vendor
diversity for review and the local-model economics the north star
wants are unreachable.

## Agent loop

One deterministic state machine, orchestrated by the application
services (PRD-056) with durable transitions before external effects:

    compose → submit → streaming turn → {text | tool calls |
    structured output | stop} → validate → authorize → execute
    (journaled) → insert results → iterate | terminal

- **Compose** builds the system/task prompt from compiled context with
  a byte-stable prefix (PRD-029) and versioned prompt-template
  identity; volatile task state follows the stable prefix so provider
  caches pay.
- **Submit** sends messages, tool definitions, model selection, cache
  and reasoning controls through the inference adapter; streaming
  events surface text deltas, tool-call deltas, usage, and stop
  metadata to attached observers (PRD-056 event stream).
- **Validate** checks each requested tool call against the canonical
  schema (unknown tool, malformed arguments, oversized payloads are
  refusals, recorded, never executed).
- **Authorize** evaluates the capability's authority scope,
  side-effect class, command and path policy, and the execution's
  warrant; refusals are recorded facts with policy-determined
  continuation (inform the model and continue, or stop closed).
- **Execute** runs the tool under the journal (below) and sandbox;
  results are size-limited, secret-scanned, and inserted as tool
  results marked as untrusted data.
- **Iterate** until a terminal state; ceilings on iterations, tokens,
  context, wall-clock, and budget are enforced preemptively.

Terminal stop reasons are a closed set: completed (with or without
structured output), iteration-ceiling, token-or-context-ceiling,
budget-stop (PRD-024 semantics), timeout, cancelled, provider-failure
(taxonomized), fatal-tool-refusal, invalid-structured-output. Honest
by construction: a stage that failed is its failure, never
token-exhaustion by bookkeeping (ledger B5's rule). Partial results,
partial usage, and a resumable checkpoint (PRD-039 phase discipline)
survive every non-completed stop.

## Canonical tool capabilities

Familiar defines tool capabilities once, in the domain — MCP is one
projection, never the model. Each capability carries: stable identity
and schema version; input/output schema; project/execution authority
binding; side-effect class (`read-only`, `idempotent-write`,
`destructive`); timeout; idempotency expectation; audit requirement;
risk classification; and warrant implications (what its execution may
consume or reserve). The initial set is small: read-file,
search/list, run-command (policy-gated), apply-edit (scope-bounded),
report-progress, submit-evidence, request-escalation.

Projections translate capabilities per runtime: MCP tools for
harnesses that speak MCP (PRD-056 capability-scoped sessions);
Anthropic native tool definitions; OpenAI native tool definitions;
xAI native tool definitions; local-runtime tool templates
(schema-constrained output for backends without native tool calling);
and direct application-service calls where no wire format is needed.
One capability, one authority model, N encodings — a projection can
narrow a capability, never widen it.

## Inference adapter contract

The minimum provider-neutral contract a PRD-057 raw runtime adapter
implements: submit(messages, model selection, tool definitions,
structured-output request, cache controls, reasoning controls) →
streamed events (text delta, tool-call delta, usage delta, stop
reason) plus final usage categories and provider request identity;
cancellation; and a shared error taxonomy — retryable (rate-limited
with retry-after metadata, overloaded, transient transport),
non-retryable (auth, invalid request, refused content), and ambiguous
(timeout with unknown completion) — with retry hints honored inside
budget. **Inference attempts are billable events, not free replays**:
a provider may have accepted, executed, and billed a request whose
response never arrived. Every submission is its own globally unique
local attempt with its own PRD-064 budget reservation; provider
request identity is recorded when exposed, and provider idempotency
keys are used only where officially supported, with their documented
semantics. A timeout with unknown completion records ambiguous/
unknown usage and cost for that attempt — pending, reconcilable
later through provider reporting, never zero. A retry is another
attempt and another reservation unless the provider guarantees
idempotent replay; observed usage from multiple attempts is never
deduplicated merely because the logical turn is the same, and retry
policy accounts for possibly duplicated provider spend. The invariant
is: replaying the same persisted provider event is idempotent, while
genuinely separate billable attempts remain separate observations. A
"resumable stop" means Familiar resumes its own workflow state — not
that the provider can resume the interrupted request. Tool execution
is never retried through the provider path. Provider-specific
request/response extensions stay in adapter-owned types; the loop
sees only the contract.

## Authority and sandboxing

A raw model receives no ambient authority. Tool execution runs
project-scoped: paths confined to the execution's worktree; writes
bounded by the PRD-013 Expected Files scope authorization; commands
filtered by approved allow/deny policy (repository-declared policy
only via the PRD-049 approval gate); the existing isolation layer
(Landlock/sandbox-exec, process groups, timeouts) encloses commands;
environment scrubbed to the minimum (inference credentials only in
the adapter's own process boundary; billing/admin credentials never —
PRD-052/054); network deny-by-default for tool commands; tool results
size-capped and secret-scanned (the value-shaped detection from B9).
Prompt-injection resistance is structural: repository content and
tool results are untrusted data — nothing a model reads or a tool
returns can grant capability, alter policy, or approve anything.
`request-escalation` creates a pending human gate on the PRD-035
surface; the model cannot approve its own escalation (PRD-056's
matrix applies to raw runtimes identically).

## Determinism, evidence, and recovery

Sampling is not deterministic; orchestration is. Execution evidence
persists: prompt-template and context-manifest versions, the complete
PRD-057 worker spec and artifact identity, the offered tool set and
schema versions, every requested call with its disposition
(validated/refused/authorized/executed), result content hashes, usage
observation ids, the stop reason, and the resume point. Execution
evidence (which may reference transcripts and tool output under the
event-model's retention and redaction rules) is a separate store from
the accounting ledger: PRD-051 rows carry only sanitized envelopes —
never prompts, responses, source code, or tool output.

Crash safety is a write-ahead tool journal: intent (call id,
capability, argument hash, side-effect class) precedes execution;
result records follow. Resume replays nothing blindly: read-only
calls may re-run; an idempotent-write with intent-but-no-result may
re-run by declaration; a destructive call with intent-but-no-result
fails closed to a human gate. The loop checkpoint (conversation
position, journal high-water mark, usage so far) makes resume
deterministic without re-billing completed turns.

## Harness versus raw runtime

The distinction stays explicit and routed on: **external harness**
(Claude Code, Codex) owns its loop, tools, permissions, session
resume, compaction, model selection, and subscription billing —
Familiar supplies context, verification, review, and accounting
envelopes, as today. **Familiar raw runtime** owns everything in this
PRD against a hosted adapter. **Local raw runtime** is the same loop
against a local backend, with local-resource capabilities and
economics. These are different PRD-057 empirical identities; routing
and PRD-032 scores never conflate them.

## Phasing

1. Loop core, canonical capabilities (read-only set +
   report/evidence), fake-model test adapter, evidence and PRD-051
   usage recording. Smallest viable worker: a raw-runtime
   **independent reviewer / narrow-task worker** with read-only tools
   and structured output — the self-contained stage where vendor
   diversity pays first.
2. Journaled write capabilities (apply-edit under scope
   authorization, policy-gated run-command) for bounded
   implementation stages.
3. Checkpoint/resume integration and context compaction where
   declared.
4. Additional adapters as configuration + adapter work under the
   PRD-057 contract (no loop changes).

## Test harness

A deterministic fake inference adapter scripts turns, tool-call
sequences, malformed calls, streaming, usage categories, stop
reasons, rate-limit and error taxonomy cases, and cancellation;
temporary repositories exercise scope refusals, sandbox and env
scrubbing, journal crash/resume matrices (intent-without-result per
side-effect class), and injection attempts (instructions inside file
content and tool results must produce no authority change). No test
performs a live or billable call; local-backend integration uses the
existing wiremock seam.

## Assumptions (recorded 2026-08-30)

- The existing `familiar-ai-llm` OpenAI-compatible backend is the
  starting local seam but the loop lives in the agent/services layer;
  the summaries path is untouched.
- Structured-output support varies by backend; where a runtime lacks
  native tool calling, schema-constrained templates are acceptable
  and their reliability is scored empirically (PRD-032), not assumed.
- The review role is the first production consumer; implementation
  stages adopt the raw runtime only after journaled writes (phase 2)
  and only through ordinary routing policy.
