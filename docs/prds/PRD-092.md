# PRD-092: One Build Command Everywhere

## Objective

Every documented build invocation carries a workaround. Linux needs
`--no-default-features` for the daemon because the tray's libxdo link gap
breaks the default build; macOS had its own build-speed pathology. A
default feature set that does not build on a supported platform is not a
default, and a first command that fails is the worst possible first
impression for a tool whose entire pitch is that it runs unattended.

There is a second, quieter cost: the gate builds with the workaround
flag, so what the gate proves green and what a user installs are not the
same artifact.

## Design

- **The default builds.** The tray moves behind an opt-in feature and the
  default set is whatever compiles cleanly on every supported platform,
  proven by a gate job rather than by anyone's laptop.
- **The workaround flag disappears from documentation.** A check enforces
  it, so the flag cannot creep back into a README line and become
  permanent again.
- **Optional features fail early and by name.** Enabling the tray without
  its system dependency reports the missing dependency at configure time
  instead of failing at link.
- **Build time is a measured number.** Clean and incremental wall-clock
  per platform against a declared ceiling, so a build-speed pathology is
  a failing check rather than a story about a bad afternoon.
- **Gate and install agree.** One resolved feature set, checked.

## Scope

Feature default restructuring across the workspace and the daemon and
tray crates; the tray's early dependency diagnostic; the documented-flag
check; per-platform build-time measurement with a declared ceiling; gate
and install feature-set parity; documentation updates.

Out of scope: packaging, installers, or distribution channels; the tray's
own functionality; Windows support beyond whatever the current feature
matrix already claims; and the verification gate's test selection
(PRD-088).

## Assumptions (recorded at specification time, 2026-09-04)

- The tray is genuinely optional for the daemon and CLI; if any
  non-optional path depends on it, that dependency is the real defect and
  is reported rather than worked around by keeping the tray in the
  default set.
- Supported platforms are current Linux and macOS; a platform without a
  gate job is not claimed as supported.
