# PRD-024: Enforceable Budgets for Agent Execution

**Status:** Ready for implementation
**Date:** 2026-08-05
**Depends on:** PRD-014, PRD-017
**Architectural direction:** Trust Is Earned Through Verification; Determinism Before Intelligence; Fail Closed On Unknown State
**Delivery boundary:** Independently mergeable budget layer across the agent adapters, the runner, and the driver loop

## Objective

Give every agent execution a ceiling that is actually enforced, so an unattended session cannot consume an unbounded amount of a subscription, a metered account, or a night.

Familiar today records what an execution consumed and never compares it to a limit. `review.max_total_tokens` bounds the review cycle only; `[driver]` bounds PRD count and wall-clock. The implementing agent — which is where essentially all consumption happens — runs with no budget of any kind.

## Motivation

The first live self-build measured one PRD at **8,399,462 tokens in 12.9 minutes**, of which 8,158,208 were cache reads and only 50,342 were output. Nothing was in a position to stop it. That is the failure the north star names directly: kick off Familiar, wake up out of tokens.

The measurement also shows *where* the consumption comes from. With only ~190k tokens of distinct context and ~50k of output, 8.4M total is explicable only by a long agentic loop re-sending a mostly-cached conversation across many turns. The cost is driven by turn count, not prompt size — so shrinking the context budget cannot fix it, and a bound on the loop itself is required.

The Claude Code CLI already provides exactly that bound. `--max-budget-usd` works with `--print` (which the adapter already passes), enforces under subscription authentication, and terminates with a distinct result subtype. Verified empirically: a run capped at $0.0001 stopped after one turn reporting `"subtype":"error_max_budget_usd"` and `"errors":["Reached maximum budget ($0.0001)"]`. The guardrail is a vendor capability Familiar is not yet asking for.

## Semantics

- **A budget is a set of ceilings** over cost, tokens, and duration. Any subset may be declared; each declared ceiling must be finite and positive.
- **Pre-emptive enforcement is preferred and declared.** An adapter states which denominations it can bound natively, in the manner `isolation_capability()` already declares isolation. The Claude Code adapter bounds cost natively; adapters that bound nothing say so.
- **A per-execution ceiling in a denomination the adapter cannot enforce natively is refused before launch**, naming the adapter and the denomination. Familiar does not accept a ceiling it can only discover was breached.
- **Session ceilings are enforced between executions** by the driver loop against recorded attempt totals, and work for every adapter. An unbounded-per-execution adapter is therefore still usable under a session ceiling, with the overshoot bounded by one execution.
- **A budget stop is a distinct, closed outcome** — not a failure to retry. The attempt is retained with its own termination reason, its partial work left in place, and the PRD left for human judgment.
- **Known zero is not unknown.** An adapter with no marginal cost reports cost as known zero with its own provenance. Unknown usage continues to fail closed; known zero does not.
- **A warrant bounded only in a denomination the adapter reports as always-zero is not a warrant.** Declaring only a cost ceiling against a zero-cost adapter is refused, naming the denominations that would bound it.
- **Vendor-reported cost is authoritative where a vendor reports one**, because that is the figure the pre-emptive ceiling is enforced against; accounting in any other unit would let the report and the stop disagree. The configured rate table remains the source for adapters that report no cost. Which source produced a row is recorded in the existing `pricing_provenance` field.

## Scope

This PRD includes:

1. A budget type over cost, tokens, and duration, carried on the execution request and validated at construction.
2. An adapter-declared budget capability, and fail-closed refusal when a per-execution ceiling exceeds what the adapter can enforce.
3. Claude Code adapter support for `--max-budget-usd`, with the pinned-argv contract updated.
4. A closed termination reason for `error_max_budget_usd`, rendered by the morning report.
5. Correct usage extraction on budget-stopped executions: token counts aggregated from `modelUsage` when the top-level `usage` block is absent or zeroed, and recorded as unknown rather than zero when neither is credible.
6. Cost provenance: vendor-reported preferred, configured rates as fallback, known-zero for costless adapters, each recorded distinctly.
7. Session-level cumulative enforcement in the driver loop against recorded attempt totals.
8. Configuration for per-execution and per-session ceilings, required rather than defaulted.
9. Focused tests over temporary repositories and fake agents only.

## Non-goals

This PRD does not:

- add budget support to the Codex adapter — it declares no native capability and is bounded at the session level until someone adds it;
- introduce an API-backed adapter, local-model execution, or any new vendor;
- implement task-class routing, model selection, or model probation;
- estimate cost for adapters that report none beyond the existing configured rate table;
- interrupt an execution mid-flight from outside the adapter, or parse partial usage from streaming events to do so;
- change review-cycle budgets, PRD-013 scope authorization, or the isolation contract; or
- modify prior PRDs, architecture documents, ADRs, contracts, or philosophy.

## Behavior

```
[agents.implementation]
max_execution_cost_microusd = 8000000     # $8.00, enforced by the vendor before the turn

[driver]
max_session_cost_microusd = 25000000      # $25.00 across the session
max_session_tokens = 40000000
```

A configured per-execution ceiling is passed to the adapter and enforced by it. On a budget stop the attempt is recorded with its own termination reason, its usage and cost recorded from whichever source is credible, and the PRD retained. The driver then compares cumulative session totals against the session ceilings and ends the session by exact reason when one is reached.

Refusals, all before launch and all naming the exact cause: a ceiling of zero or a non-finite value; a per-execution denomination the adapter cannot enforce; a warrant whose only denomination the adapter always reports as zero; a session with no finite ceiling at all.

## Acceptance Criteria

1. A per-execution cost ceiling reaches the Claude Code adapter as `--max-budget-usd`, and the argv contract test pins its position and formatting.
2. A `error_max_budget_usd` result maps to a distinct closed termination reason, is retained rather than retried, and is rendered by the morning report.
3. A per-execution ceiling in a denomination the adapter does not natively enforce is refused before launch, naming adapter and denomination, with no process spawned.
4. A budget-stopped execution records token counts aggregated from `modelUsage` when the top-level `usage` block is zeroed, and records unknown — never zero — when neither source is credible.
5. Cost provenance is recorded distinctly for vendor-reported, configured-rate, and known-zero sources, and vendor-reported wins where both are available.
6. A warrant declaring only a cost ceiling against an adapter that always reports zero cost is refused, naming the denominations that would bound it.
7. Session cumulative ceilings end the session by exact reason, computed from recorded attempt totals, for adapters with and without native enforcement.
8. A session with no finite ceiling in any denomination is refused, preserving the PRD-017 warrant rule.
9. Existing behavior is otherwise unchanged: review budgets, scope authorization, isolation, admission, claim, completion, and recovery.
10. All tests use temporary repositories, databases, and fake agents; formatting, focused Clippy, focused tests, and the workspace suite pass, or demonstrably pre-existing failures are reported with exact evidence.
11. The change is confined to the expected files and is independently mergeable.

## Test Strategy

- Argv: the cost ceiling appears exactly once, correctly formatted, and the forbidden-flag pin still holds.
- Termination: a fake agent emitting `error_max_budget_usd` yields the closed reason, retains the attempt, and renders in the report with output pinned byte-exact.
- Refusals: unenforceable denomination, zero and non-finite ceilings, cost-only warrant against a zero-cost adapter, and a warrant with no finite ceiling — each by exact diagnostic, with no process spawned and no row mutated.
- Usage: a result with a zeroed `usage` block and a populated `modelUsage` records the aggregated counts; one with neither records unknown; a costless adapter records known zero and does not trip the unknown-usage stop.
- Provenance: vendor-reported preferred over configured rates when both exist; configured rates used when no vendor cost is reported.
- Session: cumulative totals across several attempts stop at the ceiling by exact reason, for a natively-bounded adapter and an unbounded one.
- Regression: existing agent, run, drive, review, and report suites pass unchanged; the byte-exact report pin is updated only for the new reason.

## Definition of Done

PRD-024 is done when a budget is something Familiar enforces rather than merely records: the vendor stops the loop before the money is spent, an adapter that cannot be bound says so instead of pretending, a costless model is bounded by tokens and time rather than waved through, every stop is a named outcome in the morning report, and no configuration exists in which an unattended session can run without a finite ceiling in a denomination that actually binds it.
