# PRD-110: One Adapter Model — Providers, Workers, Assignments

## Objective

The settings form asks the same question in four places. `agents.implementation`
and `agents.reviewer` ask for an adapter, an executable and a model.
`review.implementation_agent` and `review.reviewer_agent` ask for an adapter
id, an agent id, a model and a provider. `inference.text` asks for a URL and a
model again. Each table has its own closed vocabulary: `agents.*.adapter` is
the four-value `AgentAdapterKind` enum, `review.*.adapter_id` is a free
string, and API runtimes such as `openai-api` are legal in a worker's
`runtime` and nowhere else. On 2026-09-24 the owner chose `openai-api` in the
first table, the form wrote it without validation, and the daemon refused to
start (FAM-BUG-094). The dropdown was then narrowed to the enum, and
`openai-api` disappeared from the only place the form offered it.

The owner's statement of the shape that is wanted: *"a factory style
polymorphic adapter model. You can just configure them at the global scope and
then assign them as needed in projects."* And the operational question that
motivates it: *"What if I have a couple OpenAI accounts, or a few Ollama boxes,
an Unsloth box and two vLLMs on my network?"*

Most of the model already exists. `[providers.<name>]` is a named endpoint
with its own credential. `[workers.<name>]` binds a provider to a model and
carries measured cost. The reviewer config already points at a worker through
`agent_id`. What is missing is that the roles do not consistently point at
workers, the worker repeats what the provider knows, and the settings surface
shows the legacy tables instead of the model. This PRD makes providers,
workers and assignments the one way to say which model does which job, and
rewrites the old tables into it on load.

## Design

### Providers: endpoint, credential, dialect

```toml
[providers.openai-work]
dialect = "openai-compatible"           # openai-compatible | anthropic | cli
host = "https://api.openai.com/v1"
auth = { env = "OPENAI_API_KEY_WORK" }

[providers.openai-personal]
dialect = "openai-compatible"
host = "https://api.openai.com/v1"
auth = { credential-store = { service = "openai", account = "personal" } }

[providers.ollama-desk]
dialect = "openai-compatible"
host = "http://127.0.0.1:11434/v1"

[providers.ollama-rack]
dialect = "openai-compatible"
host = "http://10.0.0.12:11434/v1"

[providers.vllm-a]
dialect = "openai-compatible"
host = "http://10.0.0.20:8000/v1"

[providers.anthropic]
dialect = "anthropic"
host = "https://api.anthropic.com"
auth = { env = "ANTHROPIC_API_KEY" }

[providers.claude-cli]
dialect = "cli"
executable = "claude"                   # the vendor CLI holds its own login
```

`dialect` is new and closed. It replaces the per-worker `runtime` string as the
thing that decides which client speaks to the endpoint: `openai-compatible`
covers OpenAI, vLLM, Ollama, Unsloth and xAI; `anthropic` covers the Messages
API; `cli` covers `claude` and `codex`, which carry their own login and
permission model. Discovery (`GET /v1/models`, or the Anthropic models
endpoint) and health belong to the provider, since they need its host and its
credential and nothing from any worker.

### Workers: provider plus model

```toml
[workers.opus]
provider = "anthropic"
model = "claude-opus-5"

[workers.sonnet-cli]
provider = "claude-cli"
model = "sonnet"
permission_mode = "bypassPermissions"   # cli dialect only

[workers.qwen-desk]
provider = "ollama-desk"
model = "qwen2.5:7b"

[workers.qwen-rack]
provider = "ollama-rack"
model = "qwen2.5:7b"

[pools.qwen]
workers = ["qwen-desk", "qwen-rack"]    # interchangeable; rotate, skip unhealthy
```

A worker no longer declares `runtime`; it inherits the provider's dialect. A
worker that still declares one is accepted while it agrees with the provider
and refused when it does not, so an old file keeps working and a contradictory
one is named. Everything a worker carries today that is genuinely its own —
measured cost, context size, capabilities, concurrency ceiling, `executable`
override and `permission_mode` for the `cli` dialect — stays on the worker.

A pool is a named set of workers that are interchangeable for the caller.
Dispatch rotates across the pool's healthy members and skips one whose
provider health is down. A pool is assignable anywhere a worker is. A pool is
not a routing policy: choosing between unequal workers by cost or by job class
is PRD-107's ladder, which selects among workers and pools defined here.

### Assignments: global defaults, per-project overrides

```toml
[assignments]
implementation = "sonnet-cli"
reviewer = "opus"
planner = "qwen"                        # a pool
inference_text = "qwen"
inference_embeddings = "qwen-desk"

[repositories."/home/trollboy/Projects/familiar-ai".assignments]
reviewer = "opus"                       # override any subset
```

Roles are the closed set the daemon already has jobs for: `implementation`,
`reviewer`, `planner`, `inference_text`, `inference_embeddings`. The project
page shows every role with its effective worker and whether it is inherited
or overridden, the same way it shows every other setting.

### What this replaces

| Today | After |
|---|---|
| `agents.<role>.{adapter,executable,model,permission_mode}` | a `cli` provider, a worker on it, an assignment |
| `review.<role>_agent.{adapter_id,agent_id,provider,model}` | `assignments.<role>` naming that worker |
| `inference.text.{builtin_url,builtin_model}` | a provider, a worker, `assignments.inference_text` |
| `workers.<name>.runtime` | the provider's `dialect` |

The loader rewrites the old tables into the new ones in memory on load and
logs one line per rewrite naming the old key and the worker it became. A file
that already uses providers, workers and assignments is read as is. The
rewrite is exercised by a regression that loads a copy of today's config and
asserts the resolved worker per role is unchanged. The old keys are then
documented as deprecated in the contract; removing them is a later PRD.

### The settings surface

Three panes replace the four duplicated sections and the endpoint half of
`inference.text`:

- **Providers**: name, dialect, host, credential state, Test, Discover models,
  health. Adding one is a form, not a file edit.
- **Workers**: provider dropdown, model dropdown over that provider's
  discovered list (a saved model the provider no longer lists stays
  selectable and is labelled), measured cost and context size read-only,
  pool membership.
- **Assignments**: one row per role, a dropdown of workers and pools; on a
  project page each row shows global or override.

Every save runs the daemon's own loader (FAM-BUG-094). Nothing here adds a
second validator.

## Scope

In scope: the config contract above, the in-memory rewrite of the legacy
tables, dialect-driven client selection, pools with health-aware rotation,
provider-owned discovery and health, the three-pane settings surface on the
Tauri desktop and the GTK tray, the contract document and the provider guide.

Out of scope: routing between unequal workers by cost or job class
(PRD-107), removing the legacy keys from the schema, credential storage
changes, and any change to how the vendor CLIs authenticate.

## Assumptions (recorded at specification time, 2026-09-24)

- The set of roles is the five named above; a new job class adds a role here.
- Ollama, vLLM, Unsloth and xAI are close enough to OpenAI's `/v1` surface for
  one `openai-compatible` dialect; a runtime that needs its own client adds a
  dialect value rather than a per-worker runtime string.
- The reviewer independence rule (distinct model from the implementer) is
  enforced on the resolved workers, not on the strings in the file.
