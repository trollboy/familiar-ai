# PRD-072: Raw-Runtime Token Discipline

## Objective

Attack output and tool-echo volume at the source, inside the runtime
Familiar owns. Whole-file rewrites make the model re-emit every unchanged
line at the most expensive token price, and unbounded tool output makes
it re-read logs it never needed; both are harness decisions, not model
decisions, and PRD-058's runtime is where Familiar finally controls the
harness. Targeted-edit forms are the largest single output reduction in
public agent practice; bounded tool windows are the corresponding input
reduction. Both land as runtime contract, measured by the ledger, off by
default until measurement says otherwise.

## Design

- **Targeted edits as the primary write form.** The runtime's edit tool
  takes search/replace blocks or unified-diff hunks, applies them
  atomically against current content, and fails loudly on anchor
  divergence — a stale hunk is a named error, never a corrupted apply.
  Whole-file replacement survives for legitimate cases (new files, full
  rewrites) and is labeled per write so edit-form economics are a ledger
  query. Worker instructions carry the preference; enforcement is the
  tool's shape, not prompt hope.
- **Nothing routes around the safety substrate.** Targeted edits resolve
  to writes inside PRD-013 scope authorization, appear in PRD-058's
  write-ahead tool journal with enough content to replay to the identical
  file state after a crash, and change nothing about verification or
  review evidence.
- **Bounded tool results.** Command output beyond a configured window
  reaches the model as head plus tail with an elided count and a paging
  handle; oversized file reads require explicit ranges; every elided
  region stays retrievable on demand. The journal retains full output for
  verification and review — the model's window is a token decision, the
  durable record is not.
- **Measured discipline.** Observations carry edit-form and truncation
  configuration; PRD-051 partitions volume by discipline state. Defaults
  reproduce current behavior exactly; enablement is audited
  configuration; default-on promotion cites the measured comparison.

## Scope

Edit-tool forms and atomic application in the runtime's tool layer,
journal integration and crash-replay regression, bounded result windows
with paging handles, configuration surface, ledger attribution, contract
additions to `docs/contracts/agent-loop.md`, and regressions in a
dedicated test file (anchor-divergence rejection, replay identity,
window bounding with lossless retention, byte-identical defaults).

Out of scope: the CLI-adapter workers (Claude Code and Codex own their
edit formats; this PRD governs only the Familiar-owned runtime),
compression of tool content (PRD-069 composes downstream), and context
construction (PRD-070).

## Assumptions (recorded at specification time, 2026-08-30)

- PRD-058's canonical tool capabilities and write-ahead journal exist as
  specified; this PRD extends tool shapes within that contract rather
  than defining a parallel tool surface.
- Anchor-based application over the worktree's current content is
  sufficient — the runtime serializes writes per file within an attempt,
  so concurrent-writer anchor races do not arise inside one worker.
