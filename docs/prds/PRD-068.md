# PRD-068: Driver Hygiene — Context Classification, Cache Noise, Metadata Modes

## Objective

Remove the three operational irritants wave 2 proved out (after-action
defects 9, 16, 18): a context-compilation failure killed a whole session as
`unclassified_result` instead of retaining one PRD and moving on; a stale
Codex model-cache schema flooded every long run with thousands of identical
false error lines; and the documented pre-wave `metadata-check` cannot be
consumed by automation because legacy migration debt and genuine metadata
invalidity share one nonzero exit.

## Design

- **Precise context-failure classification, bounded blast radius.** The
  `19c90d4` correction already distinguishes planned outputs from missing
  inputs; this PRD finishes the taxonomy (missing authoritative input,
  unreadable reference) so no context failure reaches
  `unclassified_result`. A PRD retained for a context failure frees its
  slot through PRD-066's continuous admission and the session keeps
  working the rest of its allowlist — one bad reference never ends an
  overnight run again.
- **Cache errors are events, not weather.** An incompatible model-cache
  schema triggers one invalidation, one refresh, and one diagnostic
  naming the incompatibility; the run proceeds on the refreshed cache.
- **Two metadata-check exits.** Strict mode is the migration forcing
  function (any legacy document fails); advisory mode is the operational
  pre-wave gate (structured-v1 diagnostics fail, legacy debt reports
  without failing). Output names the active mode so logs stay
  unambiguous. The execution plan's guidance switches to advisory for
  unattended sessions; strict remains available for the eventual legacy
  migration push.

## Scope

Context-failure taxonomy in the context crate and its drive/run mapping,
codex cache invalidate-once lifecycle, metadata-check mode flags and exit
semantics, and regressions in a dedicated `driver_hygiene` test file
(kept out of the shared daemon test directory scope so this PRD stays
schedulable beside its siblings).

Out of scope: merge queue and admission mechanics themselves (PRD-066 —
this PRD only supplies the precise retention class that admission
consumes), verification truth and waivers (PRD-067), legacy PRD
migration itself (defect 18's debt is reported, not paid, here).

## Assumptions (recorded at specification time, 2026-08-30)

- PRD-066's continuous admission is the mechanism that continues a
  session past a retained PRD; this PRD depends on it rather than
  reimplementing continuation.
- The 41 legacy documents under `policy=incremental` remain valid inputs
  for execution admission; advisory mode changes reporting, never
  admission semantics.
