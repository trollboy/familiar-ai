# PRD-073: Warm Local Model Residency

## Objective

Stop paying the load-and-warm tax on every local call. Local models make
tokens free but shift the scarce resources to context window, load time,
and KV/prefix cache — and all three only pay off inside a process that
outlives individual executions. A serving runtime that dies with each run
forfeits its prefix cache and reloads gigabytes per call; the PRD-056
daemon is the natural owner of residency, keeping configured local
servers warm between executions so the PRD-063 runtime's calls hit loaded
weights and warm caches. This revives the wave-one local-model-manager
idea on the execution-era control plane, with the era's rules: budgeted,
audited, measured, off by default.

## Design

- **Daemon-owned residency.** A residency module in the control plane
  starts, holds, and stops local serving processes for explicitly
  configured PRD-062 model artifacts. Executions route to residents;
  consecutive calls share one load. Residency spans drive sessions for
  the daemon's lifetime.
- **Prefix cache as a first-class asset.** Resident servers run with
  prefix/KV caching enabled where the serving runtime supports it, and
  Familiar records what the runtime reports — cold load, warm miss, warm
  hit — composing with PRD-070's stable context blocks: deterministic
  prefixes upstream, retained caches downstream.
- **Budgets and health.** Configuration bounds residency (which
  artifacts, how many, memory ceiling) with LRU eviction and durable
  eviction records. Health checks detect dead or hung residents within a
  configured interval, restart within a bounded count with durable
  records, and fail loudly after exhaustion — degradation to per-call
  loading is always a recorded event, never a silent tax.
- **Measured.** Observations carry residency state and server identity;
  latency and utilization partition by warm/cold in the ledger and in
  PRD-063's operator-allocation estimates. Promotion of any residency
  default cites measurements.

## Scope

The residency module (lifecycle, budgets, LRU eviction, health and
bounded restart), llm-crate routing to resident endpoints, configuration
surface with decision-row audit, durable residency/eviction/restart
records, ledger attribution, and regressions in a dedicated test file
(single-load across calls with a fake server, ceiling eviction, health
restart exhaustion, off-by-default routing identity).

Out of scope: model preparation and provenance (PRD-062), the local
runtime contract and hardware reservations themselves (PRD-063 —
residency consumes its reservation vocabulary), hosted-provider
anything, and speculative prewarming policies beyond configured
residency (a future PRD may schedule warmth; this one holds it).

## Assumptions (recorded at specification time, 2026-08-30)

- PRD-063's serving runtimes (unsloth, ollama, or successors) expose a
  long-lived server mode addressable over the neutral local transport;
  residency manages those processes rather than in-process inference.
- Cache-hit reporting varies by serving runtime; where a runtime reports
  nothing, observations record residency state only and cache evidence
  is explicitly unknown — never inferred.
