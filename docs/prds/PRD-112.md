# PRD-112: A refused reservation says so

## Objective

On 2026-09-27 the first ladder attempts on the local rung were refused
before any request (FAM-BUG-116, FAM-BUG-119). The daemon logged the
refusal with `tracing::warn!` inside the drive process, mapped it to
`BudgetStopped`, and the report read "agent execution reached its enforced
budget ceiling" for an attempt that had no budget problem at all. Finding
the real cause took a query against `resource_pools`.

The refusal is correct; its legibility is not. A refusal that costs a whole
rung must be readable in the two places an operator looks: the attempt's
retained detail and the session report.

## Scope

- `raw_agent.rs`: the `BudgetStopped` raised when
  `reserve_execution_budget` fails carries the host's refusal text (it is
  already in the `Err(detail)` that is currently only logged).
- `agent_runtime.rs`: `acquire_local_reservation` and
  `reserve_execution_budget` return a detail naming the pool, resource type
  and unavailable amount, or the budget detail, in one line.
- `run.rs`: `retained_detail` for that error path is the refusal text, not
  the enum's generic message.

## Out of scope

- A new retained reason. `budget_stopped` stays; only its detail changes.
- Recovering held reservations (FAM-BUG-119's open half).
- Any change to when a reservation is refused.
