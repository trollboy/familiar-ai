# PRD-088: CLI Surface Design Pass

## Objective

The CLI carries roughly twenty-six top-level commands with deep nesting —
`control`, `compress`, `config`, `billing`, `accounting`, `batch-review`,
`stewardship`, `plan`, `onboard`, `worker`, `backlog`, `deliver` and the
rest. That surface is a symptom: capability grew faster than the
interface was designed, one PRD at a time, each adding its own top-level
verb because there was nowhere else to put it. Meanwhile the one command
a new operator actually needs — the scope approval — is the one that is
not surfaced anywhere they will look.

The fix is not fewer features. It is a front door: a small set of daily
verbs, everything else under stable administrative namespaces, and a
no-argument invocation that answers the only question a new user has,
which is what to do next.

## Design

- **A front door.** Bare `familiar-ai` reports repository state and the
  single next runnable command. When a decision is pending, that command
  is the approval — the failure in PRD-081 stops being possible by
  construction.
- **Daily verbs at the top, administration namespaced.** The commands a
  person runs in a normal session stay top-level. Configuration,
  accounting, planning, and delivery administration move under declared
  namespaces.
- **A ceiling with a diff.** The top-level count is declared and checked,
  so the next capability has to argue for its place instead of appearing.
- **Nothing is taken away.** Relocations ship with working aliases that
  name their replacement, and a before-and-after leaf-command comparison
  proves no capability was lost in the rearrangement.
- **Help is a path, not a list.** Each level names the next step in the
  workflow, so the whole loop is discoverable without documentation.

## Scope

The no-argument front door; top-level command reorganisation into daily
verbs and declared namespaces; the declared top-level ceiling check; the
alias table with deprecation notices; workflow-aware help text; README
alignment; regressions in a dedicated test file.

Out of scope: removing or changing the behaviour of any command, the
scope-approval surfaces themselves (PRD-081), promoting the operator
tools (PRD-082 — this PRD places them, that one ships them), and the
daemon, MCP, and dashboard surfaces (PRD-035).

## Assumptions (recorded at specification time, 2026-09-04)

- A one-release alias window is sufficient given the current user
  population; the aliases are recorded so the window can be extended by
  decision rather than by omission.
- The daily verb set is small and can be settled from the observed
  session workflow (next, run, drive, resume, report, approve, deliver);
  disagreement about membership is a review question, not a blocker.
