# PRD-071: Batch-Tier Independent Review

## Objective

Halve the price of Familiar's highest-volume single-shot role. Provider
batch interfaces price asynchronous work at half the interactive rate,
and the independent reviewer is the perfect shape for them: one
self-contained call, no human waiting on the other end for low-risk
classes, quality unchanged. What batch pricing demands is an owner of
time — something that can submit now and act on the result hours later —
which is exactly what the PRD-056 control plane provides and a
CLI-process-owned execution cannot. This PRD makes the reviewer's tier a
scheduling decision: risk class and configuration choose between
interactive latency and batch economics, and the PRD-051 ledger records
what the choice actually cost.

## Design

- **Tier selection.** PRD-045's declared-risk tier policy gains a batch
  tier: risk classes explicitly configured for it route reviewer calls
  through the provider batch interface (the PRD-059 Anthropic adapter's
  batch surface first). Everything else is untouched; high-risk classes
  keep interactive review unless audited configuration says otherwise.
- **Asynchronous lifecycle, daemon-owned.** Submission parks the PRD in
  a durable review-pending state and frees the slot — PRD-066's
  continuous admission fills it with other allowlisted work. The daemon
  polls, and on completion the result enters the identical disposition
  machinery interactive review uses; there is exactly one code path from
  review result to outcome. Crash between submit and complete resumes
  from durable state: no lost batches, no double application.
- **Bounded latency.** A configured maximum wait caps how long economics
  may delay a disposition; expiry falls back to interactive tier with a
  durable, reasoned record. Batch is a discount, never a stall.
- **Measured, not assumed.** Observations record tier and
  provider-reported cost with provenance; the discount is a ledger query
  comparing batch and interactive reviews of the same risk class, not a
  number copied from a pricing page.

## Scope

Batch tier in the review tier policy, the daemon batch lifecycle module
with durable submission state (migration plus repository support), the
PRD-059 adapter's batch submission path consumption, ledger tier
attribution, configuration surface with decision-row audit, and
regressions in a dedicated test file (park-and-free, crash-resume
idempotence, expiry fallback, single disposition path, tier-partitioned
accounting).

Out of scope: batching implementation-stage work (long-horizon tool use
does not fit batch semantics), any provider other than the first landed
batch-capable adapter (others extend the same tier when their adapters
land), and changes to review content or finding semantics.

## Assumptions (recorded at specification time, 2026-08-30)

- PRD-056's control plane provides the persistent process and durable
  pending-state machinery this PRD schedules on; PRD-059 provides the
  raw Anthropic adapter whose batch surface is consumed. Neither is
  reimplemented here.
- Reviewer calls remain single-shot with structured output under the
  batch tier; if a future reviewer becomes multi-turn, it is ineligible
  for batch by construction.
