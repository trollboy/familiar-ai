# PRD-049: Shareable Project Configuration (familiar.toml)

## Objective

Let a repository carry its own Familiar topology — environment roles,
provider requirements, verification policy, risk vocabulary, PRD layout —
in a checked-in `familiar.toml`, so the next Familiar user who clones the
project is pre-configured by declaration while credentials and authority
remain strictly machine-local and operator-approved.

## Design

**Declare and bind.** The repo file declares named requirements; the
machine config binds them to real endpoints:

    # familiar.toml (checked in, shareable)
    [environments.staging]
    requires = "deploy-target"
    name = "devbox"
    [environments.production]
    requires = "deploy-target"
    name = "azure-prod"

    familiar-ai status
    familiar.toml: approved (snapshot 3f9c…, human:trollboy 2026-08-30)
    bindings: devbox → gpu-box (ok), azure-prod → UNBOUND
      run: familiar-ai config provider bind azure-prod <provider>

**Untrusted until approved.** A checked-in configuration is repository
content and therefore untrusted input (PRD-036: malicious repository
content cannot inject commands or configuration). `familiar.toml`
proposes; the operator approves; the approval records an attributed
snapshot hash. Drift from the approved hash — any edit, any pull —
suspends every authority the file granted and presents the diff for
re-approval. Recipes, verification commands, and role mappings are only
ever executed from an approved snapshot.

**Nothing personal, nothing dangerous.** The shareable set is topology
and policy. Validation fails closed on credential-shaped values,
absolute paths, and host literals bound to roles (hosts belong to the
machine-local binding, not the shared declaration).

**Layering.** familiar.toml (approved) → user config
`[repositories."<path>"]` (bindings and overrides) → global defaults,
with per-value source provenance surfaced by `config show --effective`.

## Scope

- familiar.toml discovery, schema, closed-set validation, and the
  approval-snapshot lifecycle (approve, drift detection, re-approval,
  revocation), recorded as decision rows.
- Role/requirement declarations and the `config provider bind` verb
  connecting them to PRD-047 providers.
- Effective-config resolution across the three layers with provenance.
- Documentation contract in docs/contracts/familiar-toml.md defining the
  shareable set and the threat model.
