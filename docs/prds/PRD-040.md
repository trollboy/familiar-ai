# PRD-040: First-Class Risk and Per-PRD Worker Routing

**Status:** Superseded by PRD-042, PRD-043, PRD-044, PRD-045
**Date:** 2026-08-29
**Approved:** 2026-08-29 by owner; decomposed the same day into four bounded
PRDs at the owner's request. This document is retained as the design record.
**Depends on:** PRD-030, PRD-031, PRD-039

## Objective

Make declared risk a first-class routing input and route every PRD individually
through the worker registry, retiring the legacy `model_routes` path that the
registry silently disables.

## Scope

- Define the closed `risk_classes` vocabulary in the Structured PRD Contract;
  an unknown class fails closed at metadata-check.
- Extend `RouteRequest` with declared risk classes and expected scope size;
  selection remains pure and deterministic.
- Select implementation and remediation workers per PRD inside the drive loop;
  reviewer independence is enforced against the per-PRD selected implementer.
- Registry routing rules may match on risk classes and scope size with the same
  first-match determinism as review tier rules.
- Retire `[[driver.model_routes]]` and `routed_model()`; configuring the
  retired key is a validation error naming the registry replacement.
- Compose observed risk (`ScopeFileClass`) with declared risk in review tier
  selection: observation may only raise assurance, never lower it.
- Persist routing inputs with each selection record so empirical scoring
  (PRD-032) can correlate outcomes with risk class.

## Acceptance Criteria

1. A PRD declaring a high-risk class routes to the operator-designated strong
   worker even when its expected footprint is a single file.
2. Two PRDs in one session can select different implementation workers; each
   selection record names its inputs and rejected candidates.
3. An unknown risk class fails metadata-check closed; no fallback routing.
4. Configuring the retired `model_routes` key is a validation error that names
   the replacement.
5. Declared high risk forces the Full review tier regardless of footprint rules.
6. Every selection is reproducible from persisted inputs and registry state.
