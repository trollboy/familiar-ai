# PRD-026: Per-Repository Execution Configuration

**Status:** Ready for implementation
**Date:** 2026-08-08
**Depends on:** PRD-013, PRD-014, PRD-025
**Architectural direction:** Trust Is Earned Through Verification; Determinism Before Intelligence; Fail Closed On Unknown State
**Delivery boundary:** Independently mergeable configuration layer scoping review verification, review scope, and context ceilings to a repository, with authority remaining entirely operator-owned

## Objective

Let one Familiar installation drive more than one repository honestly, by scoping the parts of configuration that are inherently repository-shaped — verification commands, allowed paths, scope classifications, context ceilings — to a `[repositories."<worktree>"]` entry, resolved deterministically at `run` and `drive` time.

PRD-025 made a foreign backlog *readable*. This PRD makes it *verifiable*: reading spectra's PRDs is useless while review still runs `cargo test` against a Go repository.

## Motivation

The configuration is global, and every value in it that matters at review time describes exactly one repository — this one. `allowed_paths = ["crates/"]` authorizes nothing in a repository whose code lives in `internal/`; the `[[review.verification]]` checks run this workspace's Docker cargo pipeline; the scope classifications name this repository's migration directory. Pointed at any other repository, review either fails closed for reasons unrelated to the work under review or — worse — passes vacuously because no configured path matches anything.

The authority boundary is the design constraint, and it is already settled doctrine: verification commands are operator-trusted input executed on the operator's machine. They must therefore live in the operator's configuration, never in the target repository — a repository that could declare its own verification argv could execute arbitrary commands by being cloned. Repository scoping changes *where in the operator's file* these values sit, and nothing about who owns them.

## Semantics

- **A repository entry may carry execution sections.** The `[repositories."<worktree>"]` table from PRD-025 accepts, in addition to its backlog profile: a `review` tree (verification checks, allowed paths, scope declaration mode, file classes, classifications, prohibited changes, review budgets and package ceilings) and an `execution_context` table (compiled-prompt ceiling). These are the repository-shaped sections, exhaustively; nothing else is scopeable.
- **Resolution is wholesale per section, never merged.** If a repository entry declares a `review` tree, that tree is the review configuration for that repository, complete; the global `[review]` contributes nothing to it. Likewise `execution_context`. Field-level merging is refused by design — a reviewer reading one section of one file must be able to state the effective policy without computing an overlay.
- **Absence falls back whole.** A repository entry with no `review` tree uses the global `[review]` exactly as today. A repository with no entry at all is untouched by this PRD in every observable.
- **Validation is identical at both scopes and fails closed at load.** A repository-scoped `review` tree passes through the same validation as the global one — including PRD-013 scope grammar, PRD-014 agent-consistency rules against the (still global) `[agents]` tables, and PRD-024 budget shape rules — before any repository is touched. An invalid scoped section is a configuration error, not a fallback to global.
- **Agents, driver warrant, and daemon concerns stay global.** Which adapters implement and review, the unattended session warrant, database, logging, and daemon settings describe the installation, not a repository. Scoping them is refused at load — an unknown key inside a repository entry names itself exactly.
- **The effective source is recorded, not inferred.** Every attempt records whether its review and execution-context configuration came from repository scope or global scope, the morning report renders it, and a review verdict is thereby always attributable to the policy that produced it.

## Scope

This PRD includes:

1. Repository-scoped `review` and `execution_context` sections on the PRD-025 repository entry, with the closed-set rule and exact-diagnostic refusal of anything else.
2. Wholesale-section resolution at `run` and `drive` admission, deterministic by canonicalized worktree path.
3. Full-parity validation of scoped sections at configuration load, including PRD-013, PRD-014, and PRD-024 rules.
4. Configuration-source recording on attempts, rendered by the morning report.
5. A commented worked example in `config/default.toml` scoping a second repository's verification to its own pipeline.
6. Focused tests over temporary repositories and fake agents.

## Non-goals

This PRD does not:

- read execution configuration of any kind from a target repository — the authority boundary is the point;
- scope agents, driver warrant, database, logging, daemon, or any non-repository-shaped section;
- merge, overlay, or interpolate between scopes — resolution is wholesale or absent;
- add new review capabilities, verification check types, or scope classes;
- change PRD-016/PRD-021 isolation, PRD-011 admission evidence, or the review cycle's structure; or
- modify prior PRDs, architecture documents, ADRs, contracts, or philosophy.

## Behavior

```toml
[repositories."/home/trollboy/Projects/spectra"]
profile = "numbered-slug"
active_dir = "docs/prd/todo"
archived_dir = "docs/prd/done"

[repositories."/home/trollboy/Projects/spectra".execution_context]
hard_ceiling_tokens = 60000

[repositories."/home/trollboy/Projects/spectra".review]
enabled = true
allowed_paths = ["internal/", "api/", "tests/", "docs/prd/"]
# … full review tree, validated exactly like the global one …

[[repositories."/home/trollboy/Projects/spectra".review.verification]]
check_id = "lint"
argv = ["/usr/bin/docker", "compose", "run", "--rm", "tools", "make", "lint"]
working_directory = "."
timeout_ms = 1200000
required = true
environment = { PATH = "/usr/local/bin:/usr/bin:/bin" }
```

`familiar-ai drive` in the spectra worktree reviews against spectra's Docker pipeline and spectra's paths; the same command in this workspace still reviews against the global cargo pipeline. A scoped section that fails validation, a scoped key outside the closed set, or an agent-consistency violation against the global `[agents]` each refuse at load, before any claim, naming the repository entry and the offending value.

## Acceptance Criteria

1. A repository whose entry scopes `review` runs exactly its scoped verification argv and scope policy, with the global `[review]` contributing no field — proven by a fixture whose global and scoped trees differ in every section.
2. A repository entry without `review` uses the global tree unchanged, and a repository with no entry is byte-identical to today across the run, drive, review, and report suites.
3. A scoped `review` tree failing any validation the global tree would fail — scope grammar, agent consistency, budget shape — refuses at configuration load with a diagnostic naming the repository entry, and no process is spawned and no row mutated.
4. A repository entry containing any key outside the closed set (backlog fields, `review`, `execution_context`) refuses at load naming that key.
5. Wholesale resolution is deterministic under canonicalized paths, including a symlinked worktree resolving to its configured entry.
6. Every attempt records its configuration source per section, and the morning report renders repository-scoped and global-scoped attempts distinguishably, pinned byte-exact.
7. Scoped `execution_context` ceilings bind context compilation for that repository only.
8. All tests use temporary repositories, databases, and fake agents; formatting, focused Clippy, focused tests, and the workspace suite pass, or demonstrably pre-existing failures are reported with exact evidence.
9. The change is confined to the expected files and is independently mergeable.

## Test Strategy

- Resolution: differing global/scoped fixtures asserting wholesale replacement per section, whole-section fallback on absence, and no-entry byte-identity.
- Validation: each refusal class exercised at load with its exact diagnostic — invalid scoped scope grammar, scoped/agents inconsistency, malformed scoped budget, unknown scoped key.
- Determinism: canonicalized-path resolution including the symlink case; two loads of one file produce identical effective configurations.
- Recording: attempts under each source rendered in the report, pinned byte-exact; source recorded correctly when drive crosses from a scoped run to a global one is out of scope (single-repository sessions), asserted refused if attempted.
- Regression: existing run, drive, review, report, and configuration suites pass unchanged.

## Definition of Done

PRD-026 is done when "which repository am I in" is a question the configuration answers instead of one the operator must remember to re-answer by editing a global file: each described repository is verified by its own pipeline against its own paths under its own ceilings, every verdict names the policy scope that produced it, authority never leaves the operator's file, and an undescribed repository — or an installation that never adds a repository entry — cannot tell this PRD happened.
