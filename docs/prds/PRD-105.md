# PRD-105: Finish PRD-100's unremediated findings

## What this PRD carries, and why it changed (2026-09-22)

This PRD was first written for two findings PRD-100's remediation stage
dropped between review passes. Both were fixed on PR #19's branch before
landing, in `7c6d92e`, each pinned by a regression that fails when the
fix is reverted:

- `raw-agent-model-override-not-attributed` —
  `a_request_model_override_is_the_model_attributed_everywhere`.
- `reservation-leaked-on-pre-loop-failure` —
  `a_failure_after_the_reservation_and_before_the_loop_releases_it` and
  `an_abandoned_execution_releases_its_reservation_row`.

The independent review of PR #19 on 2026-09-22 then found two more it
would block on, fixed in `703f68c`: every raw implementation was recorded
twice in the PRD-051 ledger, and `budget_capability` claimed cost, token
and duration enforcement the loop did not perform. Both are in the bug
ledger as FAM-BUG-070 and FAM-BUG-071.

What remains are the review's non-blocking findings, each verified
against the code before being written here. `completion-is-immutable.md`
says unmet work becomes a successor; this is that successor. It stays
`blocked` until PRD-100 integrates, because every file it names changes
in PR #19.

## The four findings carried

**`preflight-green-for-misconfigured-raw-workers`** (medium).
`preflight.rs:95` calls `build_agent_or_deferred(.., true)`, which
returns a `DeferredRawAgent` whose `preflight()` is the trait default and
always passes. A typo'd `runtime`, a missing `auth_profile`, and
`agent_runtime.enabled = false` all pass `familiar-ai preflight` and fail
at dispatch inside `build_selected_agents`. The registered factory set,
the enabled flag, and credential resolution are all available at
preflight without execution context.

**`legacy-runtime-config-host-ignored`** (medium).
`default_local_endpoint` in `run.rs` returns `http://127.0.0.1:11434`
for `ollama`, and nothing in `run.rs` or `preflight.rs` reads
`OllamaRuntimeConfig.host`. A worker configured against another host
silently talks to loopback.

**`symlink-redirect-under-allowed-dir`** (low, security).
`write_path_allowed` in `raw_runtime.rs` is a lexical prefix match on the
declared path; the executor canonicalizes and checks worktree
containment only. A symlink inside the worktree under an allowed `dir/`
entry redirects an authorized write to an in-worktree file outside every
allowed entry. The PRD-013 post-hoc diff check catches the result, so
this is parity with the CLI path rather than a bypass, and the fix is to
check the resolved path too.

**`no-tracked-cycle-with-a-raw-worker`** (test debt). No file under
`crates/familiar-ai-daemon/tests/` drives `execute_with_config_tracked`
with a raw worker. FAM-BUG-070 would have been caught by one.

## Noted and not carried

Each is real, each is small, and none changes behaviour a user sees.
Recorded so the next reader does not rediscover them:

- Settlement on a completed run uses `SettleReservedAmount`, so the
  PRD-064 ledger records consumption equal to the ceiling, not observed
  spend. PRD-086 supplies the pricing that a `Known` settlement needs.
- `OwningSqliteToolJournal::len` returns `usize::MAX` when the journal is
  unreadable and is persisted `as u64`; rusqlite refuses it, so `finish`
  fails after settlement in that one shape.
- `RawCredential` zeroizes on drop, but the `String` copies handed to the
  adapters do not; the doc comment overclaims.
- `SqliteRawAgentHost.worktree_root` is dead state since the executor
  took the request's working directory.

## Withdrawn

`denied-read-path-search-list-uncovered` (review 1), re-raised as
`denied-read-path-misses-search-list-argument` (review 2), is **not a
defect**. Both rest on the claim that `search-list` "does not carry its
target under the key `path`". Its declaration in `raw_runtime.rs` says
otherwise:

```rust
args_schema: ArgSchema { required: &["query"], optional: &["path"] },
```

`RequestScopedAuthorizer::authorize` reads `call.arguments.get("path")`,
which is exactly the declared key. The genuine escape — an absent `path`
walking from the worktree root through the denied subtree — was closed
inside this candidate with a fail-closed `None` arm and the regression
`denied_read_path_refuses_a_pathless_search_list`.

## Resolved

- **Why not fold these into PR #19 as well.** The four blocking findings
  were; these are not blocking, and widening a landing with medium and
  low findings is how a scope_broadened retention gets earned.
- **Why not reopen PRD-100 once it is complete.** Completion is immutable.
  A completed PRD edited after the fact destroys the only durable record
  of what was delivered against what was promised.
