# PRD-031: Worker Capability Registry and Deterministic Routing

**Status:** Ready for implementation
**Date:** 2026-08-26
**Depends on:** PRD-005, PRD-014, PRD-024

## Objective

Replace the two hard-wired agent slots with an adapter-neutral registry from
which deterministic policy selects an eligible worker for each stage, while an
explicit user pin always wins.

## Scope

- Register implementation, planning, review, remediation, and narrow-task
  capabilities with provider/model identity, executable, isolation, context,
  budget, and availability properties.
- Support Codex, Claude, and Ollama through existing adapters; define the
  stable contract future Fable/OpenCode adapters implement.
- Select by configured capability and cost policy, never by another model.
- Enforce reviewer independence and fail with `NoIndependentReviewer` when no
  candidate qualifies.
- Persist candidate set, rule, selected identity, and rejected reasons.

## Acceptance Criteria

1. User-pinned workers are used exactly or refused before work begins.
2. Automatic selection is deterministic for identical registry state.
3. Unavailable, over-budget, incapable, or non-independent candidates cannot run.
4. Adding a conforming adapter requires no orchestration change.
5. Preflight validates every selected stage without spending model tokens.
