# PRD-081: Resolved-Path Worktree Containment

## Objective

`SandboxedToolExecutor::resolve_within_worktree` is the only thing standing
between a model-supplied path and the host filesystem, and it currently
decides containment lexically:

```rust
if relative.is_empty()
    || Path::new(relative).is_absolute()
    || relative.split('/').any(|part| part == "..")
{
    return Err(...);
}
Ok(self.worktree_root.join(relative))
```

A lexical check cannot see a symbolic link. The runtime offers `RunCommand`,
so a worker can create one and then reach through it with a path that is
relative, `..`-free, and entirely outside the worktree.

Both directions are open, and both are demonstrated by the tests already in
the tree:

- **Read** — `read-file` with `path: "escape/secret.txt"` returns the contents
  of a file in another directory. Anything the daemon's uid can read is
  readable: SSH keys, tokens, other repositories.
- **Write** — `apply-edit` with `path: "victim.txt"` answers
  `Ok("wrote 12 bytes to victim.txt")` while overwriting a file outside the
  worktree. Anything the daemon's uid can write is writable, which includes
  shell startup files and anything else that turns a file write into code
  execution on the next login.

The write side is the severe one. Familiar's entire safety argument — scope
policy, review gates, merge queue — assumes a worker's blast radius is its
worktree. That assumption does not currently hold.

This is latent rather than live: `agent_runtime.enabled` and
`agent_runtime.token_discipline.enabled` both default to `false`, and no
shipped configuration turns them on. It is a hole in code that is present but
not yet reachable in the default configuration, which is exactly when it is
cheapest to close.

## Scope note

The code being hardened landed on `main` in `ea9a85a` (PRD-072). No dependency
on PRD-072 is declared because the work is already integrated in the tree;
declaring one would register a dependency the backlog cannot see as satisfied.

## Approach

Containment must be decided on the path the filesystem will actually use.
The shape that satisfies the tests:

1. Keep the existing lexical rejections as a cheap first pass — they are
   already covered by a regression test and cost nothing.
2. Resolve the joined path against the worktree root, following links, and
   verify the result is still inside the canonicalized root.
3. Do this for a path that does not exist yet (an apply-edit creating a new
   file): canonicalize the deepest existing ancestor and confirm *it* is
   contained, rather than failing because the leaf is absent.
4. Route every filesystem-touching capability through the one chokepoint so
   containment cannot be bypassed by adding a capability later.

Symlink resolution is inherently racy against a worker that can also run
commands; the goal here is to close the deterministic hole, and any residual
TOCTOU window should be named in the contract rather than left implied.

## Acceptance evidence

`crates/familiar-ai-daemon/tests/runtime_path_containment.rs` is the oracle
and is already written. It currently fails on the containment tests and
passes on the lexical regression guard. The change is complete when every
test in that file passes with no assertion relaxed, removed, or `#[ignore]`d.
