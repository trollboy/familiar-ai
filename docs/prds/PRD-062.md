# PRD-062: Local Model Artifact Registry and Provenance

## Objective

Give PRD-057's `ModelArtifactId` its substance: an immutable,
content-derived identity and provenance record for locally held model
artifacts — including models prepared, optimized, quantized, or
fine-tuned with Unsloth — so behaviorally different weights can never
hide behind one friendly name, and every local worker's empirical
history is anchored to exactly what ran.

## Design

**Unsloth, modeled accurately.** Unsloth is neither a provider nor a
model family. It is a preparation toolchain (LoRA/QLoRA/full
fine-tuning, RL variants, quantization, GGUF/FP8-class export) and,
per current documentation, also a serving runtime with an
OpenAI-compatible API — verified 2026-08-30 against unsloth.ai/docs,
with exact capabilities an implementation-time verification item. In
this registry Unsloth appears as **provenance**: the preparation tool,
version, and operation recorded on artifacts it produced. Its serving
role is a PRD-063 `RuntimeId`, and `provider = local` throughout.
Familiar registers externally prepared artifacts first; Familiar-
managed preparation is explicitly out of scope.

**Identity.** `ModelArtifactId` is the digest of a **canonical
manifest**, not of a directory walk. The manifest carries its own
schema version and the digest algorithm and version; it lists every
identity-bearing file — weight shards (safetensors, GGUF, and other
supported layouts enumerated by the contract), tokenizer files, chat
and tool-call templates, quantization metadata — as normalized
relative paths in bytewise-sorted order with per-file size and
digest, computed by streaming/incremental hashing so multi-gigabyte
shards register without buffering. Identity-bearing files are an
explicit include set; incidental files (logs, caches, lockfiles,
runtime scratch) are explicitly excluded and mutable external caches
never participate. Symlinks are followed only within the artifact
root — escapes, absolute paths, and traversal sequences fail closed;
hard links are ordinary content; a listed-but-missing file fails
registration. Filesystem timestamps, permissions, absolute location,
and traversal order contribute nothing, so a copied artifact keeps
its id, while any content or identity-bearing configuration change
produces a new one. Digests supplied by a runtime or provider are
provenance to record, never verified content identity — and a
runtime alias alone can never claim it. For composite identities the
manifest names the base artifact plus dynamically applied adapters
in application order. Merged fine-tunes are their own
immutable artifacts; a dynamic adapter stack is a composite identity
distinct from its merged equivalent. Any identity-bearing change is a
new id (PRD-057's partition rule applies automatically). Friendly
names are aliases for humans; they carry no identity.

**Provenance.** Each registration records the fields the acceptance
criteria enumerate — lineage (base model, upstream repo/revision),
transformation (quantization format and parameters, fine-tune and
adapter identities, preparation and export tools with versions,
Unsloth operation where applicable), interface (tokenizer, chat and
tool-call templates, context configuration, material inference
parameters), stewardship (license and usage restrictions, creation
and import timestamps, operator provenance). Unknown stays unknown;
an undigested artifact is a **degraded unverified** identity that
routing policy may refuse — never a silently trusted name.

**Registration surface.** `config artifact` verbs under the PRD-047
grammar: probe-before-persist (digest computation, file readability,
template presence — no model execution), comment-preserving TOML,
actor/UTC provenance, decision rows with before/after hashes.
Registration is idempotent by content. Malicious-artifact posture:
weights and templates are untrusted data — registering an artifact
grants no execution, and chat/tool templates are treated as injection
surfaces by PRD-058/063, never as trusted instructions.

**Migration.** Models currently reachable only as runtime aliases
(e.g. an Ollama tag) become degraded unverified-alias artifacts
until an operator registers and digests them; their history attaches
to the degraded identity honestly rather than to a guessed digest.
Machines that never register an artifact behave exactly as today.

## Scope

- Registry schema, repository methods, and identity derivation;
  composite adapter identities; degraded states.
- `config artifact` CLI verbs and validation under PRD-047
  conventions; license metadata display.
- Contract text in docs/contracts/providers.md for artifact identity
  and provenance.
- No training, no fine-tuning, no export, no marketplace, no model
  downloads — registration of what the operator already has.

## Assumptions (recorded 2026-08-30)

- Digesting multi-file artifacts (weights shards plus config) is
  feasible at registration time; very large artifacts may digest
  incrementally, and the digest algorithm is recorded with the id.
- Unsloth's current platform breadth (macOS/Linux/Windows,
  NVIDIA/AMD/Intel/CPU) comes from its own documentation and is
  re-verified at implementation; nothing here assumes CUDA-specific
  behavior on Apple Silicon.
