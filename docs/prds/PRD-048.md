# PRD-048: Internal Delivery Targets

## Objective

Make Familiar its own CI/CD at garage scale: deploy-target providers
(a VPS, a resurrected desktop dev box, a droplet, the GPU machine) wired
into `deliver`, with recipes, smoke evidence, internal gate resolution,
and the same fail-closed, evidence-recorded discipline as review.

## Design

CI already exists inside Familiar — deterministic verification with
retained, content-hashed evidence is a stronger CI than most external
services provide. This PRD supplies the missing D. A **deploy-target**
provider (`kind = "deploy-target"`) is an ssh-reachable box plus a
recipe and a role:

    familiar-ai config provider add gpu-box --kind deploy-target --host 192.168.1.112
    Added gpu-box (deploy-target) — ssh ok, linux x86_64, docker present.
    gpu-box: ssh unreachable — nothing added.
    # probe = ssh + uname + tooling discovery; auth = the operator's
    # ssh agent and ~/.ssh/config, never stored (BYO-Auth).

Recipes stay deliberately small: sync or pull, restart a unit, run one
smoke command, record the result. No fleet abstractions. Environment
roles (`staging`, `production`) are named per repository and map to
targets, so one project deploys staging to the local dev box while
another uses a droplet — same machinery, different bindings.

`external_gates` in the structured PRD contract gains its first
resolver: an **internal** gate references Familiar's own evidence
(`deploy:staging-smoke-passing`, `verification:<check_id>`), binding a
PRD's deliverability to recorded results without any external CI.
Provider-backed gate resolvers are explicitly out of scope here and
arrive with later provider kinds.

## Scope

- `deploy-target` provider kind: ssh probe, capability discovery
  (docker/systemd presence), role assignment, per-repository role→target
  mapping in configuration.
- `deliver --to <role>`: resolve role, verify target auth and
  reachability first, execute the recipe, run the smoke command, record
  every external effect and the smoke evidence with target and revision
  identity in `delivery_external_effects`.
- Internal `external_gates` resolution against recorded verification and
  smoke evidence; unresolved or failing gates block delivery closed.
- Delivery assurance tiers from the roadmap bind to roles: default stops
  at reviewed PR; PoC warrants may reach non-production targets;
  production requires manual authority.
- Preflight for unattended sessions verifies every provider the session's
  PRDs can reach before any claim (expiring auth surfaces before work
  starts, not mid-run).
