# PRD-029: Stable Prompt Prefixes and Cache Economics

**Status:** Ready for implementation
**Date:** 2026-08-09
**Depends on:** PRD-006, PRD-007, PRD-014

## Objective

Make invariant repository context a byte-stable prompt prefix and measure the
cache benefit honestly, without serving stale content or changing authority.

## Scope

- Separate stable repository/configuration context from volatile PRD and
  attempt data.
- Prove stable bytes remain identical across volatile-only changes and change
  whenever authoritative stable inputs change.
- Pass through provider cache controls only where an adapter supports them.
- Report cached share, known cost savings, and unmeasured attempts.

## Acceptance Criteria

1. Volatile-only changes preserve the exact stable prefix.
2. Repository, reference, or policy changes invalidate it.
3. Budgeting still applies to the complete prompt.
4. Provider cache data is never fabricated or converted from unknown to zero.
5. Usage and morning reports expose cache effectiveness and pricing provenance.
