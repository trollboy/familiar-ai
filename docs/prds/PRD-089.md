# PRD-089: No Holes in Required Gates

## Objective

A required gate with a skipped test is a gate with a known hole. Right
now `tests-green-crates` is required and runs with
`--skip daemon_starts_and_stops_on_sigterm`, because FAM-BUG-050's fourth
layer is open — the daemon does not reliably exit within 10s of SIGTERM
in Docker. That hole lives in a shell command string, explained in a bug
ledger entry that nothing checks. It was preceded by the mirror-image
mistake: a gate promoted to required on 2026-09-01 while it contained a
test that fails in Docker, which then blocked every landing.

Both failures are the same missing mechanism. An exclusion from a
required gate is a decision with an owner, a justification, and an
expiry, and nothing in the system currently makes it look like one.

**The underlying defect is not this PRD's work.** FAM-BUG-050 layer 4 is
bug work and is fixed under the ledger now, on the standing policy that
bugs are never deferred into future scope. This PRD builds the mechanism
that would have made the hole visible and self-closing, and takes that
exclusion as its migration case.

## Design

- **Declared, attributed, expiring.** Every exclusion names its test, its
  ledger entry, its declaring human, and a date it dies. An exclusion
  that is not declared fails the gate that contains it.
- **Visible where gates are read.** Report and `stewardship gates` list
  active holes with their remaining life. The gate's honesty does not
  depend on anyone reading a command line.
- **Self-closing.** Consecutive passes in the gate environment retire the
  exclusion automatically with a record. Holes should not outlive their
  cause because nobody remembered.
- **Promotion sees the holes.** Making a gate required while it holds an
  exclusion demands explicit acknowledgement of each one.

## Scope

The exclusion declaration surface and its validation against required
gate commands; expiry and audited extension; automatic retirement on
consecutive passes; exclusion reporting in report and stewardship;
promotion acknowledgement; migration of the existing SIGTERM exclusion;
regressions in a dedicated test file.

Out of scope: fixing FAM-BUG-050 layer 4 itself, which is ledger bug work
and not deferred to this PRD; gate tiering and load-faithful verification
(PRD-088); the preflight execution contract (PRD-078).

## Assumptions (recorded at specification time, 2026-09-04)

- Required gate commands are discoverable from configuration well enough
  to be scanned for exclusions; a gate whose command cannot be scanned is
  itself reported as unscannable rather than assumed clean.
- Automatic retirement is safe because it requires passes in the gate
  environment, which is the environment the exclusion was created for.
