# PRD-067: Durable Verification Truth and Review Terminal Integrity

## Objective

Make what Familiar reports about verification identical to what durably
happened. Wave 2 produced three trust-boundary failures (after-action
defects 7, 8, 17): a worker narrated passing tests over six real fixture
failures, PRDs reached clean terminal dispositions while acceptance-
criterion findings stood open, and environment-denied checks were
indistinguishable from implementation failures. Each converts machine
autonomy into silent wrongness — the most expensive defect class an
unattended system can have.

## Design

- **Dispositions derive from durable records.** The review phase computes
  its terminal disposition exclusively from persisted check exit records
  (verification evidence, test exit codes, review cycle findings). Agent
  narration is display text; when it contradicts the durable records the
  phase fails with a diagnostic naming the contradicted check rather than
  landing the contradiction.
- **Open findings block clean completion.** A disposition of clean or
  ready-for-human-approval with an open blocking or acceptance-criterion
  finding is a contradiction, not an outcome. The only path through is an
  explicit waiver: durable, attributed (actor and reason), and surfaced in
  the report next to the disposition it excuses. Extends the wave-2
  integrated correction for defect 5 (exact-check-id evidence joined
  through repository identity) with its cross-repository rejection pinned.
- **Environment identity is part of the check.** Each verification check
  records the environment it executed under; a check denied by that
  environment (sandbox permissions, unwritable path) is classified and
  reported as environment-denied, never as a failing implementation.
  Preflight proves required writable paths before costly stages, so the
  wave-1/wave-2 pattern — daemon tests "failing" on log-file permissions
  and being narrated away — becomes a preflight stop with a named path.

## Scope

Review disposition computation, waiver records and reporting, check
environment identity and classification, preflight writable-path probes,
and regressions for each acceptance criterion in a dedicated
`verification_truth` test file (kept out of the shared daemon test
directory scope so this PRD stays schedulable beside its siblings).

Out of scope: orchestration and integration (PRD-066), context failure
classification and cache noise (PRD-068), review retry continuation
policy beyond what PRD-041 landed.

## Assumptions (recorded at specification time, 2026-08-30)

- Durable check exit records exist for every verification stage (PRD-039
  evidence plus the wave-2 defect-5 correction); this PRD consumes them as
  the single source of truth rather than creating a parallel record.
- The waiver record follows the decision-row audit pattern (PRD-046/047):
  one transaction, actor attribution, surfaced in reports.
