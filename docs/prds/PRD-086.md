# PRD-086: Cost Measurement — Make CostUnmeasured the Exception

## Objective

Goal 1 is cost-aware multi-model routing. In practice
`estimated_cost_microusd` is `Option<u64>` and is usually `None`, which
surfaces as the `CostUnmeasured` blocker
([workers.rs:155](../../../crates/familiar-ai-daemon/src/cli/workers.rs))
— cost cannot rank this worker — so nearly everything routes to Claude
Code. The half of the mission that says nobody needs an archdemon to sort
a CSV is architecture with no measurement behind it. Cost is not
optional data about a worker; it is the input the whole routing thesis
rests on.

## Design

- **Every worker has a cost basis.** Published per-token rates give an
  estimate before the first run. The PRD-051 ledger gives a measured
  cost per accepted execution after it. An operator may declare an
  estimate explicitly, with authority and reason recorded. The basis is
  stored with the number, so nobody has to guess where a figure came
  from.
- **Measurement supersedes declaration.** After enough accepted
  executions the measured figure wins, and the supersession is a durable
  event. Observations with unknown cost are counted, not discarded —
  unknown coverage is itself a reported number.
- **Unmeasured becomes actionable.** `CostUnmeasured` stops being the
  resting state and becomes a named configuration gap with the command
  that closes it.
- **Measure before steering.** This PRD changes no route. It produces the
  inputs PRD-032's empirical routing and probation consume, so that when
  routing does change, the change cites numbers.

## Scope

Cost basis resolution and storage in the worker registry; ledger-derived
measured cost with supersession records; the enriched CostUnmeasured
blocker; cost-coverage reporting with a failure floor; recorded routing
reasons distinguishing unrankable from outranked; regressions in a
dedicated test file.

Out of scope: changing any route or default (PRD-032), authoritative
provider billing collection and reconciliation (PRD-051), local-runtime
cost modelling beyond what the ledger already records (PRD-063), and
budget enforcement (PRD-024).

## Assumptions (recorded at specification time, 2026-09-04)

- Published per-token rates are a legitimate pre-measurement basis
  provided they are stored as a basis and superseded by measurement; a
  rate that drifts is a stale basis, not a wrong architecture.
- The PRD-051 ledger already records enough per-execution detail to
  derive a cost per accepted execution for hosted workers; where it does
  not, the gap is reported as an uncovered worker rather than filled by
  estimation.
