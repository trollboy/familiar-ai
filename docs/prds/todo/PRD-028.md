# PRD-028: Cost-Tiered Review

**Status:** Ready for implementation
**Date:** 2026-08-09
**Depends on:** PRD-008, PRD-013, PRD-026
**Architectural direction:** Trust Is Earned Through Verification; Determinism Before Intelligence; Small, Bounded Work Wins
**Delivery boundary:** Independently mergeable deterministic selection of review depth by measured change footprint, with today's behavior as the unconfigured default

## Objective

Stop paying adversarial-review prices for trivial diffs. Review depth becomes a **tier**, selected deterministically from the measured footprint of the change under review — never from its prose, never by a model's opinion of its own work — with the most expensive tier as the fail-closed default for anything the rules cannot place.

This is the first PRD of the Cheap track: the review loop is currently the largest cost multiplier in an attempt, and it spends identically on a one-line rename and a concurrency redesign.

## Motivation

Every reviewed attempt runs the full pipeline: implementation agent, then a reviewer agent on the most capable configured model, then possible remediation cycles. The reviewer's cost is justified by the risk of the change, but the pipeline never measures that risk. A connector PRD touching three files under one directory pays the same review bill as a cross-cutting refactor.

The measurement already exists. The review evidence collector produces the exact change footprint — files changed, change kinds, bytes, and the PRD-013 scope classes each file falls into. Nothing consumes it for economy. Tiering on that footprint is deterministic, auditable, and cannot be gamed by the implementation agent's self-description, because it is computed from the diff the agent actually produced.

## Semantics

- **A tier is a named review depth.** This PRD ships exactly three: `checks-only` (deterministic verification commands run; no reviewer agent is invoked), `standard` (reviewer agent on an operator-named cheaper model), and `full` (today's reviewer, unchanged). There is no user-defined tier.
- **Selection is deterministic from the measured footprint.** An ordered list of operator rules maps footprint ceilings — maximum files changed, maximum changed bytes, allowed scope classes — to a tier. The first rule the footprint satisfies wins. A footprint satisfying no rule, touching a scope class the rules never name, or that cannot be measured at all selects `full`. Fail closed means fail *expensive*.
- **Tiering never widens authority.** Scope authorization, allowed paths, prohibited changes, and verification checks are identical across tiers; a cheaper tier runs fewer or cheaper *review agents*, never fewer *checks*. `checks-only` still requires every required verification check to pass, and its disposition records that no agent reviewed it.
- **Absence is today.** No `[review.tiers]` configured means one tier, `full`, byte-identical behavior. Tier configuration participates in PRD-026 wholesale per-repository resolution like every other review field.
- **The chosen tier is recorded, not inferred.** Each review cycle records which tier ran, which rule selected it, and the measured footprint values; the morning report renders the tier beside the attempt. A verdict is attributable to the depth of scrutiny that produced it.
- **Validation is fail-closed at load.** Rules with non-positive ceilings, an unknown tier name, an unknown scope class, a `standard` tier without a named reviewer model, or agent-consistency violations against the `[agents]` tables refuse at configuration load with exact diagnostics.

## Scope

This PRD includes:

1. Tier configuration on the review tree (global and PRD-026 repository-scoped), with fail-closed validation.
2. Deterministic footprint measurement from the existing review evidence, and rule evaluation selecting a tier.
3. `checks-only` and `standard` execution paths in the review coordinator, with `full` unchanged.
4. Tier, selecting rule, and footprint recorded on the review cycle; morning report rendering.
5. Focused tests over fake agents proving tier selection, fail-expensive defaults, and unchanged-behavior-when-unconfigured.

## Non-goals

This PRD does not:

- let any model choose or influence its own review tier;
- reduce, skip, or reorder verification checks in any tier;
- change scope authorization, prohibited-change rules, or remediation semantics;
- add difficulty estimation of PRDs before execution (that is planner territory, PRD-019);
- introduce per-tier budgets (PRD-024's layer applies unchanged); or
- modify prior PRDs, architecture documents, ADRs, contracts, or philosophy.

## Behavior

```toml
[[review.tiers]]
tier = "checks-only"
max_files = 2
max_changed_bytes = 2000
scope_classes = ["test", "configuration"]

[[review.tiers]]
tier = "standard"
reviewer_model = "haiku"
max_files = 10
max_changed_bytes = 20000

# Anything larger, unmeasurable, or out-of-class: full review, as today.
```

A two-file test-only diff runs verification and completes without a reviewer invocation, recording `tier=checks-only`. A nine-file change reviews on haiku. A migration touching a scope class no rule names reviews on the full reviewer. An installation with no `[[review.tiers]]` behaves byte-identically to today.

## Acceptance Criteria

1. With no tiers configured, the run, drive, review, and report suites are byte-identical to today.
2. A footprint satisfying a `checks-only` rule completes review with zero reviewer-agent invocations, all required checks passing, and a disposition recording the tier.
3. A footprint satisfying a `standard` rule invokes the reviewer on the configured model, recorded on the cycle.
4. A footprint satisfying no rule, exceeding every ceiling, touching an unnamed scope class, or unmeasurable selects `full` — proven per case.
5. Tier selection is computed from collected git evidence, and an implementation agent's output text cannot influence it — proven by a fixture whose diff and prose disagree.
6. Invalid tier configuration — unknown tier, non-positive ceiling, unknown scope class, `standard` without a model, agent inconsistency — each refuse at load with exact diagnostics, at both global and repository scope.
7. The morning report renders the tier per attempt, pinned byte-exact; untier-ed attempts render unchanged.
8. All tests use temporary repositories, databases, and fake agents; formatting, focused Clippy, focused tests, and the workspace suite pass, or demonstrably pre-existing failures are reported with exact evidence.
9. The change is confined to the expected files and is independently mergeable.

## Test Strategy

- Selection: a rule-evaluation table over footprints crossing each ceiling boundary and each scope-class condition, pinned to the selected tier and rule.
- Paths: fake-agent runs through each tier asserting reviewer invocation count, checks executed, and recorded disposition.
- Fail-expensive: each unplaceable-footprint case pinned to `full`.
- Configuration: each refusal at load with its exact diagnostic, global and scoped.
- Regression: unconfigured installations byte-identical across existing suites.

## Definition of Done

PRD-028 is done when review spend is proportional to measured risk: trivial diffs pay for checks, moderate diffs pay for a cheap reviewer, everything else pays full price exactly as today — with the tier chosen by rules the operator wrote, recorded on every cycle, and impossible for the reviewed agent to influence.
