# PRD-103: Finish PRD-090's unmet criteria

## Why this exists

PRD-090 (CLI surface design pass) is `completed`, and stays completed. Its
independent review on 2026-09-21 returned disposition
`ReadyForHumanApproval`, stop reason `CleanReview`, and it should have: none
of its four findings were blocking.

But two of those findings say acceptance criteria were only nominally
satisfied, and a third is a defect in the code that shipped. "Did not block"
is not "was done".

This is the successor `docs/contracts/completion-is-immutable.md` describes.
It inherits the findings rather than re-litigating the PRD.

## What it inherits

**`f2-ac5-leaf-set-not-compared`** (test_gap, medium). PRD-090's AC5 asked
that "a regression compares the full set of reachable leaf commands before
and after and asserts the set is unchanged except for declared additions".
What shipped —
`every_relocated_leaf_is_reachable_at_its_new_namespaced_home` — hardcodes a
partial list of expected leaves per namespace and asserts each appears in
that level's `--help`. The finding's own words: it "never enumerates the
reachable leaf set (it does not recurse past the levels it names, e.g.
`config artifact`, `config provider`, `plan backlog approve-and-complete`,
`ops worker run`), never derives the baseline set from the base revision, and
uses `any(|name| name == leaf)` so extra or missing unlisted leaves are
invisible."

The criterion's purpose is that no capability is silently removed. A spot
check cannot establish that, because the thing it would catch is precisely
the leaf nobody listed.

**`f3-alias-regression-does-not-assert-target`** (test_gap, low). AC3 asked
that "a regression enumerates the alias table and asserts each resolves to
its target". What shipped runs `<old> --help`, asserts success, and asserts
stderr carries the relocation notice — and that notice "is printed from raw
argv before clap parses anything, so it proves only that the name is in
`RELOCATED_COMMAND_ALIASES`". An alias wired to the wrong handler, or deleted
from `Command` leaving only the notice, still passes.

**`f1-front-door-misreports-broken-backlog`** (correctness_defect, medium).
`front_door_report` computes no eligible work whenever `validate_graph`
fails, and swallows every selection error with `manager.next(&cwd).ok()`.
Both collapse into `NothingToDo`, so a repository with a structurally broken
backlog is told `nothing to do` — "a false statement of state for a
repository that has PRDs it cannot schedule, and it is exactly the case where
a new operator most needs to be told something is wrong."

## Not inherited

`f4-bare-invocation-writes-durable-state` — that the no-argument front door
performs a durable reconciliation write. It is a real observation and a
maintainability finding, but it is a design question about what the bare
invocation should be, not an unmet criterion of PRD-090. It wants its own
PRD and its own decision, and bundling it here would make this successor a
re-run wearing a new number.

## Scope

The two regressions PRD-090's criteria asked for, written so they fail when
the thing they guard breaks; and the front-door state that distinguishes an
empty backlog from an unschedulable one. Nothing else in the CLI surface is
reopened — the relocation, the namespacing and the README all stand.

## Assumptions (recorded at specification time, 2026-09-21)

- The command tree is walkable from `--help` output. If clap's rendering
  turns out to be an unreliable source for a leaf inventory, deriving the set
  from the `Command` enum at compile time is the better answer and is a
  scope-conformant substitution, not a deviation.
- PRD-090's work is on a branch and not yet merged to `main`. This PRD
  assumes it lands first; if it does not, these regressions have nothing to
  guard and this PRD blocks on that rather than reimplementing it.
