# PRD-094: Local Workers Reachable From Dispatch

## Objective

PRD-063 delivered a complete local-inference runtime — adapter, transport,
reservation helpers, telemetry — that no daemon dispatch path constructs. That
deferral is recorded and accepted in PRD-063. This PRD closes it.

Until a `provider = "local"` worker can be selected and executed by the daemon,
goal 1 ("Cheap — intelligent multi-step, multi-model orchestration") gets
nothing from that work: local models on developer hardware are the cheapest
worker available and they are currently unreachable.

## Why reachability is an explicit criterion here

Three PRDs in a row shipped a deliverable nothing invoked — PRD-072's
targeted-edit worker instruction (`td-worker-instruction-never-emitted`),
PRD-092's gate scripts (`f1-gate-scripts-unwired`), and PRD-063's local adapter
(`F1-no-production-dispatch`). In each case three independent reviewers wrote
the same sentence, and in each case the acceptance criteria said the artifact
must *exist* and never that it must be *reachable*.

Acceptance criterion 2 exists to break that pattern for this PRD. The general
version belongs in PRD-093 (PRD admission quality).

## Inherited findings

Four non-blocking findings from PRD-063's final review live in code this PRD
makes reachable, so they become live defects here and are owed as acceptance
criteria above:

- `N1-llm-crate-untested-by-any-passing-check` — no required check runs
  `familiar-ai-llm`, so the transport's own tests prove nothing.
- `C3-telemetry-aggregates-attempts-under-first-attempt-id` — one aggregated
  row labelled with the first attempt's id, on a table indexed per attempt.
- `C4-allocation-policy-reregistration-silently-ignored` — `INSERT OR IGNORE`
  returning `Ok(())` while the stored policy diverges from the operator's.
- `U2-transport-implementation-not-disclosed` — 1107 lines omitted from the
  review package for budget, so none of its contract claims were reviewed.

## Approach

Route the local profile through the existing worker-selection path rather than
beside it: a `local` worker resolves to `LocalInferenceAdapter` the same way a
`claude-code` worker resolves to its adapter, so reservation acquisition,
execution, resolution, and telemetry are one path with one set of failure
modes. `resolved_worker_plan` currently returns `Err` for a local profile; that
refusal is the seam.
