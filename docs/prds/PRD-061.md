# PRD-061: xAI Grok Raw-API Inference Adapter

## Objective

Add xAI as a first-class provider — Grok models through the official
xAI API as a PRD-058 raw runtime (`xai-api`) — reusing verified
protocol machinery from the OpenAI adapter where safe while keeping
authentication, capabilities, pricing, errors, billing evidence, and
empirical identity strictly xAI's own.

## Design (provider details verified 2026-08-30; re-verify at implementation)

**Own provider, borrowed wire format.** The official surface is
`https://api.x.ai/v1` with bearer-key authentication and a
`/v1/responses`-style endpoint compatible with OpenAI SDK shapes:
function tools defined by JSON schema, calls returned as
function-call items with `call_id`, `name`, and `arguments`, parallel
tool calls on by default. Where implementation-time verification
proves exact compatibility, the adapter may reuse a **neutral
internal Responses-compatible transport codec** — a helper below
provider semantics that encodes/decodes the shared wire shapes and
nothing more. The codec carries no OpenAI authentication assumptions
and no OpenAI model, pricing, billing, capability, rate-limit, or
error semantics; it permits provider-specific event decoding and
extensions; implementing, testing, enabling, or disabling this
adapter requires no enabled OpenAI adapter; and PRD-060 owns none of
xAI's wire contract — protocol reuse is engineering economy, not
semantic identity or a domain prerequisite. xAI
keeps its own `ProviderId`, `RuntimeId = xai-api`, auth profile
(e.g. `env: XAI_API_KEY` reference), capability profiles, error
taxonomy, price schedules, and PRD-057 empirical identities. Grok is
a model family of xAI, never "an OpenAI model."

**Verified capability differences are the point.** Streaming delivers
a function call whole in a single chunk rather than argument-streamed
— a recorded capability difference that the loop and any UI must not
assume away. Structured outputs and web-search/batch features are
documented at the overview level; reasoning controls and usage field
names were **not verifiable** in the consulted official pages. Per
PRD-057, those capabilities carry `unknown` provenance until declared
from verified documentation or probed safely at implementation time —
resemblance to OpenAI is never evidence.

**Usage and accounting.** Observations normalize only fields verified
against current xAI documentation; anything else stays unknown
(never zero, never borrowed). Rows carry the xAI spec identity and
sanitized envelopes into PRD-051. **No official programmatic
administrative usage or cost API was found in the consulted xAI
documentation**: authoritative xAI billing is therefore explicitly
unsupported — the PRD-051 `external-billing`/unknown discipline —
and xAI spend reports label local-estimate coverage only. If xAI
ships an official reporting API later, it arrives as its own
collector under the PRD-052/054 pattern, not as an assumption here.

**Pricing.** Grok schedules are versioned, dated, and sourced from
official xAI pricing at implementation time; requested aliases and
resolved model identities are both recorded, and schedules key on
resolved identity where exposed.

**Security.** BYO-Auth throughout: the xAI key is an external
reference resolved in the adapter boundary; redaction covers logs,
errors, and evidence; tool subprocess environments inherit nothing;
there is no xAI admin credential class to confuse because no such
surface is integrated.

## Scope

- The xAI adapter with xAI-owned configuration, probes, capability
  profiles, and error handling, optionally over the neutral
  Responses-compatible codec described above (a below-semantics
  helper, not another provider abstraction and not a new PRD).
- Usage normalization gated on implementation-time field
  verification; sanitized envelopes; PRD-051 attribution.
- Grok price-schedule entries and capability-profile defaults for
  `xai-api` workers; explicit unsupported state for authoritative
  billing.
- Deterministic fixture suite per the acceptance criteria; wiremock
  transport fakes; no live calls.
