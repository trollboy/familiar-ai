# PRD-069: Native Token Compression

## Objective

Give Familiar caveman-class token compression as first-party capability —
compressed worker output registers, deterministic input compression with
byte-exact recovery, and measured verdicts — implemented entirely in this
workspace. Caveman (github.com/JuliusBrussee/caveman) is the existence
proof: ~65% output-token reduction from a compressed response register and
a pinned 33.2% input-token reduction from transparent pre-provider
compression. Familiar replicates the functionality and never depends on
the package: the useful engine layer is BSL-1.1 licensed, the mechanisms
are not exotic, and Familiar's economics must not rest on an external
service in its request path. This is goal-1 (Cheap) infrastructure with
goal-1 discipline: every knob defaults off, every effect is measured by
the PRD-051 ledger, and nothing is promoted on somebody else's benchmark.

## Design

### 1. Compressed output register (the skill, natively)

A configurable per-role/per-stage response register instructing a worker
to compress its prose while a hard fidelity contract protects everything
machines consume: code spans, diffs, file paths, identifiers, and
structured output (review findings JSON, scope declarations) pass through
verbatim — only surrounding natural-language prose compresses. Register
definitions are versioned data owned by this repo (intensity variants may
exist), injected into worker instructions by `run.rs` when configured.
Rationale for output-first: agent output is appended to context and
re-read every subsequent turn, so output compression compounds into
slower context growth in exactly the long sessions that dominate measured
spend. The reviewer role is the first candidate — single-shot, structured,
lowest fidelity risk — consistent with PRD-067 making narration
non-authoritative.

### 2. Deterministic input compression (the proxy, natively)

A `familiar-ai-compress` crate providing reversible, deterministic
compression of provider-bound request content with byte-exact recovery.
Three properties are load-bearing and pinned by regression:

- **Determinism / prefix stability:** identical input bytes compress to
  identical bytes across calls and process restarts, so provider prompt
  caching survives — the whole net-benefit question on cache-heavy
  workloads (97%+ cache reads in measured runs) turns on this property.
- **Byte-exact round trip:** decompress(compress(x)) == x, always.
- **Cache-breakpoint transparency:** provider cache-control markers pass
  through verbatim and unmoved.

The crate exposes a transform API for Familiar-owned request paths (the
PRD-058 raw runtime and PRD-059–061 adapters integrate it when they land)
and a local endpoint mode for agents that accept a base-URL override, so
existing adapters can be fronted without code changes. Endpoint mode
forwards credentials untouched and persists nothing.

### 3. Ledger attribution and the experiment verdict (learn, natively)

Compression state is a material execution parameter: every accounting
observation carries the active register and input-compression identities
and versions, so PRD-051 queries partition cleanly (and PRD-057's worker
identity treats compressed and uncompressed configurations as distinct
empirical workers when it lands). A `compress experiment` command labels
paired on/off executions and reports measured per-category deltas —
uncached input, cache read, cache write, output, known cost — per lane.
The open question it exists to settle: whether input compression's token
reduction survives the cache-read economics of prefix-heavy workloads, or
trades cheap cached tokens for expensive fresh ones. The answer comes
from ledger rows, in either direction; the repository's prior
"compression loses to caching" position is retired or confirmed by this
measurement, not by argument.

### 4. Explicit enablement, audited

Everything defaults off. Enabling any register or input compression for a
role, stage, or provider is a configuration mutation through the PRD-047
decision-row pattern (actor, audit row). Promotion to a default requires
a recorded experiment result to point at. No implicit behavior changes.

## Scope

- The `familiar-ai-compress` crate: register definitions, deterministic
  reversible input transform, endpoint mode.
- Configuration surface and validation in `config.rs`; register injection
  in `run.rs`.
- Ledger attribution fields (migration plus repository support) and the
  experiment/report CLI in a dedicated `compress_cli.rs`.
- The `docs/contracts/compression.md` contract: register fidelity rules,
  determinism guarantees, attribution semantics.
- Regressions in a dedicated `token_compression.rs` test file: byte-exact
  round trip, restart determinism, breakpoint transparency, byte-identical
  prompts when disabled, structured-output fidelity under the register,
  attribution partitioning.

Out of scope: DOM/browse compression and image-rendered prompts (no
Familiar surface needs them), automatic default-on for any lane (requires
a recorded experiment), wiring into the raw runtime and hosted adapters
(PRD-058–061 integrate the transform API when they land), and semantic
summarization (wave-one summaries/rollups are a different mechanism with
a different trust model).

## Assumptions (recorded at specification time, 2026-08-30)

- PRD-051's observation schema accepts additional typed attribution
  fields without breaking existing rows; absent attribution reads as
  uncompressed.
- The register cannot force a model to comply; the fidelity contract is
  enforced where Familiar can check (structured outputs must parse; code
  spans in findings must match the worktree), and register efficacy is an
  empirical question the ledger answers per worker.
- Endpoint mode is same-machine only and carries no authentication
  material of its own; provider credentials flow through unread.
