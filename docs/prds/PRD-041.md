# PRD-041: Verification-Failure Escalation

**Status:** Ready for implementation
**Date:** 2026-08-29
**Approved:** 2026-08-29 by owner
**Depends on:** PRD-024, PRD-044

## Objective

Convert a cheap worker's deterministic verification failure into one bounded
retry at the next routing tier before retaining the PRD for a human, making
speculative cheap execution economically rational.

## Scope

- On required verification failure before review, permit at most one escalated
  re-execution using the next eligible worker tier from PRD-044 routing.
- Escalation respects session warrants and per-execution budgets; an
  over-budget escalation retains instead of running.
- Never escalate for policy stops, scope violations, or review findings —
  those keep their existing paths.
- Escalated attempts start from the original PRD state on a clean tree, never
  from the failed attempt's tree.
- Persist both attempts with identities, costs, and the escalation reason; the
  morning report states escalations distinctly.

## Acceptance Criteria

1. A cheap-worker verification failure re-executes once on the designated
   stronger worker without human involvement.
2. A stronger-worker failure, or the absence of a stronger tier, retains the
   PRD exactly as today.
3. Escalation cannot exceed session cost, token, or duration warrants.
4. Both attempts' evidence is persisted and attributable; nothing overwritten.
5. Crash recovery never duplicates an escalated execution.
