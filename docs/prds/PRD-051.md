# PRD-051: Billing Modes and the Usage Observation Ledger

## Objective

Turn Familiar's lossy, five-representation usage bookkeeping into one
append-only observation ledger with distinct token categories, per-model
attribution, retained raw evidence, versioned price schedules, and a
closed billing-mode vocabulary — so budgets, reports, PRD-032 empirical
routing, and later authoritative reconciliation (PRD-052/053) all read
the same trustworthy facts.

## Design

**Billing modes.** Every monetary fact carries one of a closed set of
modes: `local-estimate` (Familiar priced what it observed),
`subscription-declaration` (an operator-declared fee or availability,
never metered spend), `authoritative-report` (provider-reported cost,
arriving via PRD-052), and `external-billing` (a system Familiar cannot
collect from; recognized, never faked). The local ledger exists without
any configuration; only the other modes require configured sources.
Unknown stays unknown — no mode ever converts absent data to zero.

**Normalized usage observations.** One append-only row per model per
stage observation, carrying execution/attempt/stage/session identity,
the PRD-044 selected worker identity (`provider/model`), adapter and
model identity, service tier and provider request id when reported, and
distinct token categories: uncached input, cache read, cache write,
output, and — where the provider reports it — reasoning output. Today
the Claude adapter destroys the cache-write category and per-model
breakdown at the parse boundary and discards the raw JSON entirely; all
three survive here. The raw terminal result
metadata is retained as an integrity-protected evidence artifact per
the event-model contract, so later reconciliation can drill past the
summary. Vendor-reported cost (Anthropic documents `total_cost_usd` as
a client-side estimate) is recorded as an estimate, never as an
invoice. Direct API requests Familiar itself sends (today only the
local inference router; any future Messages-API path) record
provider-returned usage through the same ledger or record an explicit
unknown.

**Versioned price schedules.** The exact-model pricing map gains
identity: a schedule has an id, effective time, currency, and per-model
rates for each priced category (the current table cannot express
Anthropic's cache-write premium). Every estimate records schedule id
and calculation version. Prices change by adding a schedule; historical
estimates are never recomputed in place. Existing
`execution_history.pricing` entries remain valid as a labeled legacy
schedule. All persisted currency is integer microusd; floating point
never touches a persisted amount.

**Honest lifecycle evidence.** Observations are written at durable
stage boundaries, not only at finalization, so a failed finalize
(ledger B13) loses at most the unwritten tail rather than the whole
attempt's usage. Resume and retry attach new observations to their own
attempt identity; checkpointed work is never re-billed as new spend
(PRD-039 discipline). The `execution_history` adapter pin
(`CHECK(agent = 'codex')`) is corrected so multi-adapter attribution is
possible.

**Subscription declarations.** A configured subscription price on a
worker or provider is stored as an operator declaration with actor and
UTC provenance. Subscription headroom remains declared availability
(PRD-032's rule) and is modeled apart from cost; no monetary spend is
ever inferred from subscription-backed activity. Where a provider
publishes a plan-credit rate card, estimated credit consumption is its
own typed unit beside microusd — credits never convert to dollars
(per-provider schedules arrive with PRD-054).

## Scope

- Ledger tables and repository methods for usage observations, raw
  result evidence references, price schedules, and cost estimates;
  migration of the adapter boundary (`ExecutionResult`) and
  finalization path to carry all four token categories and per-model
  rows without collapsing.
- Closed persisted cost-provenance classification (vendor-reported,
  configured-rate, known-zero — completing PRD-024's unimplemented
  known-zero) on estimate rows, replacing the stringly field trapped in
  `cycle_json`.
- Config schema for price schedules and subscription declarations,
  validated closed; documented in docs/contracts/providers.md alongside
  the PRD-047 provider contract.
- `familiar-ai usage` reads the ledger and labels every amount with
  billing mode, provenance, and the distinct cache categories; existing
  output semantics (unknown counted, never summed as zero) preserved.
- No network collection, no reconciliation, no new CLI verbs beyond the
  usage/reporting reads — those are PRD-052/053/054.

## Assumptions (recorded at specification time, 2026-08-30)

- Microusd precision suffices for normalized amounts; any finer
  provider precision is retained verbatim in raw evidence and rounded
  half-to-even at microusd for the normalized value.
- The five existing usage representations are converged incrementally:
  the ledger becomes authoritative for new rows; historical
  `execution_history` rows are readable as-is and are not backfilled or
  rewritten.
- Per-model observations come from the adapter's `modelUsage` block
  when present; when only aggregate usage is credible, one observation
  row records the aggregate with its model identity unknown-but-stated.
