# PRD-050: Cloud Deploy Targets via Replaceable CLIs

## Objective

Extend deploy targets from garage boxes to AWS, GCP, Azure, and
DigitalOcean by treating clouds the way Familiar treats coding agents:
as replaceable executables. No SDK integrations — a cloud target is its
vendor CLI plus an operator-approved recipe, with BYO-Auth through each
CLI's own credential chain.

## Design

    familiar-ai config provider add azure-prod --kind deploy-target \
        --via az --recipe "az webapp deploy --name myapp ..."
    Added azure-prod (deploy-target via az) — authenticated as trollboy@….
    azure-prod: az CLI not authenticated — run `az login`.
    # auth descriptors per CLI: az → `az login`, aws → profile/SSO,
    # gcloud → ADC, doctl → `doctl auth init`. Familiar stores none of it.

The abstraction from PRD-048 is unchanged: probe (CLI present +
authenticated), recipe execution, smoke command, recorded effects and
evidence. One project maps production to Azure while another maps it to
AWS; a third keeps production on a droplet — the role indirection from
PRD-048/049 carries the whole variability.

## Scope

- `--via <cli>` target flavor with per-CLI auth descriptors and probe
  commands; recipes execute through the named CLI only.
- Evidence parity with ssh targets in `delivery_external_effects` and
  smoke recording.
- Session preflight covers cloud CLI auth freshness; expiry mid-session
  retains with the remedy.
- Recipes arrive only via approved configuration (machine config or an
  approved familiar.toml snapshot per PRD-049) — never from unapproved
  repository content.
