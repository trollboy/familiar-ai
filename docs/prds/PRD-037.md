# PRD-037: Security Hardening and Failure-Injection Burn-In

**Status:** Ready for implementation
**Date:** 2026-08-26
**Depends on:** PRD-021, PRD-024, PRD-033, PRD-034, PRD-039

## Objective

Prove Familiar fails closed under malicious inputs and failures at every durable
phase before it is trusted with broad unattended warrants.

## Scope

- Threat-model PRDs, repositories, agent streams, verification, delivery,
  credentials, journals, supervisors, and human overrides.
- Inject process kill, reboot-equivalent recovery, disk/database faults,
  corrupted journals, rate limits, network partitions, and partial external
  side effects.
- Test command/argument injection, symlink escapes, secret exfiltration, log
  redaction, and privilege boundaries.
- Make every recovery idempotent and every unresolved condition reportable.

## Acceptance Criteria

1. No injected failure can fabricate completion, review, approval, or delivery.
2. Secrets do not appear in prompts, logs, reports, database rows, or comments.
3. Recovery never duplicates model execution or external side effects.
4. Restart storms are bounded and visible.
5. The burn-in suite produces a durable coverage matrix tied to phases.
