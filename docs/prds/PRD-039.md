# PRD-039: Checkpointed Execution and Concurrent Resume

**Status:** Ready for implementation
**Date:** 2026-08-26
**Depends on:** PRD-017, PRD-018, PRD-030, PRD-034

## Objective

Make every successful execution stage durable and resumable so Familiar never
regenerates valid implementation work merely because review, verification,
policy accounting, process interruption, or machine restart happened later.
Expose `familiar-ai resume <PRD>` and `familiar-ai resume all`; the latter
recovers every valid partial concurrently under the ordinary dependency,
conflict-scope, ownership, and warrant rules.

## Required Behavior

1. Persist a closed execution phase state machine: claimed, implemented,
   verified, reviewed, approved, integrated, and completed, plus explicit
   blocked and invalid-checkpoint outcomes.
2. After implementation and every remediation, freeze a checkpoint containing
   repository identity, base revision, worktree/branch identity, diff hash,
   changed-file manifest, agent identity, usage, and test evidence.
3. A valid implementation result that exceeds a post-run accounting threshold
   becomes `implemented_pending_review` with an overage finding. It is never
   discarded or represented as though a preventive hard limit fired.
4. Only provider-native enforcement and preemptive process controls are hard
   execution limits. Unsupported hard denominations fail before launch.
5. `resume <PRD>` validates the checkpoint and continues from its last durable
   phase without repeating any completed stage.
6. `resume all` discovers every resumable attempt, reports invalid candidates,
   and schedules the valid set concurrently using dependency eligibility,
   Expected Files conflict scopes, and configured concurrency ceilings.
7. A failed resumed item does not stop independent items. Dependents remain
   blocked until their prerequisite completes.
8. Drive, resume, delivery, and persistent-worker entry points share one
   exclusive ownership protocol. A second mutating orchestrator fails before
   claims, agents, or worktree changes.
9. `resume all --dry-run` is read-only and prints deterministic candidates,
   starting phases, conflicts, dependency blockers, and invalid-checkpoint
   reasons.
10. Missing, dirty, manually altered, stale-base, or hash-mismatched checkpoints
    fail closed with exact evidence. Familiar never guesses from a dirty
    worktree alone and never deletes a worktree containing unique changes.
11. Recovery is idempotent across interruption at every phase boundary; the
    morning report distinguishes resumed, completed, blocked, skipped, and
    invalid attempts.
12. Existing retained/interrupted attempt records receive a deterministic
    compatibility classification without fabricating absent checkpoint facts.

## Acceptance Criteria

1. An integration fixture reproducing the PRD-024/026/029/030/034 incident:
   implementation succeeds, a post-run token threshold is exceeded, and
   `resume all` reaches review/completion without invoking implementation again.
2. Multiple independent implemented checkpoints resume concurrently while
   overlapping scopes serialize and dependency order is preserved.
3. Restarting `resume all` after a forced interruption repeats no completed
   stage and creates no duplicate review, completion, or audit evidence.
4. Invalid checkpoints are individually blocked with exact diagnostics while
   valid independent checkpoints continue.
5. Active drive/resume ownership is mutually exclusive and refusal has no
   repository or database side effects beyond the refusal audit record.
6. Dry-run output and morning-report output are byte-stable and preserve unknown
   usage or provenance as unknown, never zero.
7. Full formatting, focused static analysis, focused recovery tests, and the
   workspace suite pass.

## Definition of Done

PRD-039 is complete when a successful implementation can always be resumed
from durable evidence, `resume all` safely drains every compatible partial with
bounded concurrency, and no post-run accounting decision can force Familiar to
pay for the same implementation twice.
