# PRD-091: Multi-Host Driver Leases

## Objective

`WorkerLock` claims `control-plane.claim` inside `$XDG_RUNTIME_DIR` — a
path on one box. One driver, one machine; all the parallelism Familiar
has is within-machine. The standing direction is that width is the goal
and a single-machine ceiling is a defect rather than a safety feature,
and this is the exact mechanism that imposes the ceiling.

The mutual exclusion the claim provides is correct and must survive. What
changes is where it lives: a filesystem path only one host can see
becomes a durable, host-identified, expiring lease that every host can
see. That is the smallest change that makes a second machine possible,
and it is deliberately the whole of this PRD.

## Design

- **The claim becomes a lease.** Host identity, process identity,
  acquisition time, expiry. The refusal that protects durable writes from
  concurrent operators now works between machines, not just between
  processes.
- **Liveness by renewal, not by presence.** A holder renews on a
  heartbeat. Expiry is what makes a dead host's work recoverable without
  an operator deleting a file, and takeover is recorded with both hosts
  named.
- **Losing the lease stops the driver.** A host that cannot renew — or
  finds itself superseded — stops writing durable state within a bounded
  interval. A partitioned host that keeps driving is the failure this
  criterion exists to prevent.
- **Per repository, so two hosts are useful immediately.** Independent
  leases mean a second machine can drive a second repository the day this
  lands, before any cross-host distribution exists.
- **Single host pays nothing.** No configuration, no behaviour change,
  filesystem claim retained for local exclusion.

## Scope

The durable lease record and its storage; host and process identity;
renewal, expiry, and recorded takeover; the cross-host refusal; bounded
write cessation on lease loss; per-repository lease independence;
single-host compatibility; regressions in a dedicated test file.

Out of scope: distributing one repository's work across hosts, cross-host
worktree or artifact transport, remote agent execution, and any shared
store other than the existing database. Those are the successor PRD; this
one establishes the contract they need and nothing more.

## Assumptions (recorded at specification time, 2026-09-04)

- Hosts sharing a store share a database reachable by all of them; a
  store that is not shared reduces to today's single-host behaviour with
  no change in outcome.
- Clock skew between hosts is bounded well below the lease interval;
  where it is not, expiry is computed from store-side time rather than
  host time, and the choice is recorded in the lease record.
